# Контракт-тесты FTP/FTPS против vsftpd

Общий контракт-тест-сьют `pa_vfs::contract` (ADR-0013) против трёх экземпляров vsftpd 3.0.5 в Docker (`alpine:3.22` + `vsftpd`):

| Сервис | Порт | Пассивные порты | Режим |
|---|---|---|---|
| `plain` | 18621 | 18700–18739 | обычный FTP |
| `explicit` | 18631 | 18740–18779 | явный FTPS (`AUTH TLS`), TLS обязателен для входа и данных, `require_ssl_reuse=YES` |
| `implicit` | 18641 | 18780–18819 | неявный FTPS (TLS с первого байта) |

Все порты — только на `127.0.0.1`; пассивный диапазон проброшен 1:1, клиент подключается к адресу управляющего соединения (сервер в контейнере объявляет внутренний адрес).

```bash
core/crates/pa-vfs-ftp/tests/servers/run.sh              # все тесты
core/crates/pa-vfs-ftp/tests/servers/run.sh -- plain     # часть
```

Нужны Docker с плагином compose, `openssl` и cargo. Скрипт кладёт фикстуру в `/media/контракт`, создаёт самоподписанный сертификат (тесты закрепляют его отпечаток `sha256:`), поднимает контейнеры, запускает `cargo test -p pa-vfs-ftp --features server-tests --test contract_servers` и удаляет контейнеры и сеть (именованных томов нет). vsftpd запускается под `init: true`: как PID 1 он завершается после нескольких сессий.

Что проверяется: весь контракт в трёх режимах (корень — каталог входа и `/`), подкаталог как корень, неверный пароль и анонимный вход (`AuthenticationFailed`, пароль не попадает в текст), отказ сервера без TLS, отказ незакреплённого самоподписанного сертификата и чужого отпечатка, продолжение одной передачи при последовательном чтении и `REST` при переходах.

Ветка `MLSD`/`MLST` (серверы с RFC 3659) в vsftpd не проверяется: он их не поддерживает, работает путь `LIST`/`SIZE`/`CWD`.
