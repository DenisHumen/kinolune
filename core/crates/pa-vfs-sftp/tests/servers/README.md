# Контракт-тесты SFTP против OpenSSH

Общий контракт-тест-сьют `pa_vfs::contract` (ADR-0013) против OpenSSH в Docker (`alpine:3.22` + `openssh-server`, `internal-sftp`, порт `127.0.0.1:18622`).

```bash
core/crates/pa-vfs-sftp/tests/servers/run.sh                      # все тесты
core/crates/pa-vfs-sftp/tests/servers/run.sh -- password_login    # часть
PA_SFTP_PORT=18623 PA_COMPOSE_PROJECT=my-run core/crates/pa-vfs-sftp/tests/servers/run.sh
```

Скрипт кладёт фикстуру в `/media/контракт` (рядом с посторонним файлом) и поднимает контейнер. Контейнер создаёт пользователя (домашний каталог — смонтированная только на чтение фикстура), генерирует ключи хоста и клиентские ключи (ed25519 без пароля, ECDSA с паролем) и пишет отпечатки ключей хоста для тестов. Затем `cargo test -p pa-vfs-sftp --features server-tests --test contract_servers`, после — `docker compose down` (контейнер и сеть; именованных томов нет). Логин, пароль и ключи одноразовые.

Что проверяется:

- весь контракт с входом по паролю (корень — абсолютный путь) и по ключу ed25519 (корень — `~`);
- вход зашифрованным ключом ECDSA; неверная фраза ключа, неверный пароль и анонимный вход дают `AuthenticationFailed`, пароль не попадает в текст ошибки;
- TOFU: первый вход сообщает ключ хоста ровно один раз, это один из ключей сервера (`ssh-keygen -l`), сохранённая строка снова разбирается и работает как закреплённый ключ;
- другой ключ хоста отклоняется до отправки пароля (`HostKeyChanged`), и так при каждой попытке.

Без фичи `server-tests` эти тесты не компилируются. Подключение к CI — задача CI-012.
