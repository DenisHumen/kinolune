# Экосистема приложений Kinolune (схема, веха M16)

> Запрос владельца 2026-11-23. **Это план на будущее: работа начинается только по команде владельца** — сейчас доделывается само приложение. Задачи — ROADMAP §3.29 (ECO-001…ECO-009), шкала «Экосистема». Что нужно сделать в Universal Video Downloader — [`uvd-handoff.md`](uvd-handoff.md).

## Идея

Несколько наших приложений работают вместе вокруг домашнего сервера:

- **Сервер** — компьютер или NAS с нашим дистрибутивом и медиасервером Kinolune (режим B, §3.14 SRV; дистрибутив — §3.17 DIST). Хранит медиатеку и всё, что ему прислали.
- **Kinolune** на телефоне, ТВ и компьютере — смотрит медиатеку сервера, отмечает просмотренное, удаляет.
- **Приложения-поставщики** — сначала [Universal Video Downloader](https://github.com/DenisHumen/Universal-Video-Downloader) (UVD, desktop, скачивает видео с 1800+ сайтов, следит за новыми сериями), потом Kinolune desktop (свои загрузки и записи Twitch) и будущие приложения. Скачали — отправили на сервер.

Пример: на компьютере в UVD включено «Новые серии» для аниме → вышла серия → UVD скачал → отправил на сервер → серия появилась в медиатеке Kinolune на ТВ → посмотрели, отметили, удалили → файл удалён с сервера, а UVD показывает «Удалено с сервера».

## Как приложения находят сервер

Сервер постоянно объявляет себя в локальной сети через mDNS/DNS-SD (это уже есть: SRV-004, `pa-discovery`): служба `_kinolune._tcp` с TXT-записями — имя сервера, версия протокола, отпечаток TLS-сертификата, что сервер умеет (`upload`, `library`, `events`). Приложение при запуске слушает сеть и показывает найденные серверы списком («Найден сервер „Домашний“»). Если mDNS в сети не работает — можно ввести адрес вручную.

## Как приложение подключается (одноразовая авторизация)

1. Приложение выбирает сервер и показывает **временный код** (например, `4827-1953`, живёт 5 минут) и **QR-код** с тем же кодом и отпечатком сервера.
2. Подтвердить можно одним из способов:
   - отсканировать QR телефоном, на котором Kinolune уже подключён к этому серверу как администратор, и нажать «Разрешить»;
   - ввести код в веб-админке сервера или в Kinolune («Настройки → Сервер → Подключённые приложения → Добавить»);
   - войти **логином и паролем** пользователя сервера прямо в приложении.
3. Код и QR действуют **один раз** и только для этой авторизации; после использования или истечения — недействительны.
4. Сервер выдаёт приложению **сессию** (долгоживущий токен обновления, привязанный к ключу приложения, PASETO v4 как в SRV-003) с правами только на нужное: `upload` (присылать файлы), `library:read` (видеть свои присланные), `delete:own` (удалять свои). Приложение хранит токен в системном хранилище ключей.
5. **Переавторизация не нужна**, пока приложением пользуются. Если активности не было **14 дней** (настройка на сервере: 7–30), сессия истекает и нужно подключиться снова. Список подключённых приложений и кнопка «Отключить» — в админке сервера и в Kinolune.

Соединение — TLS с проверкой отпечатка из mDNS/QR (без доверия к случайному сертификату). Только локальная сеть; вне дома — позже, через облако Kinolune+ (ретранслятор SUB-011, ECO-009).

## Как файл попадает на сервер

- Приложение отправляет файл **докачиваемой загрузкой** (по частям, с продолжением после обрыва) и **описанием**: откуда (сайт, ссылка), что это (фильм / серия: название, сезон, серия; стрим Twitch: канал, дата), желаемое имя, размер и хэш.
- Сервер проверяет место и права, кладёт файл в библиотеку «Присланное» (папка на сервере, по умолчанию `Медиа/Присланное/<приложение>/…`, раскладка как у UVD: сериал/сезон/серия), сканирует и распознаёт как обычные файлы (подсказка из описания ускоряет распознавание).
- Повтор того же файла (тот же хэш) не создаёт копию.

## Что видно в Kinolune

- Полка и раздел «Присланное»: что пришло, от какого приложения, когда; статус загрузки, пока файл едет.
- Обычные действия: смотреть, отметить просмотренным, удалить. **Удаление в Kinolune удаляет файл на сервере** (с подтверждением).
- Если файл удалили на сервере (в админке, в Kinolune на другом устройстве, по сроку хранения) — у всех клиентов и у отправителя он помечается «Удалено с сервера», а не пропадает молча.

## Синхронизация между приложениями

Сервер рассылает события по WebSocket (SRV-011): `item.received`, `item.progress`, `item.ready`, `item.watched`, `item.deleted`. Kinolune обновляет медиатеку, UVD — статусы отправленного («На сервере», «Просмотрено», «Удалено с сервера»). Пропущенные события догоняются по курсору при следующем подключении.

## Что решить владельцу перед стартом (ECO-001)

- Срок неактивной сессии по умолчанию (предложено 14 дней).
- Кто может удалять присланное: отправитель и админ (предложено) или все пользователи сервера.
- Квоты места на приложение и срок хранения присланного (например, удалять просмотренное через N дней — по желанию).
- Лицензия и форма протокола: открытая спецификация (`docs/api/`), чтобы сторонние приложения тоже могли присылать файлы.
