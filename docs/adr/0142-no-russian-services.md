# ADR-0142: Не использовать российские сервисы, оставить русский язык

- **Статус:** Принят
- **Дата:** 2026-11-24
- **Решают:** владелец проекта
- **Связано:** NET-017, COMM-001, `docs/STRATEGY.md` (пожертвования), `docs/legal/providers.md`

## Контекст и проблема

Kinolune — украинский продукт. В планах и коде были российские площадки и сервисы: Boosty в ссылках на пожертвования, Yandex.Disk первым облаком в NET-017. Нужно одно правило, по которому решать, что подключать.

## Решение

Kinolune не подключает российские сервисы и площадки: облака, платёжные и донатные площадки, соцсети, видеохостинги, провайдеров метаданных. Русский **язык** остаётся: интерфейс на русском, разбор русских имён файлов и названий.

Исключения по решению владельца (2026-11-24):

- **Shikimori** — провайдер метаданных аниме, важен для распознавания аниме и русских названий.
- **AniLibria** — название релиз-группы в разборе имён файлов: это часть имени файла пользователя, а не сервис, к которому обращается приложение.

Сразу сделано:

- Boosty убран из ссылок на пожертвования (`kDonationLinks`), проверки флейворов, стратегии, политики конфиденциальности и юридических документов.
- В NET-017 вместо Yandex.Disk — MEGA (сквозное шифрование, вход по почте и паролю), затем Google Drive, OneDrive, Dropbox.

Поле `kinopoisk` в модели и схеме v1 — только ID из NFO и имён файлов пользователя, запросов к Кинопоиску нет; миграции не меняются, новых интеграций с Кинопоиском не делаем.

## Последствия

- Новые интеграции проверяются на это правило при ревью; исключения — только решением владельца.
- Украинский язык интерфейса (uk) добавляется как полноценный рядом с русским и английским (отдельная задача).
