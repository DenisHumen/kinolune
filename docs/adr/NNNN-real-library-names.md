# ADR-NNNN: Распознавать реальные имена медиатеки: нумерованные папки — сериалы, мусор сайтов — общими правилами, сиквел-номер — сезон

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** META-032 (эта задача, отчёт владельца по alpha.8 на macOS), META-005/006 (парсер), LIB-007 (группы папок), META-013/014/015/030; [ADR-0084](0084-scorer-pair-features-joint-group.md), [ADR-0085](0085-episode-numbering-module.md), [ADR-0087](0087-bundled-anime-database.md)

## Контекст и проблема

Медиатека владельца (1 105 строк листинга, ~1 030 видео: западные фильмы и сериалы, ~50 папок аниме, около 30 из них с русскими названиями) в alpha.8 распознавалась плохо:

1. Папка `Сериал/Season 1/` с файлами `01 Название серии.m4v` … `43 ….m4v` давала 43 фильма: у файла нет `SxxEyy`, а план файла строится по его имени; то, что группа LIB-007 уже знала «это сериал», планировщик не использовал.
2. Имена, сохранённые с сайтов: `Название — смотреть аниме онлайн бесплатно на Сайт.mp4`, `… tracker.org.mkv` — мусор попадал в название и в поиск.
3. Теги в папках: `Название OVA [Группа] [DVDRip]`, `Название [TV] BDRemux`, `Название_TV`, `… season 2`, `… S01`.
4. Русские сайты нумеруют каждый сезон как `s1`: `Хроника 2/Хроника 2 s1e05.mp4`, `Ворота Часть 2 s1e05.mp4` в папке `… season 2` — сезон 2 сливался с первым (одинаковые 1×01…1×12 в одной работе).
5. Русские папки аниме получали тип `show`: путь аниме (встроенная база, AniList, Shikimori) для них не запускался.
6. Название карточки: TMDB отвечает на языке метаданных, а без перевода — на языке оригинала (японские иероглифы); Shikimori давал русское название только аниме. Карточки шли вперемешку: русские, английские, японские.
7. Постеры: при совпадении без постера TMDB и без обложки AniList картинки не было; изображения Shikimori не использовались вовсе (их пути относительные к сайту, не к API).

Распознанное раньше не пересчитывалось: план строится только для файлов без живого матча, поэтому исправления парсера не дошли бы до уже отсканированных библиотек.

## Факторы решения

- Только локальные правила и данные, без своих серверов (ADR-0004); без регулярных выражений в парсере (линейность, META-005).
- Замер `pa-eval` на корпусе v0 не должен ухудшиться (META-014/015/030).
- Не трогать планирование, лимиты и задачи (`pa-jobs`) — над скоростью скана работает LIB-023.
- Решения пользователя и NFO не пересчитываются никогда.
- Личные данные: листинг владельца в репозиторий не попадает.

## Рассмотренные варианты

1. Правила в планировщике и парсере + пересчёт автоматических решений старой версии парсера (выбран).
2. Список сайтов и тегов (`YummyAnime`, `rutracker.org`…) в лексиконе.
3. Решать «папка = сериал» только в метаданных (поиском TMDB по названию папки).
4. Не пересчитывать: исправления только для новых сканов, старым библиотекам — «сбросить и пересканировать».

## Решение

Выбран вариант **1**.

**Нумерованная папка — сериал** (`pa-catalog::recognize::Planner`). Группа LIB-007 (не диск) с ≥ 2 основными видео, у каждого имя начинается с номера из 1–3 цифр и разделителя (`01 Title`, `1. Title`, `07_Title`), номера разные, ни у одного нет года, и меньше половины имён содержат название папки — это один сериал: название, год и сезон — из папок (`parse::folder_work`, новая публичная функция парсера; сезон по умолчанию 1), эпизод — номер, название эпизода — остаток имени (`_` → пробел). Год или название папки в именах (`1. Saga Part One (2001)`) — коллекция фильмов, папку не трогаем.

**Мусор сайтов** (`pa-recognition::parse::junk`, до токенизатора). Общие правила, не список сайтов: имя обрезается на первом слове призыва (`смотреть`, `скачать`, `бесплатно`, `торрент`, `torrent`, `watch online/free`, `free download`), если перед ним есть слово названия (`Мастера меча онлайн — смотреть онлайн` сохраняет «онлайн» названия); удаляются куски вида `метка.tld` / `www.метка.tld` (короткий список общих и постсоветских доменов, без `tv`), в том числе в скобках; в точечных именах — только строчный хвост `.метка.org`. Студии озвучки (`LostFilm.TV`) остаются: они дают язык аудио.

**Папки.** Хвостовой `TV` в названии папки — тег типа (`Kanto_TV` → `Kanto`), `[TV]`, `OVA`, `[DVDRip]`, `Remux`, `S01`, `season 2` уже разбирались парсером; `_` — разделитель. Если название файла — название папки и ещё ≥ 3 слова подзаголовка (без числа сразу после и без ` - `), короткое название папки добавляется альтернативным для поиска.

**Сиквел-номер — сезон.** Для файла с написанным сезоном (`s1e05`, `S02E01`): хвостовое число 2–4 названия при сезоне 1 или том же числе (`Хроника 2 s1e05` → «Хроника», 2×05; `Стражи 2 - S02E01` → «Стражи», 2×01), часть (`Часть 2`, `Part 2`) при сезоне 1, сезон папки ≥ 2 (`… season 2/… s1e05`) при сезоне 1 в файле. Полное название остаётся синонимом для поиска. Голое `Название 2 - 05` (без сезона в имени) не меняется: так AniDB называет записи, и нумерация META-015 переводит их в сезоны TMDB. Диапазон 2–4 и требование написанного сезона защищают `Babylon 5 S01E01`, `Area 88`, `Cyborg 009`.

**Аниме среди `show`** (`pa-catalog::metadata`). Работа типа `show` спрашивает встроенную базу аниме как аниме; путь аниме (AniList по id или поиск, Shikimori по MAL id) запускается, если TMDB нашёл японскую анимацию (`original_language = ja`, жанр 16) или TMDB не нашёл ничего, а база нашла с уверенностью ≥ 0.92. AniList ищется по английскому и оригинальному названию TMDB, потом по своим. Нашли — работа становится `anime`. Живой TMDB-матч с другим жанром (одноимённый игровой сериал) путь аниме не запускает.

**Название карточки — язык метаданных**, который приложение берёт из языка интерфейса: перевод TMDB на этом языке → (для `ru`) русское название Shikimori → название TMDB, если оно локализовано (отличается от оригинального или язык оригинала совпадает) → английский перевод TMDB → английское/ромадзи AniList → название TMDB. Так японское название без перевода больше не попадает на карточку, а русский интерфейс получает русское название везде, где его знает хоть один провайдер.

**Постер.** Порядок: TMDB (приоритет 0) → обложка AniList (10) → **постер Shikimori (20)**: `RussianInfo::poster`, абсолютный URL от сайта (`https://shikimori.io/system/animes/original/<id>.jpg`, без параметра кэша), заглушка `missing_*` — не постер. `pa-imagecache` такие URL уже скачивает (HTTPS, любой хост). Кадр из видео как запасной постер в этой задаче не делался.

**Пересчёт старых решений.** `PARSER_VERSION` 0.2.0 → 0.3.0. В начале `recognize::run` автоматические матчи (`rule`/`scorer`, без правила папки — `recomputable`), чей `parse_results.parser_version` старше, планируются заново; матч удаляется (файл распознаётся заново в том же проходе), только если план изменился: фильм ↔ серия, другие сезоны у `show` (аниме перенумеровывает META-015), другое название у работы без матча провайдера (мусор в старом названии). Иначе обновляется только версия разбора. Осиротевшие работы удаляет существующий `remove_orphans`; метаданные новых работ подтягивает следующий прогон.

## Последствия

- Хорошо — регрессионный тест `pa-catalog/tests/real_library.rs` на анонимизированной структуре медиатеки владельца (`tests/fixtures/real-library.tsv`: 1 026 видео, придуманные названия, настоящие разделители, скобки, нумерация, кириллица, хвосты сайтов и студий): каждый файл — верный тип, работа, сезон, эпизод и название эпизода. До → после: папок, ставших одним сериалом, 51/53 → 53/53; работ-фильмов 71 → 28 (нужно 28); эпизодов, записанных фильмами, 43 → 0; неверных сезонов/эпизодов 24 → 0; неверных названий 26 → 0; названий с мусором 2 → 0.
- Хорошо — замер корпуса v0 (`pa-eval`, до/после на одном сервере) не хуже ни в одной строке: парсер (title 98,13 %, number 99,22 %, season 100 %), матчер медиатеки на западном подмножестве (train + dev: Precision@auto 99,30 %, Coverage 99,30 %, тихих 11; test: 97,12 % / 98,86 %, тихих 10), скорер (Coverage 93,60 % / 87,16 %, тихих 0 / 6) и медиатека с базой аниме META-030 на всех типах (Coverage 92,56 % / 92,56 %, тихих 44 / 3) — все метрики совпадают побайтно; запросов к синтетическому TMDB +0,4 % (2 737 → 2 748 на train + dev, 589 → 598 на test: синонимы «полное название с номером сиквела» и короткое название папки). Отчёт — `tools/recognition-eval/baselines/v0/meta032.md`. Первый вариант правила «название папки — альтернативное» ухудшал test скорера (13 файлов `Gundam 0080 - …` уходили на проверку) и был сужен до замера.
- Плохо: папка фильмов без годов с номерами в начале (`Pixar/1 Toy Story.mkv`, `2 Cars.mkv`) станет сериалом «Pixar»; длительности (фильм ≫ серия) группа LIB-007 планировщику не передаёт. Исправляется вручную, правило ловит год и название папки в именах.
- Плохо: сериал, у которого число в названии и файлы `s1e`, — `Вавилон 2 s1e01` — станет «Вавилон», сезон 2 (диапазон 2–4 сужает риск, полное название остаётся синонимом для поиска).
- Плохо: после обновления первый скан один раз разбирает все автоматически распознанные файлы (без сети, порядка секунды на тысячи файлов); изменившиеся работы заново спрашивают провайдеров.
- Нейтрально: работа `show`, которую распознал путь аниме, становится `anime` (тип аниме, порядок AniDB); списки «Сериалы» показывают оба типа.

### Как проверяем соблюдение

`pa-catalog/tests/real_library.rs` (структура медиатеки и пересчёт старых решений: старые фильмы-эпизоды и мусорное название исправляются, решение пользователя остаётся), `tests/metadata_display.rs` (русская папка аниме: русское название в `ru`, английское в `en`, постер Shikimori, тип `anime`), юнит-тесты `recognize.rs` (нумерованные папки, коллекции фильмов, сиквел-сезоны и исключения), `parse/junk.rs` и `parse/mod.rs` (мусор сайтов, сезоны и теги папок), `pa-metadata/tests/shikimori.rs` (URL постера и заглушка). Замер — `pa-eval run` (parser, tmdb, scorer, медиатека с базой аниме) до/после.
