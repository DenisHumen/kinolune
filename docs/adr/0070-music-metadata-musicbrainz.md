# ADR-0070: Брать музыкальные метаданные из MusicBrainz и обложки из Cover Art Archive фоновым прогоном после скана

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** META-021, MUS-001, MUS-004, LIB-013, UI-016; `docs/research/03-metadata-recognition.md` §3.4; [docs/legal/providers.md](../legal/providers.md) §2.3; ADR-0018 (HTTP-стек ядра), ADR-0020 (теги lofty), ADR-0036 (кэш картинок)

## Контекст и проблема

Музыкальная медиатека (MUS-001, MUS-004) знает только теги файлов: у многих коллекций нет обложек, жанры записаны как попало (`Hip Hop/Rap`, `(17)`, `RnB`), у артистов нет ничего, кроме имени. MusicBrainz даёт открытые (CC0) данные релизов и артистов, Cover Art Archive — обложки, но MusicBrainz ограничивает клиента одним запросом в секунду с IP и требует User-Agent с контактом; картинки архива не лицензированы.

## Факторы решения

- Условия провайдеров: 1 запрос в секунду, User-Agent `App/Version ( contact-url )` без личного email, картинки — только показ и кэш на устройстве.
- Точность: коллекции, протеганные Picard (MBID в тегах), и коллекции без MBID (только артист, альбом, номера и длительности).
- Скан не должен ждать сети: большой фонотеке нужны десятки минут запросов.
- Тесты без сети, на выдуманных данных.

## Рассмотренные варианты

1. MusicBrainz + Cover Art Archive в ядре (`pa-metadata`, `pa-catalog`), фоновый прогон после скана, отдельные таблицы метаданных.
2. AcoustID (отпечатки) для каждого файла.
3. Задача очереди `pa-jobs` вместо фонового потока.
4. Фото артистов из Fanart.tv или Wikimedia Commons.

## Решение

Выбран вариант **1**: он укладывается в условия MusicBrainz и не задерживает скан.

- `pa_metadata::musicbrainz` и `pa_metadata::coverart` — клиенты на общем конвейере (кэш → лимит → повторы → устаревший ответ): 1 запрос в секунду без всплесков на каждый хост, 503 повторяется с паузой, User-Agent `Kinolune/<версия> ( https://github.com/DenisHumen/kinolune )`.
- Сопоставление альбома (`pa_catalog::music_metadata`): release MBID из тегов → release-group MBID → поиск по названию и альбомному артисту с ранжированием по названию (без «(Deluxe Edition)»), артисту, числу треков, году и длительностям (допуск 3 с, до трёх lookup с треками). Порог — 0,8.
- Хранение — новые таблицы `music_album_metadata` и `music_artist_metadata` (expand-only миграция `202611211000_META-021_music_metadata`); теги в `music_albums` и `music_artists` не переписываются, кроме пустого `music_artists.mbid`.
- Обложка — URL фронта release group (`…/front-500`), картинку скачивает `pa-imagecache` на устройстве; локальная обложка (файл в папке, встроенная) показывается первой.
- Жанры нормализуются (`pa_library::genre`) — и из тегов при записи трека, и из MusicBrainz; у треков без жанровых тегов в видах музыки показываются жанры альбома.
- Прогон запускает `RustLibrary` после каждого скана в фоне (`fetch_music_metadata`, свой токен отмены); виды музыки обновляются по мере работы. В тестах прогон выключен (`musicMetadata = false`), включает его `openAppLibrary`.

Не входит: AcoustID (только по opt-in с ключом пользователя или ключом проекта после подтверждения плана Open Source — LEGAL-002), фото артистов, правка тегов в файлах.

### Последствия

- Хорошо: обложки, жанры, тип релиза, лейбл и данные артистов без ключей и без серверов проекта; ответы кэшируются (`provider-cache.sqlite`), повторный прогон не ходит в сеть.
- Плохо: первый прогон большой фонотеки долгий (≈2–3 запроса на альбом, 1 в секунду); артисты без MBID ищутся только по точному единственному совпадению имени — часть артистов останется без данных.
- Требует работы: фото артистов — если появится совместимый источник; AcoustID по opt-in; настройка «не ходить в MusicBrainz» в настройках приложения.

## Плюсы и минусы вариантов (опц.)

### Вариант 2 — AcoustID

- Плюс: находит файлы без тегов.
- Минус: ключ приложения и план Open Source не подтверждены (LEGAL-002), нужен Chromaprint и декодирование каждого файла; только opt-in.

### Вариант 3 — `pa-jobs`

- Плюс: переживает перезапуск.
- Минус: прогон и так продолжается с места остановки (строки метаданных пишутся по одной), а очередь задач в FRB-слое пока используется только офлайн-копиями; фоновый поток проще.

### Вариант 4 — фото артистов

- Fanart.tv: нужен ключ проекта (решение владельца) и у картинок нет лицензии.
- Wikimedia Commons (через связь Wikidata): у каждого файла своя лицензия с обязательной атрибуцией автора на экране — без отдельной задачи на поштучную атрибуцию показывать нельзя.
