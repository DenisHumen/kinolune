# ADR-NNNN: Хранилище Twitch — шаблоны имён с id в конце, импорт чужих архивов в модель TWI-007, правила записи и AutoRecord в приложении

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта
- **Связано:** `TWI-019`, `TWI-017`, `TWI-018`, `TWI-009`, `TWI-007`, `NET-019`, `UI-015`; [ADR-0041](0041-build-flavor-mechanism.md), [ADR-0057](0057-twitch-live-notifications.md), [ADR-0062](0062-storage-targets-retention.md), [ADR-0064](0064-twitch-vod-downloader.md), [ADR-0066](0066-twitch-live-recording.md), [ADR-0067](0067-offline-copies.md); исследование 06 §4.3, §2.7

## Контекст и проблема

Загрузчик VOD (TWI-017) и рекордер эфиров (TWI-018) пишут файлы с фиксированными именами, рекордер и `AutoRecord` не подключены к приложению, сохранённые файлы не видны в модели библиотеки (`twitch_assets`), архивы, сделанные TwitchDownloader, yt-dlp и streamlink, не импортируются. Нужны: настраиваемый шаблон имён с санитизацией для Windows и SMB, дедупликация по `video_id` / `stream_id` / `slug`, импорт, UI правил записи с retention (по умолчанию 14 дней или 10 эфиров) и предупреждением о ToS, библиотека записей и загрузок, настройки места и квоты. Всё — только в full-сборке.

## Решение

- **Шаблоны** (`pa_twitch_archive::naming`). Три шаблона: папка (`{login} [{user_id}]/{year}`), имя VOD (`{date} <{categories} — >{title}`) и записи (`{date} LIVE <{categories} — >{title}`) — как в 06 §4.3. Переменные `{date} {year} {month} {time} {login} {display_name} {user_id} {title} {categories} {part} {id} {type}`; `<…>` — необязательная группа, пропадает, если переменная внутри пуста (`<` и `>` запрещены в именах Windows, поэтому свободны для синтаксиса). Суффикс id (` [v<id>]`, ` [s<id>]`) не входит в шаблон и добавляется всегда: файл, перенесённый вручную, находится по имени. Каждый компонент пути санитизируется (`meta::sanitize`: запрещённые символы Windows/SMB, конечные точки и пробелы, имена устройств DOS, ≤ 160 байт, обрезается название, не id). Папка на элемент (ADR-0064) сохраняется: `<папка>/<база>/<база>.mkv` и сайдкары. Шаблоны едут в параметрах задачи (`naming`), поэтому задачи, поставленные до смены настроек, доделываются со старыми; неверный шаблон отклоняется при сохранении (`invalid_template`), а в задаче заменяется шаблоном по умолчанию. Для части VOD (глава) `{categories}` — категория части.
- **Импорт** (`import::scan` + `library::import_dir`). Обход папки (скрытые `.tmp`, `.trash`, `*.part` пропускаются); видео сопоставляется со сайдкарами по совпадению имени без суффиксов сайдкара, по id сайдкара в имени видео или как единственное видео папки. Источники описания по убыванию надёжности: наш `.info.json` (`kinolune.twitch.vod/1`, `…live/1`), yt-dlp `.info.json` (`extractor` `twitch:*`, `webpage_url`), дамп `streamlink --json` (`plugin: twitch`, `metadata.id` — stream id), чат-JSON TwitchDownloader (`streamer`, `video.id`, `video.chapters` с `gameId`), id в имени (`[v…]`, `v…`, `[s…]`, `[c-…]`). Чат-JSON любого вида становится `twitch_chat_logs`. Регистрация: строка `files` + `twitch_assets` (`origin` `import` / `download` / `recording`), для VOD — `twitch_videos` и главы в `twitch_category_segments` (источник `import`, имена категорий — в `twitch_categories`); главы yt-dlp без id категории берутся, только если категория с таким именем уже известна. Канал без `user_id` (yt-dlp и streamlink сохраняют только логин) ищется в `twitch_streamers`, затем в Helix (`TwitchSource::user_by_login`); не найден — файл не регистрируется и считается в отчёте.
- **Корень файлов.** `files.source_id` обязателен, поэтому каждая папка с сохранёнными файлами Twitch — строка `sources` вида `twitch_archive` (`scan_into_library = 0`, `auto_scan = 0`). pa-catalog и pa-sources фильтруют этот вид в списках и в поиске по URI: папка не появляется в «Источниках» и не сканируется в медиатеку.
- **Дедупликация** (06 §4.3). Перед постановкой загрузки: нет активной задачи с тем же VOD и диапазоном и нет сохранённого файла с тем же ключом и длиной ±2 % (часть VOD — другая длина, не дубликат); иначе `duplicate` (приложение показывает «уже сохранён или скачивается»). Импорт: тот же ключ и длина — дубликат, тот же путь — уже зарегистрирован.
- **Готовые задачи** регистрируются при каждом запросе списков (`register_finished`): папка из `result.rel_path` сканируется тем же `scan`, путь — ключ, повторно не добавляется. Файлы, которых нет на диске (retention перенёс в корзину, пользователь удалил), в библиотеке не показываются.
- **Приложение** (`pa-frb` `CoreTwitchDownloads`, только full). На общей очереди базы (NET-019, ADR-0067) регистрируется и `twitch_live_record`; два места: `twitch` (загрузки, `<data>/downloads/twitch`) и `twitch_live` (записи, `<data>/recordings/twitch`, отдельно — чтобы retention правил записи не трогал скачанные VOD). Путь и квоту выбирает пользователь; при запуске существующие места не перезаписываются. Шаблоны хранятся в настройках приложения и передаются ядру при старте. Правила (`twitch_record_rules`) — по профилю и каналу; при каждом изменении `AutoRecord::apply_retention` переносит «N последних / X дней» в правила retention места.
- **AutoRecord.** `CoreTwitchDownloads::follow_live(&CoreTwitchLive)` добавляет наблюдателя событий монитора TWI-009 (вызывается в потоке монитора до отправки события в Dart): `MonitorEvent::Timeline` (`stream.online` и смена категории) канала с включённым правилом → `AutoRecord::on_change_with` ставит задачу записи с шаблонами. Монитор работает и при выключенных уведомлениях, если у каналов есть включённые правила (`LiveNotificationController.setRecordingChannels`); уведомления в этом случае не показываются.
- **UI** (только `AppFlavor.twitchArchive`, раздел «Стримы» скрыт для детских профилей — UI-015). Кнопка «Запись» на странице избранного канала → правило: автозапись (при первом включении — предупреждение о личном использовании и ToS, 06 §2.7), качество, чат, «последние N» (10) и «дней» (14), фильтр категорий из глав VOD канала. «Записи и загрузки»: идущие записи с индикаторами «идёт запись», «пауза» / «ждёт места», «N пропусков» (из чекпойнта рекордера: `gaps`, `media_ms`), сохранённые записи и загрузки (главы, чат, реклама отмечена, происхождение). Настройки: папки, квоты, шаблоны с предпросмотром, импорт папки.

## Последствия

- Хорошо: done-when TWI-019 проверяется без Twitch и FFmpeg (`tests/import.rs`): папка TwitchDownloader сопоставляется по `video_id`, главы с категориями попадают в `twitch_category_segments`.
- Хорошо: имена по умолчанию теперь содержат категории (06 §4.3); id остаётся в конце, поэтому импорт и ручной перенос работают и для старых имён.
- Плохо: папки `twitch_archive` — строки `sources`, которые скрываются фильтром в двух крейтах; новый код, читающий `sources` напрямую, должен помнить про этот вид.
- Плохо: шаблоны живут в настройках приложения, а не в базе: на сервере (SRV-016) их нужно будет передать так же.
- Ограничение: `TWITCH_VIDEO_ID` из тегов файла при импорте не читается (нужен FFmpeg); только сайдкары и имя.
- Ограничение: правила читаются для активного профиля, когда приложение решает, держать ли монитор; правила других профилей записываются, только если монитор уже работает. При активном детском профиле монитор не работает (UI-015), автозапись не начинается.
- Ограничение: запись идёт, пока приложение запущено (desktop/Android); фоновая запись без приложения — сервер (SRV-016).
- Ограничение: смена папки места не переносит уже сохранённые файлы.

## Как проверяем соблюдение

`cargo test -p pa-twitch-archive --features pa-flavor/full,testing`: `tests/import.rs` (TwitchDownloader по `video_id` с главами и чатом, yt-dlp VOD/клип и streamlink-запись с поиском канала через фейковый Helix, наши `.info.json` и имя файла, дедупликация, файлы вне диска), юнит-тесты `naming` (шаблоны по умолчанию, группы, санитизация, отказ и откат), `import` (id в именах, сопоставление). `tests/download.rs` и `tests/live.rs` — новые имена по умолчанию. `flutter test test/twitch_archive_test.dart --dart-define=KINOLUNE_FLAVOR=full` — индикаторы, правило с предупреждением, шаблоны и квота, импорт, точки входа только в full; скриншоты в `docs/screenshots/progress/twi-019/`.
