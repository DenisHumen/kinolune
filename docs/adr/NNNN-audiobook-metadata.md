# ADR-NNNN: Метаданные аудиокниг — разбор имён, описание и обложка из Open Library, неуверенное — на проверку

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (направление — запрос 2026-11-17), мейнтейнер (детали; владелец поручил решать по правилу «максимально просто для клиента»)
- **Связано:** MUS-019, MUS-018, LEGAL-002, META-021, META-035; [ADR-0107](0107-audiobooks.md), [ADR-0103](0103-content-kind-classifier.md), [ADR-0070](0070-music-metadata-musicbrainz.md)

## Контекст и проблема

MUS-018 собрал книги из файлов: автор, чтец, серия и номер берутся из тегов и пути. У реальных раздач имена разные: `Фамилия Имя - Название [Чтец, 2015, 96 kbps, MP3]`, `Автор/Серия/02 - Название`, `Sanderson, Brandon - Elantris`, `[Аудиокнига] …`, m4b из Audible с чтецом в теге композитора. Не хватало обложки и описания на странице книги, а книги, которые распознаны неуверенно, ничем не отличались от остальных.

Нужно: источник описаний и обложек без ключа (или с необязательным ключом пользователя), чьи условия это разрешают; работает для русских и английских книг; ничего, кроме названия и автора, с устройства не уходит; корпус-тест без сети в CI; «done when» ROADMAP — корпус из 100 структур распознаётся ≥ 90 % при тихих ошибках ≤ 1 %.

## Рассмотренные варианты источника

1. **Open Library** (Internet Archive): поиск `search.json` и работы `/works/{id}.json` без ключа; 1 запрос в секунду без контактного e-mail (3 — с e-mail в User-Agent); на данные каталога Internet Archive не заявляет прав; обложки `covers.openlibrary.org` по id обложки не лимитируются, условия — показывать, не выкачивать массово.
2. **Google Books**: ключ необязателен, но без ключа API сразу отвечает 429 (общая квота анонимных запросов исчерпана — проверено 2026-11-18); ключ означает проект в Google Cloud у пользователя; условия — Google APIs ToS (брендинг «Powered by Google», ограничения кэша, удаление контента по требованию). Русские издания у Google полнее.
3. **ЛитРес**: публичного API нет.

## Решение

**Источник — только Open Library** (вариант 1). Google Books не используется: без ключа он не работает, а «вставьте свой ключ Google» — та настройка, которой у клиента быть не должно. Проверка на корпусе показала, что русская классика и современная проза в Open Library есть (часто под русским названием, автор — латиницей); чего нет, то просто остаётся без описания.

**Разбор имён** (`pa_catalog::book_names`, чистые функции): `Автор - Название (читает Чтец)`, трекерный формат `[Чтец, год, битрейт, формат]`, чтец в скобках без пометки, если одно из слов — распространённое имя (`(Олег Басилашвили)`, но не `(Роман)`), `… - читает Чтец` и `…. Читает Чтец`; серии: `Автор - Серия 01 - Название`, `Автор - Серия - 01 - Название`, `Серия. Книга 2. Название`, `Название (Серия, Book 1)`, `(Серия #3)`; папки выше книги: `Автор/Название`, `Автор/Серия/02 - Название`, `Автор/Серия/Название` (автор — тот, кто похож на имя человека); `Фамилия, Имя` разворачивается; `[Аудиокнига]`, `(Unabridged)` и битрейты отбрасываются; число без разделителя — часть названия (`451 градус по Фаренгейту`, `Метро 2033`). Догадки сканера (исполнитель и альбом, взятые им из пути) тегами не считаются.

**Сопоставление** (`pa_catalog::book_metadata`): спрашиваются только книги с автором и названием. Поиск `title + author`, если точного совпадения нет — по одному названию (автор в Open Library часто латиницей). Фамилии сравниваются по согласным после транслитерации («Стругацкие» = Strugatsky, «Сапковский» = Sapkowski, однобуквенный скелет — ещё и по первой букве). Решение:

- **совпало** — то же название (без регистра, «ё», пунктуации, артикля, подзаголовка, скобок с транслитерацией) и тот же автор → на странице книги описание («О книге», свёрнуто до 5 строк, подпись «Описание: Open Library») и обложка Open Library, если в папке нет своей; среди совпавших — работа, где автор первый (не адаптация иллюстратора), затем с бо́льшим числом изданий;
- **на проверку** — название похоже (≥ 60 % слов), или книга без автора, или название общее («Рассказы», «Избранное», «Stories»): ничего из интернета не показывается, книга помечена `needs_review`, на странице — строка «Не уверены, что это за книга…»;
- **не найдено** — ничего близкого; повтор через месяц.

**Хранение** — таблица `audiobook_metadata` (миграция `202612240000_MUS-019_audiobook_metadata`), ключ — свёрнутые автор и название: одна книга на двух источниках спрашивается один раз, переименованная — заново. Ответы HTTP кэшируются в общем `provider-cache.sqlite` (поиск — месяц, работы — три месяца); совпавшие книги освежаются раз в 90 дней, ошибки сети — через час, пять ошибок подряд останавливают прогон. Прогон — продолжение фонового прогона музыкальных метаданных (META-021), та же отмена и сброс.

**Приватность**: в Open Library уходят только название и автор, прочитанные из имён и тегов; не пути, не файлы, не звук. User-Agent — имя приложения и URL проекта, без e-mail, поэтому лимит — 1 запрос в секунду.

**Корпус** (`pa-catalog/tests/audiobook_corpus.rs`): 107 структур — реальные книги и чтецы, раскладки, как у раздач и в Audible (папки частей, `CD1`/«Часть 1», m4b с тегами и без), без личных путей. Ответы Open Library записаны (`openlibrary.jsonl`), CI идёт без сети; описания работ в записи заменены заглушкой — это часто тексты издателей, в репозитории им не место. Перезапись: `KINOLUNE_RECORD_OPENLIBRARY=1` (настоящие часы, 1 запрос в секунду). Ожидаемая работа Open Library для каждой книги проверена вручную.

## Последствия

- Хорошо: без ключей и настроек; описание и обложка у большинства известных книг, русских тоже; неуверенное не показывается, а помечается; повторных запросов нет.
- Плохо: описания Open Library почти всегда на английском, даже у русских книг. Перевода нет.
- Плохо: русские книги, которых нет в Open Library под русским названием, остаются без описания (на корпусе — 28 из 107: часть современных, переводы, сборники).
- Плохо: корпус составлен и разбор настроен на нём одним и тем же человеком (агентом) — 107/107 на нём не гарантирует такой же доли на чужой медиатеке. Ошибки в реальных библиотеках добавлять в корпус.
- Плохо: исправить книгу «на проверку» пока нельзя — это интерфейс META-035 (исправление распознавания); ядро отдаёт флаг `needs_review`.

## Решения по открытым вопросам (2026-11-18)

Владелец поручил решать самим по правилу «максимально просто для клиента».

1. **Google Books** не подключаем, ни с ключом проекта, ни с ключом пользователя: без ключа не работает, ключ пользователя — лишняя настройка, ключ проекта — условия Google и отзыв ключа.
2. **Переключателя «искать описания книг в интернете» нет**: запросы идут вместе с музыкальными метаданными, которые уже включены; уходят только название и автор (как для фильмов в TMDB). В «О программе» — указание Open Library и что туда отправляется.
3. **Своя обложка в папке важнее** обложки Open Library.
4. **Неуверенные совпадения не показываются вовсе** (ни обложка, ни описание) — лучше без описания, чем с чужим.
