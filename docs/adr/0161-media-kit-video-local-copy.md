# ADR-0161: Локальная копия media_kit_video с исправлением текстуры Linux и возврат памяти после закрытия плеера

- **Статус:** Предложен
- **Дата:** 2026-11-25
- **Решают:** мейнтейнер (владелец делегировал решения)
- **Связано:** BUG-001, QA-016, PLAY-013; [ADR-0012](0012-release-0-1-player-media-kit.md)

## Контекст и проблема

BUG-001: память приложения на Linux росла с каждым открытием и закрытием плеера. После `mallopt(M_ARENA_MAX, 2)` (#295) осталась утечка живых выделений: release-сборка, Xvfb, цикл «открыть → 6 с → перемотка → 4 с → закрыть», 40 циклов — RSS +10,7 МБ/цикл, занятое в куче glibc +8 МБ/цикл.

heaptrack (30 циклов) показал одного виновника: 248,8 МБ в 30 выделениях — ровно одно на закрытый плеер, кадр 1920×1080×4 из Mesa, выделенный в потоке растеризации Flutter. Это GL-текстура, в которую Flutter (`FlPixelBufferTexture`) загружает кадры видео при программном выводе media_kit_video, а в аппаратном выводе — текстура Flutter поверх EGLImage кадра mpv. media_kit_video отпускает свою текстуру в потоке платформы (`VideoOutputManager.Dispose`), где GL-контекст Flutter не текущий: `glDeleteTextures` там ничего не освобождает, и последний кадр каждого закрытого плеера остаётся в памяти навсегда (на настоящей видеокарте — в видеопамяти).

Исправить можно только в нативном коде плагина (или в движке Flutter). Исправления в upstream media_kit_video нет (2.0.1 — последняя версия).

## Рассмотренные варианты

1. **Локальная копия media_kit_video 2.0.1 через `dependency_overrides`** (как `media_kit_libs_android_video`, PLAY-013), исправлен только `linux/`: текстура отпускается (программный вывод) или её имя удаляется (аппаратный) в потоке растеризации, при следующем кадре любого видео, где контекст Flutter текущий.
2. **Патч поверх pub-кэша при сборке** (CMake подменяет файл плагина). Хрупко: ломается при обновлении пакета и в чужих сборках.
3. **Ждать upstream.** Утечка P0 остаётся у всех пользователей Linux.

## Решение

Выбран вариант **1**. Копия лежит в `clients/flutter/packages/media_kit_video` (MIT, лицензия рядом, REUSE.toml), её подключают приложение и пример pa_player. Изменены `linux/texture_gl.cc`, `linux/texture_sw.cc`, `linux/video_output.cc` и заголовок `texture_sw.h`; Dart и другие платформы — как в upstream. CI Flutter не форматирует и не линтует копию (это не наш код). Когда upstream исправит, копию удаляем.

Дополнительно `MediaKitEngine.dispose()` на Linux через 7 с после последнего закрытого плеера (mpv уничтожает свой хэндл через 5 с) вызывает `malloc_trim(0)`: освобождённые libmpv/FFmpeg сотни мегабайт возвращаются системе, а не остаются «свободными внутри кучи» и не дробятся. Не glibc (musl) — вызов пропускается.

## Последствия

- После исправления (те же 40 циклов): RSS +0,2…0,7 МБ/цикл, занятое в куче ровное (+0,1 МБ/цикл), см. PR BUG-001.
- Последний закрытый плеер держит один кадр до открытия следующего видео — ограничено, не растёт.
- При обновлении media_kit_video копию нужно обновить вручную (перенести три файла `linux/`).
- Регрессию ловят `tools/qa/e2e/player_soak.sh` (без стенда, CI `soak.yml` при изменениях нативного стека плеера) и `run.sh --soak` (вердикт по RSS и по занятому в куче).
