# ADR-0106: Трейлер в баннере — как выбираем ролик и когда он играет

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Решают:** мейнтейнер по поручению владельца («максимально просто для клиента»)
- **Связано:** UI-036, [ADR-0100](0100-trailers-and-watched-state-art.md), LIB-005, LIB-007, NET-014, NET-015, META-027

## Контекст и проблема

[ADR-0100](0100-trailers-and-watched-state-art.md) задал источники трейлеров и поведение баннера. При реализации UI-036 остались вопросы, которые ADR-0100 не решает:
- что важнее — язык ролика или его тип;
- как совместить «трейлер играет вместо фона» с правилами YouTube API, которые запрещают рисовать что-либо поверх встроенного плеера;
- что делать на платформах без WebView;
- какие настройки нужны;
- когда «вверх» на пульте открывает трейлер.

Владелец поручил решить их самим, выбирая самый простой для пользователя вариант.

## Решение

### Выбор ролика (ядро, крейт `pa-trailers`)

1. **Источники:**
   - свой файл (extras LIB-007: сначала `trailer`, потом `teaser`);
   - трейлер медиасервера: Jellyfin/Emby `LocalTrailers` фильма, поток `/Videos/{id}/stream`;
   - ролик TMDB `videos`.

   Высший источник выигрывает сразу. Нижние даже не спрашиваются: при своём файле запроса к TMDB нет. Если интернет-трейлеры выключены, к TMDB не обращаемся совсем.
2. **Среди роликов TMDB:**
   - Трейлер и тизер всегда выше клипа: клип — это сцена из фильма, а не трейлер. Английский трейлер лучше русского клипа.
   - Дальше язык: интерфейса → оригинала → английский → любой.
   - Дальше тип: Trailer → Teaser → Clip. Featurette и прочее не берём.
   - Дальше официальный канал, YouTube раньше Vimeo, больший размер, более новый ролик.
3. **ID ролика проверяется в ядре.** У YouTube это 11 символов `[A-Za-z0-9_-]`, у Vimeo — цифры. В страницу плеера он попадает только в JSON, где `<` экранирован.
4. **Сериалы.** Трейлер медиасервера ищется только для фильмов: у элемента сериала в медиатеке нет файла на сервере. Свой файл и TMDB работают и для сериалов.

### Баннер

- **Свой и серверный трейлер** играют на месте фона, под затемнением. Плеер приложения (media_kit), без звука, по кругу, с тихим затуханием в конце каждого круга.
- **Ролик YouTube/Vimeo** играет в своей рамке 16:9 над названием: справа, на телефоне во всю ширину. Поверх рамки ничего не рисуется: ни затемнения, ни текста, ни кнопок. Этого требуют правила YouTube API. Если рамка не помещается над названием (меньше 108 логических пикселей в высоту, обычно на телефоне), в баннере только «живой» фон. Трейлер тогда открывается кнопкой.
- **«Живой» фон.** Если трейлера нет или его негде играть, backdrop медленно (24 с) приближается и смещается.
- **Нажатие на баннер** (телефон, десктоп) и кнопка «Трейлер» открывают трейлер на весь экран со звуком. Свой и серверный играют в плеере приложения, онлайн-ролик — в официальном плеере во WebView. На весь экран над плеером только полоса с заголовком, поверх плеера ничего нет.
- **«Вверх» на пульте** открывает трейлер, только если фокус в **верхнем** ряду кнопок. Из нижнего ряда «вверх» по-прежнему переходит на ряд выше. «Назад» закрывает трейлер. Фокус и прокрутка страницы остаются там, где были.
- **Пауза.** Баннер встаёт на паузу и снова играет, когда условие уходит:
  - страница прокручена больше чем на половину баннера;
  - страницу закрыл другой экран (TickerMode);
  - приложение в фоне;
  - на ТВ фокус ушёл ниже кнопок.

  Когда фокус возвращается наверх, страница сама прокручивается к началу, чтобы баннер был виден целиком.
- **Автопревью не запускается:**
  - при «Трейлеры в баннере: никогда»;
  - в режиме энергосбережения Android (`PowerManager.isPowerSaveMode`; проверяется при открытии страницы и при возврате в приложение);
  - при системном «уменьшить движение». В этом случае и фон не двигается.

### Платформы без WebView

У `webview_flutter` нет реализации для Linux и Windows. Там онлайн-ролик в баннере не играет, вместо него «живой» фон. Кнопка «Трейлер» открывает страницу ролика в приложении YouTube или в браузере (`url_launcher`). Это совпадает с решением ADR-0100 для tvOS (tvOS — отдельное SwiftUI-приложение, в UI-036 не входит).

### Настройки («Настройки → Трейлеры»)

- **«Трейлер в баннере»: всегда / только Wi-Fi / никогда.** По умолчанию «всегда». «Только Wi-Fi» отключает автопревью на мобильной сети для трейлеров, которые идут по сети (онлайн и с сервера). Свой локальный файл играет всегда. Кнопка и «вверх» работают в любом режиме: так проще, чем отдельный переключатель «показывать кнопку».
- **«Трейлеры из интернета»** — вкл./выкл., по умолчанию вкл. Выключено — к TMDB за роликами не обращаемся, YouTube и Vimeo не открываются, остаются свой файл и сервер.
- Обе настройки хранятся на устройстве (`Preferences`), между устройствами не синхронизируются.

### Приватность

- К TMDB `videos` обращаемся только при открытии карточки. Ответ кэшируется вместе с другими ответами провайдера.
- К YouTube обращаемся только когда ролик начинает играть: в баннере или на весь экран.
- Страница плеера загружается строкой с HTTPS-адресом сайта проекта как origin, как у Twitch embed: YouTube требует referrer. С этого сайта ничего не скачивается.
- Строка про YouTube/Vimeo добавлена в политику конфиденциальности (§4).

### Лицензии

Новых зависимостей нет.

| Компонент | Лицензия | Где учтено |
|---|---|---|
| `pa-trailers` (Rust) | MPL-2.0 | Использует только `serde`/`serde_json` из workspace; `cargo deny` без изменений |
| `webview_flutter`, `webview_flutter_android`, `webview_flutter_wkwebview` | BSD-3-Clause | Уже в приложении с TWI-005 |
| `connectivity_plus` | BSD-3-Clause | Уже с NET-019 |
| `url_launcher` | BSD-3-Clause | Уже с TWI-005 |

Лицензии pub-пакетов Flutter сам добавляет в экран «Лицензии» (NOTICES). Плееры YouTube и Vimeo — сторонние сервисы, а не код в сборке.

## Последствия

- Баннер с онлайн-роликом на телефоне обычно показывает «живой» фон, а не видео: рамка 16:9 над длинным описанием не помещается. Это цена соблюдения правил YouTube. Свой и серверный трейлер играют на всю ширину.
- В виджет-тестах вместо WebView и плеера подставляются фейковые поверхности (`TrailerPlatform.instance`). Реальное воспроизведение YouTube во WebView проверяется только вручную на устройстве.
- Ключ TMDB в сборке нужен для онлайн-трейлеров. Без ключа работают свой файл и сервер.
