# ADR-0128: «Исправить матч» — ID или ссылка любого из семи сайтов, «Почему?» по сигналам и один шаг на всю папку

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (поручил решать по правилу «максимально просто для клиента»), мейнтейнер
- **Связано:** UI-012, META-016 ([ADR-0101](0101-review-inbox.md)), META-017 ([ADR-0112](0112-folder-rules-release-templates.md)), META-035 ([ADR-0115](0115-folder-rules-ui.md)), META-034, LIB-014 ([ADR-0122](0122-nfo-export-ids-in-names.md)), META-030; `docs/research/03-metadata-recognition.md` §4.6

## Контекст и проблема

UI-012 просит инбокс «Нужна проверка» и «Исправить матч»: карточки с уверенностью и альтернативами, «Почему?» с топ-сигналами, поиск по всем провайдерам, вставку ID или URL (TMDB, TVDB, AniDB, MAL, Shikimori), применение ко всей группе и создание правила папки.

Большая часть уже была в `main`:

- инбокс «На проверку» с кандидатами, сигналами (`MatchSignals`), «Верно», «Это оно», поиском по названию и «Это не фильм» (META-016, ADR-0101);
- правило папки и шаблоны релиза: каждое исправление учит самую глубокую папку работы и решает всю папку сразу (META-017, ADR-0112), тип и нумерация на той же странице (META-035, ADR-0115);
- полоса кандидатов на карточке фильма или сериала и кнопка на главной (META-034); «Сохранить в файлах» (LIB-014).

Не хватало: вставки ID или ссылки (старый диалог принимал только TMDB ID и только без ядра); поиска не только в TMDB; видимой уверенности и раскрываемого «Почему?»; явного «применится ко всей папке» до выбора и отчёта после; смены типа, если выбранный результат другого вида (выбор сериала для «фильма» был ошибкой); входа в исправление с карточек главного экрана.

## Факторы решения

- Максимально просто для клиента: вставил ссылку, нажал «Это оно» — всё остальное приложение делает само.
- Никаких своих серверов (ADR-0004); ключ TheTVDB, AniDB UDP и т. п. не заводим.
- Решение пользователя окончательно и распространяется на всю папку (ADR-0101, ADR-0112).
- Не переделывать существующие экраны, а дополнить страницу работы.

## Рассмотренные варианты

1. **Разбор ссылок и ID в ядре, разрешение через то, что уже есть** (TMDB `/find`, база аниме на устройстве, список Anime-Lists, AniList), выбор и смена типа одним вызовом с отчётом.
2. Свои клиенты TheTVDB v4 и AniDB HTTP API — нужны ключ проекта или регистрация клиента, лимиты AniDB жёсткие; для вставки ID это лишнее.
3. Разбор ссылок в Dart — дублирует логику для tvOS-клиента и не знает базы аниме.

## Решение

Выбран вариант **1**.

**Что принимаем** (`pa_catalog::review_lookup::parse_pasted`): ссылки themoviedb.org (`/movie/603-…`, `/tv/1399`), thetvdb.com (`?id=81189`, `/dereferrer/series/81189`), imdb.com (`/title/tt…`), anidb.net (`/anime/69`, `/a69`, `aid=69`), myanimelist.net (`/anime/5114`), shikimori.* (`/animes/z5114-…`), anilist.co (`/anime/…`); ID с приставкой (`tvdb 81189`, `[tmdbid-603]`, `{tmdb-603}`, `tmdb movie 603`, `mal:5114`, `shiki 5114`, `anidb 69`); `tt…`; голые цифры — ID TMDB вида работы (если такого нет — другого вида). Ссылку TheTVDB с названием вместо номера (`/series/frieren`) не разрешаем: без ключа TheTVDB номер не узнать, приложение просит вставить номер.

**Как разрешаем** (`Catalog::review_lookup`, ничего не пишет): TMDB — по ID; TheTVDB и IMDb — через TMDB `/find`; AniDB, MAL, Shikimori (ID Shikimori — это ID MAL) и AniList — по базе аниме на устройстве (META-030) и списку Anime-Lists: запись AniList и сериал или фильм TMDB, при доступном AniList — его название и обложка. Результаты вида работы идут первыми. У найденного по ID сигнал `tier = "id"`: «Почему: найдено по ID TheTVDB».

**Поиск «по всем провайдерам»**: ручной поиск по названию (`review_search`) добавляет к TMDB записи базы аниме на устройстве (AniDB, AniList, MAL, Shikimori в одном индексе) — без запроса в сеть; у аниме они первыми, у остальных — только близкие названия (от 0,85). Без ключа TMDB — только они.

**Один шаг** (`Catalog::review_apply`, FRB `review_apply`): если результат другого вида — сначала тип работы (сериал TMDB у «фильма» → «Сериал», фильм TMDB → «Фильм», AniList → «Аниме», как кнопка «Тип» META-035), потом `review_choose`: все файлы работы — `user_set`, правило папки и шаблоны (META-017). Возвращает `FixReport` — сколько файлов следуют исправлению и какие папки получили правило; после «Верно» то же отдаёт `review_fix_report`. «Применение ко всей группе» — это и есть работа целиком плюс разнос по папке правилом; отдельной кнопки «применить к группе» нет: применяется всегда.

**Приложение** (страница работы, тот же экран META-016):

- «уверенность N %» у кандидата и у строки «Проверьте»; «Почему?» раскрывает сигналы списком с отметками «за» и «против»; короткая строка «Почему: …» осталась;
- над числом файлов — «Выбор применится ко всем N файлам и к новым файлам этой папки»;
- «Вставить ID или ссылку»: поле, кнопка «из буфера» (вставляет и сразу ищет), «Найти» или Enter; непонятный текст, неизвестный ID и ошибка — своими строками;
- у результата другого вида — «Тип станет: …»;
- после выбора — «Исправлено N файлов. Новые файлы в «папка» распознаются так же»;
- «Исправить распознавание» доступно из меню постера на главной (полки, «Продолжить просмотр», «Следующая серия»: правый клик, долгое нажатие, клавиша меню на пульте), пункт меню постера переименован из «Изменить метаданные» в «Исправить распознавание».

### Последствия

- Хорошо: исправление одной вставкой ссылки с любого из семи сайтов; аниме ищется без сети; выбор результата другого вида больше не ошибка; пользователь до выбора видит, что исправление пойдёт на всю папку, и после — сколько файлов исправлено.
- Плохо: ссылка TheTVDB с названием не разрешается (нужен номер); MAL/Shikimori/AniDB без базы аниме на устройстве (сборка без неё) находятся только через AniList по ID MAL.
- Нейтрально: Кинопоиск (упомянут в исследовании) не поддержан — у него нет открытого API без ключа; при необходимости — отдельной задачей.

### Как проверяем соблюдение

- `core/crates/pa-catalog/tests/fix_match_group.rs`: 24 серии в ручной очереди, вставка ссылки TheTVDB → TMDB `/find` → `review_apply` исправляет все 24 и создаёт одно правило папки, 25-я серия без сети попадает в работу; смена типа «фильм» → «сериал»; MAL, Shikimori и AniDB через базу аниме; ручной поиск находит аниме в базе.
- `pa-catalog/src/review_lookup.rs` (юнит-тесты разбора ссылок и ID).
- `clients/flutter/packages/pa_library/test/review_inbox_test.dart` (вызов через мост), `clients/flutter/app/test/fix_match_test.dart` (виджеты, скриншоты телефон / компьютер / ТВ — `docs/screenshots/progress/ui-012/`).
