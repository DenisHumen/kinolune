# ADR-NNNN. Установщик NAS-ОС: своя разметка и `bootc install to-filesystem`, `/var` в сабволюме `@var`, файл ответов

- Статус: **предложен** (DIST-005)
- Дата: 2026-11-25
- Задача: DIST-005 · исследование: [05](../research/05-nas-linux-distro.md) §2.4 · связано: [ADR-0010](0010-nas-os-phase0.md), DIST-004, DIST-006, DIST-007, DIST-010

## Контекст

Установщик (`distro/installer`, Go) должен ставить Kinolune OS на выбранный диск без участия человека (по файлу ответов) и так же из TUI (DIST-006). Требования 05 §2.4: GPT + UEFI, ESP 1 GiB, `/boot` 2 GiB, корень на btrfs с отдельным сабволюмом для `/var`, опциональный раздел данных; источник — офлайн-образ в `containers-storage` ISO, а система должна отслеживать реестр (иначе «привязка к локальному пути», и обновлений не будет никогда); подпись образа обязательна. Нельзя трогать загрузочную флешку и чужие диски.

`bootc install to-disk` умеет разметить диск сам, но не создаёт раздел данных и сабволюм для `/var`, поэтому нужна своя разметка и `to-filesystem`.

## Решение

1. **Разметка (GPT, только UEFI):** `EFI-SYSTEM` 1 GiB vfat → `/boot/efi`; `boot` 2 GiB ext4 → `/boot`; `root` btrfs (тип Linux root x86-64/arm64) → `/`; при `data_partition: true` корень = `root_size_gib` (по умолчанию 64 GiB), остаток — `kinolune-data` btrfs → `/var/srv/data/<pool>` (`nofail`). Метки разделов совпадают с метками ФС. Разметку делает `sfdisk` (util-linux есть в любой базе, `sgdisk` в fedora-bootc нет).
2. **Минимальный диск:** корень не меньше 16 GiB, итого 19 GiB + 2 MiB под GPT ≈ 20.4 GB. Это значение заменило временные 16 GB из DIST-004 (`disks.DefaultMinSize`); тест следит, чтобы числа совпадали. Раздел данных — не меньше 8 GiB.
3. **`bootc install to-filesystem` с `--skip-finalize`**, по умолчанию через `podman run --privileged --pull=never <payload> bootc …` (как в документации bootc и в 05 §2.4); вариант `runner: host` вызывает `bootc` живой системы с `--source-imgref`. `--target-imgref` по умолчанию `ghcr.io/denishumen/alpha-os:<channel>` (канал `stable`), `--enforce-container-sigpolicy` по умолчанию включён. Файл ответов **отклоняет** target с транспортом (`containers-storage:`, `oci:`, `oci-archive:`, `dir:`…) и без хоста реестра.
4. **`/var` — сабволюм `@var`** в корне btrfs. Его создаём **после** bootc (bootc требует пустую корневую ФС), копируем туда содержимое stateroot `/var` (`cp -a --reflink=auto`, метки SELinux сохраняются) и монтируем строкой в `/etc/fstab` деплоя (`subvol=/@var,compress=zstd:1`). Корень — верхний уровень btrfs, отдельного сабволюма `@` нет: его содержимое целиком принадлежит ostree и откатывается им же. Снапшоты `@var` перед обновлением — DIST-010.
5. **Конфигурация пишется прямо в `/etc` деплоя и в `@var`**, без kickstart: `/etc/hostname`; пользователь — строки в `/etc/passwd|group|shadow|gshadow` (системные учётки Fedora лежат в `/usr/lib/{passwd,group}` через nss-altfiles, строку `wheel` при необходимости копируем оттуда, как делает `useradd`), UID — первый свободный ≥ 1000 по обоим файлам, домашний каталог `/var/home/<user>` со `/etc/skel` и ключами SSH; пароль — готовый yescrypt-хеш из файла ответов (рекомендуется) либо открытый пароль, который хеширует `chpasswd --root … --crypt-method YESCRYPT` библиотекой libxcrypt образа (пароль только через stdin); NetworkManager keyfile `kinolune-lan.nmconnection` (0600) для статики или явно названного интерфейса, DHCP на любом проводном интерфейсе — штатное поведение NM без файла; `/var/lib/alpha/install.json` (схема 1: install_id, версия установщика, hostname, язык, канал, образ, диск, UUID ФС, пул данных, `first_boot`) — без секретов.
6. **Метки SELinux** для всего записанного ставит `setfiles -r <deploy> <file_contexts деплоя>`; `@var` на время настройки bind-монтируется в `<deploy>/var`, чтобы пути совпадали с политикой. Если в образе есть политика, а `setfiles` нет — установка падает, а не оставляет непомеченные файлы.
7. **Безопасность:** цель берётся только из пробы дисков DIST-004 (после разрешения `/dev/disk/by-*`); отказ, если диск исключён (загрузочный носитель установщика или текущей системы, loop/zram, оптический, read-only, маленький), если на нём что-то смонтировано, если указан раздел. Все команды записи получают только выбранный диск и его разделы (проверено тестом). Без `--yes` установка спрашивает имя диска в терминале, без терминала — отказывает. `--dry-run` печатает план и команды, ничего не трогая.
8. **Файл ответов** — JSON, `version: 1`, неизвестные поля — ошибка; все ошибки валидации выводятся сразу. Схема и пример — `distro/installer/README.md`, `distro/installer/examples/answers.json`. TUI (DIST-006) заполняет ту же структуру `answers.Answers`.

## Последствия

- `+` Один код установки для TUI, файла ответов и будущего веб-установщика; всё, кроме реальных `mkfs`/`bootc`, покрыто unit-тестами на фейковом runner.
- `+` Раздел данных и `@var` появляются с первой установки, DIST-010 не нужна миграция.
- `−` Мы зависим от раскладки ostree (`/ostree/deploy/<stateroot>/deploy/*.0`) после `bootc install`; при смене бэкенда bootc (composefs-native) это место придётся обновить — его ловит QEMU-тест.
- `−` `/var` из fstab монтируется поверх bind-монтирования stateroot; если bootc начнёт сам управлять отдельным `/var`, переходим на его механизм.
- Открыто: LUKS2 + TPM2 (DIST-022), выбор языка/часового пояса в системе (пока только в `install.json`), MOK для NVIDIA (DIST-006/LEGAL-010).
