# ADR-0148: Включение нативного плеера Twitch удалённым конфигом — неподписанная «следующая версия», kill-switch `twitch.native_player`, реальная версия приложения

- **Статус:** Предложен
- **Дата:** 2026-11-24
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** `TWI-030`, `TWI-029`, `TWI-004`, `TWI-008`, `TWI-014`, `TWI-020`, [ADR-0039](0039-remote-config-minisign.md), [ADR-0047](0047-twitch-vod-chapters.md), [ADR-0049](0049-twitch-section-ui.md), [ADR-0054](0054-twitch-native-player.md), [ADR-0144](0144-twitch-embed-windows-linux.md), [remote-config.md](../dev/remote-config.md)

## Контекст и проблема

Нативный плеер Twitch (TWI-004, TWI-014) готов, но подписанный конфиг (`serial` 2) держит `twitch.gql_playback: false` и `player: embed`. Решение владельца 2026-11-20: в full-сборке нативный плеер поверх официального embed (TWI-029). Конфиг подписывает только владелец, офлайн (ADR-0039); агент ключ не трогает. Нужно:

1. Подготовить новую версию так, чтобы PR можно было влить **до** подписи и ничего не сломать.
2. Дать аварийный откат на embed по версии и платформе, если Twitch сломает API.
3. Проверить новую версию в debug до подписи.

Найдено по ходу: приложение передавало ядру как версию для kill-switch'ей константу `kAppVersion = '0.1.0'`, а не версию сборки (`0.1.0-alpha.N`). Kill-switch с диапазоном версий не различал альфы.

## Решение

1. **Неподписанная «следующая версия» лежит отдельно:** `tools/remote-config/remote-config.next.json` (`serial` 3). `config/remote-config.json` в PR не меняется: клиенты скачивают его с `main`, а тест `published_config_is_signed_with_the_production_key` требует верную подпись. Владелец копирует файл в `config/`, подписывает `just core sign-config` и публикует (шаги — в remote-config.md). Тесты проверяют, что следующая версия валидна, на один `serial` впереди опубликованной (или уже совпадает с ней), сохраняет `updates.release_public_key`, а в full-сборке на всех платформах даёт нативный плеер и главы из GQL; store-сборка — embed.
2. **Значения Twitch — публичные, из открытых клиентов** (это не секреты: их отдаёт сайт twitch.tv каждому браузеру):
   - `gql_client_id` — client id веб-сайта twitch.tv, как в streamlink и twitch-dl;
   - `PlaybackAccessToken` — как в streamlink, TwitchLink, frosty;
   - `VideoPlayer_ChapterSelectButtonVideo` — как в yt-dlp, TwitchDownloader, twitch-dl;
   - `VideoMetadata` — как в yt-dlp и streamlink.
   Каждый хэш найден минимум в двух независимых проектах. На живом Twitch в этом PR их не проверяли: по правилу владельца живые проверки идут вечером.
3. **Kill-switch — существующий механизм `kill_switches` (ADR-0039), без нового поля схемы.** Новое поле (например, `twitch.native_disabled_for`) уже выпущенные сборки бы проигнорировали. А `kill_switches` они понимают с CORE-014. Два уровня:
   - `twitch.gql_playback` (или `twitch.*`) — выключает весь GQL: нативный плеер и главы. Работает **во всех** выпущенных сборках;
   - новое имя `twitch.native_player` — только плеер уходит на embed, главы из GQL остаются. Работает в сборках с этим изменением; старые его не знают.
   Ядро (`TwitchFeatures::resolve_for` → `EmbedReason::Killed`) и Dart (`decideTwitchRoute(killSwitchHit: …)`) учитывают оба имени.
4. **Версия для kill-switch'ей — настоящая версия сборки** (`runningVersion()`: `KINOLUNE_VERSION` из релизного workflow, иначе версия платформы), а не `kAppVersion`. Выпущенные до этого сборки всё ещё сообщают `0.1.0`. Чтобы задеть только их, достаточно kill-switch'а с `min_app_version: "0.1.0"` и `max_app_version: "0.1.0"`; будущий релиз `0.1.0` он тоже задел бы, но к тому времени его снимут.
5. **Debug-проверка без подписи:** в debug-сборке ядра (`cfg(debug_assertions)`) переменная окружения `KINOLUNE_DEBUG_REMOTE_CONFIG=<файл>` подменяет встроенную копию неподписанным документом. Кэш и сеть при этом не используются. В release-сборке кода нет, так что обойти подпись нельзя.
6. **Встроенная копия (`builtin/remote-config.json`) остаётся безопасной** (`serial` 2, нативный плеер выключен). Опубликованный конфиг с бо́льшим `serial` побеждает при первом же обновлении. Тест больше не требует, чтобы опубликованная копия совпадала со встроенной: она может быть новее.
7. Sub-only VOD по-прежнему всегда «Открыть на Twitch» — теперь это часть `decideTwitchRoute`.
8. Канареечного теста TWI-020 ещё нет (задача открыта). Когда он появится, он должен брать хэши и client id из `config/remote-config.json`, а не из переменных окружения.

## Последствия

- PR вливается без подписи; TWI-030 закрывается после публикации подписанного `serial` 3.
- В репозитории появляются публичные client id и хэши Twitch. Прежнее правило «их нет в репозитории» (twitch-live-checks.md) действовало до решения владельца включить нативный плеер.
- Если Twitch сменит хэш, нативный путь получит `gql_hash_invalid` и уйдёт на embed (`falls_back_to_embed`). Исправление — новая версия конфига с новым хэшем (опять подпись владельца).
- Решения владельца: нужен ли заранее kill-switch для сборок, которые сообщают `0.1.0` (до этого изменения); включать ли `twitch.chat_replay` (в этой версии выключен).
