# ADR-0067: Офлайн-копии — крейт `pa-offline`, копия привязана к исходному файлу, загрузчик потока отдаёт копию, одна очередь задач на базу

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта
- **Связано:** `NET-019`, `UI-018`, `CORE-011`, `CORE-012`, `LIB-010`, `LIB-018`, `LIB-020`, `PLAY-007`, `MUS-004`, `TWI-017`; [ADR-0028](0028-pa-jobs-persistent-queue.md), [ADR-0038](0038-network-playback-loopback-proxy.md), [ADR-0055](0055-profiles-parental-filters.md), [ADR-0062](0062-storage-targets-retention.md), [ADR-0064](0064-twitch-vod-downloader.md); исследование 04 §1.9

## Контекст и проблема

Фильм, эпизод, сезон, альбом или плейлист из SMB/WebDAV нужно скачать на устройство и смотреть без сети: в самолёте, на даче, с выключенным NAS. Загрузка большая (4 ГБ и больше), сеть рвётся, процесс убивает ОС. В медиатеке должен остаться один элемент — тот же прогресс, версии, избранное и синхронизация, — а играть он должен с копии, когда она есть. У элемента бывают части (LIB-020), сайдкар-субтитры (PLAY-007), локальный постер и несколько версий (LIB-010). Очередь `pa-jobs` и места хранения `pa-storage` уже есть; загрузчик Twitch (TWI-017) открывал свою очередь на базу.

## Решение

- **Крейт `pa-offline`**: тип задачи `offline_copy` в `pa-jobs`, приоритет `USER_WAITING`, место хранения `offline` (вид `downloads`, резерв 5 % тома), `bytes_total` — сумма известных размеров; шлюз и монитор `pa-storage` действуют как для любой задачи. Сезон, альбом и плейлист — по задаче на элемент; уже скачанное и скачиваемое пропускается.
- **Что копируется** (`plan`): выбранная версия или версия по умолчанию, все её части по порядку, сайдкар-субтитры каждой части и локальный постер. Пропавший необязательный файл (субтитры, постер) пропускается; пропавшее видео — `failed` с `source_missing`. Элементы локальных папок не копируются (`local`), образы дисков тоже (`unplayable`).
- **Докачка.** Файлы читаются позиционными чтениями (`ByteSource::read_at`, то есть range-запросами SMB/WebDAV) и дописываются в `<файл>.part` в `.tmp/job-<id>/out/`; длина `.part` — смещение, с которого продолжать после паузы, обрыва и убитого процесса. Отдельной карты не нужно: файл пишется последовательно. Раз в 2 с `.part` синхронизируется на диск и смещение пишется в чекпойнт (для прогресса). Обрыв соединения в пределах окна 2 мин переподключается в том же запуске с паузами 1, 2, 4 … 15 с; дольше — `retrying` с бэкоффом очереди, до 20 попыток. Готовый файл переименовывается из `.part`, поэтому при новом запуске полный файл без `.part` не перекачивается.
- **Коммит и связь.** Папка копии `<название> [<id элемента>-<id задачи>]/` с исходными путями внутри коммитится `StorageManager::commit_file` (группа хранения `movies`, `show:<id>`, `album:<id>` или `music`) и записывается в новые таблицы `offline_copies` (элемент хранения ↔ элемент медиатеки, версия) и `offline_files` (исходные `source_id` + `path` ↔ файл копии). Убитый между коммитом и записью запуск дописывает строки при повторе. Удаление элемента хранения (вручную, retention) удаляет копию каскадом; элемент в корзине копией не считается.
- **Воспроизведение с копии.** `pa_catalog::SourceOpener` (загрузчик потока, ADR-0038) сначала ищет живую копию файла по (`source_id`, `path`) и отдаёт локальный файл; иначе — сеть, как раньше. Элемент, его `streamUri`, прогресс, версии и синхронизация не меняются: копия привязана, а не новый элемент. Через тот же загрузчик без сервера работают субтитры, части и обложки. Проверка профиля (`may_open`, ADR-0055) стоит перед копией: детский профиль не откроет чужую копию.
- **«Загружено»** в музыке (MUS-004) — трек есть на устройстве: локальная папка или живая офлайн-копия (`EXISTS` по `offline_files` в запросе треков).
- **Wi-Fi only** — политика сети задачи (`unmetered` / `any`); переключатель меняет её и у незавершённых задач. Сеть сообщает приложение (`connectivity_plus`, BSD-3-Clause → `CoreOffline.set_network`), это условие всей очереди.
- **«Удалять просмотренное»** — правило retention места `offline` без группы (`watched_after_days`, избранное не трогается). Перед очисткой `sync_watched` переносит «просмотрено» активного профиля из прогресса медиатеки в `storage_items.watched_at_ms` (снимает ограничение ADR-0062 для офлайн-копий). Ручное удаление загрузки удаляет файлы сразу, без корзины (`StorageManager::delete_item`): исходник остаётся в источнике.
- **Одна очередь на базу.** `pa-frb` держит процессную очередь и менеджер мест на базу (`shared::jobs`): `CoreOffline` и `CoreTwitchDownloads` регистрируют обработчики на ней. Иначе второй `JobQueue::open` вернул бы чужие `running` в `queued`, а второй `StorageManager::attach` заменил бы шлюз первого.
- **Приложение.** `CoreOffline` в `pa-frb`; в Dart — `OfflineController` (список, состояние элемента, события прогресса из очереди). Кнопка «Скачать» на странице фильма (с выбором версии), «Скачать сезон» на странице сериала и отметка на эпизоде, «Скачать альбом» и «Скачать плейлист» в музыке, «Скачать» в контекстном меню медиатеки; экран «Загрузки» с местом, паузой, отменой, повтором, удалением и настройками (папка на десктопе, Wi-Fi only, «удалять просмотренное»), тот же блок в настройках. Папка по умолчанию — внешние файлы приложения на Android, `<data>/downloads/offline` на десктопе; пока в ней есть копии или загрузки, она не меняется (`busy`).

## Последствия

- Хорошо: офлайн-воспроизведение не требует изменений в плеере, элементах и синхронизации; всё, что идёт через загрузчик потока, автоматически берёт копию.
- Хорошо: 4 ГБ с Samba на стенде докачиваются после остановки сервера и после SIGKILL процесса; файл совпадает побайтно (`tests/servers.rs`).
- Плохо: локальная копия всё равно идёт через loopback-прокси, а не прямым путём к файлу; накладные расходы малы (так же играют сетевые файлы).
- Плохо: копия привязана по пути в источнике; переименованный в источнике файл после пересканирования — новый путь, старая копия перестаёт находиться (место освобождает удаление или retention).
- Ограничение: фоновые загрузки идут, пока жив процесс приложения. Android WorkManager + foreground service `dataSync` и iOS `BGProcessingTask` из «Что» задачи не сделаны — нужна платформенная обвязка; после перезапуска приложения загрузки продолжаются сами.
- Ограничение: «просмотрено» для retention берётся из активного профиля в момент очистки.
- Решение владельца: включать ли Wi-Fi only по умолчанию на десктопе (сейчас включено везде; на десктопе с Ethernet это ничего не меняет).

## Как проверяем соблюдение

`cargo test -p pa-offline` (`tests/offline.rs`: копия с субтитрами и постером играет через `SourceOpener` с выключенным источником; обрыв в пределах окна и долгий обрыв с повтором — докачка со смещения; пауза, продолжение и отмена без остатков в `.tmp`; SIGKILL процесса и докачка с `.part`; сезон и весь сериал; «удалять просмотренное»; Wi-Fi only на мобильной сети; папка не меняется под копиями; локальные элементы не копируются). `core/crates/pa-offline/tests/servers/run.sh` — стенд Samba + WebDAV LIB-018: 4 ГБ с SMB с остановкой Samba на 20 с и SIGKILL, побайтная сверка, воспроизведение через прокси с остановленными серверами; эпизоды с субтитрами с WebDAV. `cargo test -p pa-library --test schema` — новые таблицы. `flutter test test/offline_test.dart` — кнопка, выбор версии, экран загрузок по событиям, настройки.
