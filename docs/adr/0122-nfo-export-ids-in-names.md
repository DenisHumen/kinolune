# ADR-0122: Знания в файлах: NFO в формате Kodi/Jellyfin и ID в имени папки по команде пользователя, импорт при скане

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (направление: «максимально просто для клиента», решения делегированы), мейнтейнер (детали)
- **Связано:** LIB-014 (эта задача), LIB-007 (чтение NFO), META-017 ([ADR-0112](0112-folder-rules-release-templates.md)), NET-023 ([ADR-0104](0104-source-writes.md)), LIB-004 (переносы файлов), `docs/research/03-metadata-recognition.md` §4.6

## Контекст и проблема

Медиатека знает о работе больше, чем написано в именах файлов: верный результат TMDB, исправления пользователя, описание. Это знание живёт только в базе приложения. После переустановки, на новом устройстве без синхронизации или в другом плеере (Jellyfin, Kodi, Plex) всё распознаётся заново, и те же ошибки повторяются. Стандартных способов положить знание рядом с файлами два: NFO-файл Kodi/Jellyfin и ID в имени папки (`[tmdbid-603]` у Jellyfin, `{tmdb-603}` у Plex). Чтение NFO при скане уже есть (LIB-007): ID из `movie.nfo`, `<видео>.nfo` и `tvshow.nfo` решают работу с `decided_by = nfo`. Не хватало записи и чтения ID из имён.

Открытые вопросы владелец поручил решить самим по правилу «максимально просто для клиента».

## Факторы решения

- Ничего не писать в чужие папки без явной команды пользователя.
- Не терять пользовательские файлы: свой NFO пользователя не затирается молча.
- Источники только для чтения и медиасерверы не трогать.
- Результат должен читать Jellyfin (done when задачи) и сам Kinolune.
- Не ломать то, что рядом: субтитры и другие сайдкары привязаны к имени видео.
- Без миграций базы и новых зависимостей.

## Рассмотренные варианты

1. Автоматическая запись NFO после каждого распознавания.
2. **Запись по команде со страницы «Исправить распознавание» через ядро записи NET-023.**
3. Экспорт всей медиатеки одной кнопкой в настройках.

## Решение

Выбран вариант **2**. Автоматическая запись (1) меняет файлы на NAS без ведома пользователя и плодит мусор при ошибочном распознавании. Массовый экспорт (3) можно добавить позже поверх тех же функций.

**Где кнопки.** Раздел «Сохранить в файлах» на странице «Исправить распознавание», под «Тип и нумерация»:

- «Записать NFO» (`knowledge-nfo`), под кнопкой — пути файлов, которые будут записаны;
- «Добавить ID в имя папки» (`knowledge-rename`), под кнопкой — новое имя папки.

Без ID провайдера раздел говорит «Сначала выберите верный результат». Если часть файлов в источнике только для чтения — об этом строка, туда ничего не пишется.

**Что пишется в NFO** (`pa_catalog::knowledge::nfo_xml`): корень `<movie>` или `<tvshow>`; `title`, `originaltitle`, `year`, `runtime` (минуты), `plot`, `genre`; ID — `<uniqueid type="…" default="true">` (первый — TMDB) и старые теги `<tmdbid>`, `<imdbid>`, `<tvdbid>`, `<anidbid>`. Берутся только ID своего типа: у фильма TMDB `movie`, у сериала `tv`. Кодировка UTF-8, спецсимволы экранируются. NFO эпизодов не пишутся: Jellyfin и Kodi находят сериал по `tvshow.nfo`, а эпизоды — по номерам в именах.

**Куда пишется NFO.**

| Работа | Файл |
|---|---|
| Фильм в своей папке (группа `movie_folder`) или папка диска (`BDMV`, `VIDEO_TS`) | `movie.nfo` в этой папке |
| Фильм вперемешку с другими файлами, образ `.iso` | `<имя видео>.nfo` рядом |
| Сериал, аниме | `tvshow.nfo` в папке сериала: папка эпизодов, а если она — сезон (`Season 1`, `S01`, `Сезон 2`, `Specials`), то папка над ней |

Для сериала папка над сезоном берётся, только если она названа как работа (любое из её названий) или уже несёт ID. Иначе это может быть папка «Сериалы» со многими шоу. В корень источника и в «свалку» (группа `loose`) `tvshow.nfo` не пишется. Экстры, сэмплы и игнорируемые файлы не влияют на выбор мест.

**Чужой NFO.** Если файл уже есть, страница показывает «— уже есть, будет заменён», а «Записать NFO» спрашивает «Заменить NFO?». После согласия старый файл уходит в корзину источника (`Conflict::Replace`, ADR-0104), оттуда его можно вернуть. В ядре без `replace` существующий файл пропускается (`Conflict::Skip`).

**ID в имени.** Пишется форма Jellyfin `[tmdbid-438631]`, а если TMDB нет — `[imdbid-tt…]` (фильм) или `[tvdbid-…]` (сериал). Форма проверена в Docker-тесте: Jellyfin 10.10.7 без интернета берёт ID из такого имени папки. Переименовывается только папка, которая принадлежит работе целиком (папка фильма или диска, папка сериала по правилам выше). Отдельные файлы не переименовываются, иначе субтитры и другие сайдкары потеряют связь с видео. Папка, в имени которой уже есть ID, не переименовывается. Занятое имя не заменяется (`Conflict::Skip`). Совпадения файлов и прогресс переживают переименование: переименование идёт через `refresh_after_write`, а LIB-004 узнаёт перенесённые файлы по отпечатку (проверено тестом).

**Импорт.**

- NFO читается как раньше (LIB-007).
- Новое: `pa_scanner::structure::ids_in_name` читает формы `[tmdbid-…]`, `[tmdbid=…]`, `{tmdb-…}`, `[imdbid-tt…]`, `{imdb-tt…}`, `[tvdbid-…]`, `{tvdb-…}`, `anidb` так же. Такой ID в `recognize` работает как ID из NFO (`decided_by = nfo`, уверенность 1), но NFO важнее.
  - У фильма ID берётся из имени файла, затем из имени его папки фильма или диска.
  - У сериала — из папки группы и папок выше. Для группы-«свалки» ID из имени папки не берётся.
- Отдельного значения `decided_by` нет: и NFO, и имя — это «знание в файлах», а CHECK в схеме не меняется. Поэтому миграции нет.
- Совпадения, которые уже есть, не пересчитываются. Новые ID действуют на новые файлы и на новую медиатеку над теми же файлами (проверено тестом).

**Безопасность.**

- Все записи идут через `pa_vfs::files` (`upload`, `rename`), с той же проверкой имён и корзиной, что в NET-023.
- Источники без записи определяются пробой `files::writability`. Недоступный источник считается только для чтения.
- Профиль с ограничениями видит раздел только у видимых ему работ (`require_visible`).

### Последствия

- Хорошо:
  - знание о работе переживает переустановку и переход на Jellyfin/Kodi;
  - ничего не пишется без команды, свой NFO пользователя не теряется;
  - без миграций и новых зависимостей.
- Плохо:
  - NFO эпизодов и артворк (`poster.jpg`) не записываются;
  - массового экспорта нет — по одной работе;
  - ID в имени отдельного файла не ставится (только папка);
  - уже распознанные файлы не перераспознаются по новым ID в именах до сброса распознавания.

## Подтверждение

- `core/crates/pa-catalog/tests/knowledge.rs`:

  - запись, пропуск существующего, замена с корзиной;
  - переименование с сохранением работ;
  - импорт ID из имени и из записанных NFO в новую медиатеку.
- Юнит-тесты `knowledge`, `recognize::ids_in_names_decide_like_nfo`, `structure::ids_in_names`.
- `core/crates/pa-catalog/tests/nfo_jellyfin/run.sh` (done when):
  - Kinolune записывает `movie.nfo`, `tvshow.nfo` и переименовывает папку с `[tmdbid-550]`;
  - Jellyfin `jellyfin/jellyfin:10.10.7` в своём контейнере `pa-test-lib014-jellyfin` на Docker-сети без интернета показывает названия, описания и `ProviderIds` (Tmdb, Imdb, Tvdb) из этих файлов.

- `clients/flutter/app/test/knowledge_section_test.dart` (раздел, диалог замены, переименование) и `packages/pa_library/test/review_inbox_test.dart` (вызовы через мост).
