# ADR-0136: Готовность к подписке Kinolune+ — платные только облачные сервисы, локальное бесплатно навсегда; «швы» в коде закладываются уже сейчас

- **Статус:** Принят (решение владельца 2026-11-19)
- **Дата:** 2026-11-19
- **Решают:** владелец проекта, мейнтейнер
- **Связано:** STRATEGY.md §4 и §12, ROADMAP §3.26 (SUB-001…SUB-018), SYNC-007 ([ADR-0129](0129-folder-sync.md)), SRV-013, META-020, UI-026, LEGAL-008, PKG-022

## Контекст и проблема

Стратегия v2 (2026-11-13): open source под MPL-2.0, всё работает локально, денег — только добровольные пожертвования, своих серверов нет.

Владелец (2026-11-19): в будущем, **после полной реализации проекта и когда появится аудитория**, ввести подписку. Часть функционала будет по подписке, но так, чтобы люди «не бесились» и охотно её покупали. Включать её не сразу, но готовить уже сейчас. Новые модули должны писаться с этим учётом, а для уже написанных нужно знать, что поправить, чтобы потом осталось «немного доделать».

Ограничения:
- Код клиента открыт (MPL-2.0). Если закрыть платой локальную функцию, её вырежут в форке за вечер, а сообщество обидится.
- Сторы (App Store, Google Play) требуют оплату цифровой подписки через свой IAP (LEGAL-008).
- Приватность — главное обещание проекта: «мы не знаем, кто и что смотрит».

## Решение

### 1. Что платное, а что бесплатно навсегда

**Платное (Kinolune+)** — только то, что требует **нашего сервера, наших ключей или нашей себестоимости**:

| Сервис | Почему платно | Бесплатная альтернатива, которая остаётся |
|---|---|---|
| Доступ к медиатеке вне дома через наш ретранслятор | трафик и серверы | прямое подключение, свой iroh-relay (SRV-013), VPN пользователя |
| Облачная синхронизация и бэкап (E2E-шифрование) | хранилище | LAN-синхронизация, синхронизация через свою папку (SYNC-007) |
| Push-уведомления на телефон (новая серия, загрузка готова, эфир) | серверы push | локальные уведомления и баннеры (UI-026) |
| Расширенные квоты метаданных и субтитров через наш прокси (TMDB, Fanart.tv, OpenSubtitles VIP) | платные ключи и лимиты | базовые лимиты и **свой ключ** пользователя |
| ИИ-функции: распознавание «трудных» файлов (META-020), перевод субтитров, умный поиск и подборки, краткое содержание серий | стоимость моделей | всё распознавание без ИИ; свой ключ ИИ-провайдера или локальная модель |
| Удобство: бета-канал с ранним доступом, голос в выборе задач, приоритетная помощь по отчётам | время команды | обычный канал обновлений, issues на GitHub |
| Косметика: темы, иконки приложения, обои главной, значок «поддерживает проект» | — | стандартное оформление |

Сборки из магазинов (Google Play, App Store, tvOS) с автообновлением — тоже кандидат, но как покупка самого приложения, а не подписка. Решение о модели для магазинов принимается при запуске (SUB-016).

**Бесплатно навсегда** (не трогать ни при каких условиях):
- воспроизведение, все кодеки, HDR и Dolby Vision, звук и passthrough, субтитры;
- число источников, размер медиатеки, профили семьи, родительский контроль;
- распознавание без ИИ, метаданные со своим ключом;
- синхронизация между своими устройствами по LAN и через свою папку, офлайн-загрузки;
- медиасервер (режим B), NAS-дистрибутив, Twitch;
- всё, что когда-то было бесплатным: при переводе функции в подписку у тех, кто ей уже пользуется, она остаётся навсегда.

Нет рекламы и нет телеметрии «для бесплатных».

### 2. Как это устроено в коде («швы»)

Платным делает **сервис**: аккаунт и наш сервер. Клиентский код платных функций остаётся открытым. Без нашего сервера облачная часть просто не работает, поэтому форку нечего «взламывать».

Каждая функция-кандидат пишется через **интерфейс с бесплатной локальной реализацией по умолчанию**. Облачная реализация потом добавляется как ещё одна реализация того же интерфейса, без переделки вызывающего кода:

| Шов | Где | Реализации сейчас | Реализация Kinolune+ потом |
|---|---|---|---|
| `Entitlements` — единственное место, где решается «доступно ли» | `pa-runtime` (SUB-002) | `LocalFree`: всё из списка «бесплатно навсегда» доступно, облачных функций нет | подписка аккаунта (SUB-010) |
| `SyncBackend` — способ доставки журнала операций | `pa-sync` (SUB-004) | LAN, папка (SYNC-007) | облако E2E (SUB-012) |
| `RemoteAccess` — транспорт вне дома | `pa-sync`/SRV (SUB-006) | прямое, iroh со своим relay (SRV-013) | наш ретранслятор (SUB-011) |
| `ApiKeySource` — откуда ключ провайдера | `pa-metadata` и др. (SUB-003) | ключ сборки (`CARGO_PA_*`), ключ пользователя | наш прокси с квотами (SUB-014) |
| `Notifier` — как доставить уведомление | `pa-runtime` + UI (SUB-005) | локальные уведомления, баннеры UI-026 | push (SUB-013) |
| `AiProvider` — модель для ИИ-функций | новый крейт (SUB-007) | выключено, ключ пользователя, локальная модель | наш ИИ-сервис (SUB-015) |

Правила:
1. **Никаких проверок «платный ли пользователь» в коде функций.** Функция спрашивает только `Entitlements` (одна точка), UI — один общий виджет-метку «Kinolune+». Пока подписки нет, `Entitlements` всегда отвечает по `LocalFree`, и платных кнопок в интерфейсе нет.
2. **Функции из списка «бесплатно навсегда» никогда не спрашивают `Entitlements`.**
3. **Облачное — только по включению пользователя** (opt-in) и с шифрованием на устройстве: ключи не покидают устройства, сервер видит только зашифрованные блоки и счётчики квот. Аккаунт не связывается ни с какой телеметрией.
4. **Без аккаунта всё бесплатное работает полностью** — аккаунт нужен только облачным сервисам.
5. Серверная часть сервисов — отдельный репозиторий или каталог при запуске (SUB-010); лицензия решается тогда. Клиент — MPL-2.0, как сейчас.
6. Новые модули в областях из таблицы пишутся сразу через соответствующий шов. Существующие приводятся к нему задачами SUB-002…SUB-007 (см. ниже).

### 3. Что уже написано и что поправить

| Модуль | Сейчас | Что поправить | Задача |
|---|---|---|---|
| `pa-metadata` (`key.rs`), TMDB, Fanart.tv (ADR-0132), OpenSubtitles (ADR-0108) | ключ сборки или пользователя выбирается в каждом клиенте отдельно | общий `ApiKeySource`: пользователь → сборка → (потом) прокси | SUB-003 |
| `pa-sync` LAN и папка (ADR-0129) | два независимых пути | общий `SyncBackend`; облако — третья реализация | SUB-004 |
| уведомления: баннеры UI-026, локальные уведомления Android/iOS, Twitch «в эфире» (TWI-009) | вызываются напрямую | `Notifier` с локальной реализацией | SUB-005 |
| удалённый доступ: SRV-013 (iroh) | ещё не сделан | писать сразу через `RemoteAccess` | SUB-006 |
| META-020 LLM-fallback | ещё не сделан | писать сразу через `AiProvider` | SUB-007 |
| обновления (PKG-022) | канал stable | канал «бета» как параметр, доступ к нему потом через `Entitlements` | SUB-008 |
| настройки и «О программе» | — | место под аккаунт и Kinolune+ (скрыто, пока подписки нет) | SUB-002 |

### 4. Когда включать

Задачи-заготовки (SUB-002…SUB-008) делаются в ходе основного плана и считаются в шкале «Система». Запуск подписки (SUB-010…SUB-018) — отдельная веха **M13**. Она начинается только после 100 % основного плана и только когда есть аудитория. Решение о запуске, цене и составе — за владельцем. M13 считается отдельной шкалой «Подписка» и в «Систему» не входит.

## Рассмотренные варианты

- **Закрыть платой локальные функции (как Infuse Pro: кодеки, Dolby, число источников)** — отвергнуто: обходится форком, вызывает раздражение, противоречит open source.
- **Закрытый платный модуль в клиенте** (MPL-2.0 это допускает) — отвергнуто: ломает доверие и прозрачность, и всё равно не защищает от форка.
- **Только пожертвования (v2)** — остаётся до запуска подписки; после запуска пожертвования сохраняются.

## Последствия

- Агенты и контрибьюторы в областях из таблицы §2 пишут код через шов и не добавляют проверок «платности».
- В интерфейсе до запуска M13 нет платных кнопок, меток «Pro» и упоминаний подписки.
- `docs/STRATEGY.md` получает §12; при запуске нужна стратегия v3: облачные серверы, политика конфиденциальности, условия, налоги (SUB-017, SUB-018).
