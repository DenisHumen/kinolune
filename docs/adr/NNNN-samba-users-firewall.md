# ADR-NNNN: Samba, пользователи и firewall Kinolune OS: без анонимного доступа, корневой помощник с типизированными операциями, SSH выключен

- **Статус:** Предложен
- **Дата:** 2026-11-26
- **Решают:** мейнтейнер (владелец делегировал решения)
- **Связано:** DIST-018, DIST-013, DIST-014, DIST-005, BUG-034; [ADR-0165](0165-alpha-admin-backend.md), [ADR-0010](0010-nas-os-phase0.md); [исследование 05](../research/05-nas-linux-distro.md) §5.2

## Контекст и проблема

В образе фазы 0 (DIST-001) Samba настроена статическим `smb.conf`: одна шара `Media`, `guest ok = yes`, `map to guest = Bad User`. Ручная установка в ВМ (ISO `0.0.0-ci.7`) показала, что `smbclient -N -L` и `smbclient -N //host/Media -c ls` работают без пароля: любое устройство в сети видит и читает медиатеку. Пользователей Samba нет вовсе, личных папок и Time Machine нет. SSH включён и открыт в firewall, хотя 05 §5.2 говорит «SSH по умолчанию выключен». Зона `home` firewalld открывает лишнее (`ssh`, порты NetBIOS 137–139 сервиса `samba`).

Нужно решить: кто и как получает доступ к шарам; откуда Samba берёт пароли; как админка, работающая без root (ADR-0165), меняет пользователей, базу паролей Samba и её конфиг; что открыто в firewall и что с SSH.

## Факторы решения

- Просто для обычного человека: один логин и пароль на админку, «Общие папки» Windows и Finder на Mac.
- Приватность: медиатека и личные файлы не видны всей сети без явного решения владельца.
- ADR-0165: взлом веб-демона не должен давать root или новых администраторов.
- Конфиг Samba должен обновляться вместе с образом ОС (`/etc` при обновлении bootc сливается трёхсторонне, локально изменённый файл образ не перезапишет).
- Телевизоры в LAN часто не умеют вводить пароль (05 §5.2: «чтение для гостей опционально»).

## Рассмотренные варианты

**Анонимный доступ к `Media`.** 1) Как в фазе 0: гость читает всегда. 2) Гостей нет совсем. 3) По умолчанию только по паролю, чтение для гостей включается в админке.

**Права на изменения.** 1) Дать демону `alpha-admin` запись в `/etc/samba` и `/var/lib/samba`. 2) AccountsService (`org.freedesktop.Accounts`) для пользователей + polkit, Samba — отдельно. 3) Корневой помощник с фиксированным набором типизированных операций (как `alpha-admin-auth`), конфиг рендерит он сам из типизированных настроек.

**Пароли Samba.** Samba не умеет проверять пароль по хэшу yescrypt из `/etc/shadow`, ей нужен NT-хэш в своей базе (`passdb.tdb`). Значит, пароль Samba можно записать только тогда, когда открытый пароль известен: при создании пользователя и смене пароля, при входе в админку, в установщике.

## Решение

**Анонимный доступ — вариант 3.** По умолчанию все шары только по паролю: `map to guest = Never`, `restrict anonymous = 2`, анонимный список шар (`smbclient -N -L`) отказывает. Анонимной записи нет ни в каком режиме. Настройка «Чтение медиатеки без пароля» (`media_guest_read`, по умолчанию выключена) делает `Media` доступной гостю только на чтение (`map to guest = Bad User`, `restrict anonymous = 0`, `guest ok = yes`, `read only` для гостя); личные папки и Time Machine гостю недоступны всегда. ROADMAP и ADR явно анонимное чтение по умолчанию не требуют, а 05 §5.2 называет его опцией.

**Шары** (генерируются, путь данных — `/var/srv`):

| Шара | Путь | Кто |
|---|---|---|
| `Media` — «Медиатека» | `/var/srv/media` (`2775 root:alpha-users`) | пользователи NAS читают и пишут; гость — только чтение, если включено |
| `Users` — «Личные папки» | `/var/srv/users/<имя>` (`0700` владелец) | каждый видит только свою папку (`hide unreadable`) |
| `TimeMachine` — «Time Machine» | `/var/srv/timemachine/<имя>` (`0700` владелец) | резервные копии Mac, своя папка у каждого (`fruit:time machine`), шару можно выключить |

«Пользователи NAS» — люди (UID ≥ 1000) в группах `alpha-users`, `wheel` или `alpha-admin`. Общие параметры: SMB3 минимум, `smb ports = 445` (NetBIOS выключен), `vfs_fruit` + `streams_xattr` для macOS, `server string = Kinolune OS (%h)` (BUG-034), Samba сама анонсирует `_smb._tcp` и `_adisk._tcp` через Avahi; `<имя>.local` публикует Avahi, Windows находит NAS через `wsdd`.

**Права — вариант 3.** Новый помощник `alpha-admin-priv` (root, socket-activated `Accept=yes`, сокет `/run/alpha-admin/priv.sock` `0600 alpha-admin`, проверка `SO_PEERCRED`) выполняет только фиксированные операции: список пользователей; создать пользователя, сменить пароль, сделать администратором, удалить; синхронизировать пароль Samba; прочитать и записать настройки общих папок; включить или выключить SSH. Произвольных команд, путей и текста конфига он не принимает: настройки — несколько булевых полей, `smb.conf` рендерит сам помощник. Вариант 1 позволил бы взломанному демону вписать в `smb.conf` `root preexec` и получить root; вариант 2 не закрывает Samba и требует ещё одного сервиса в образе.

**Повторный ввод пароля администратора.** Создание и удаление пользователей, смена чужого пароля и прав администратора требуют в запросе пароль действующего администратора (`admin_password`, как `sudo`); помощник сам проверяет его через PAM и членство в `wheel`/`alpha-admin`. Демон с украденной сессией или взломанный демон без пароля администратора нового администратора не создаст. Нельзя удалить себя, снять права с себя и удалить или понизить последнего администратора. Неверный пароль считается в блокировке входа (ADR-0165).

**Синхронизация паролей Samba** (`smbpasswd -a -s`, список и удаление — `pdbedit`):

- при создании пользователя и смене пароля через админку;
- при каждом успешном входе в админку (помощник ещё раз проверяет пароль через PAM; так подтягивается пароль, сменённый в консоли через `passwd`);
- установщик (DIST-005), если пароль введён открытым текстом, кладёт NT-хэш первого пользователя в `/var/lib/alpha/samba/import.smbpasswd` (`0600 root`), при первой загрузке он импортируется `pdbedit -i` и удаляется. С `password_hash` в файле ответов пароль Samba появится при первом входе в админку.

Удаление пользователя: `userdel -r` (в `/var/home` только настройки оболочки и ключи SSH), запись Samba удаляется, а его папки в `Users` и `TimeMachine` не стираются, а переименовываются в `deleted-<имя>-<время>` и передаются `root:wheel` — администратор может забрать или удалить файлы.

**После ревью безопасности (2026-11-26):**

- Удаление, снятие прав и смена пароля пользователя завершают его сессии админки (`auth.Store.RevokeUser`; при смене собственного пароля остаётся текущая сессия), а каждый запрос заново проверяет по `/etc/group` и `/usr/lib/group`, что пользователь всё ещё администратор.
- Удаление и смена пароля завершают его SMB-сессии: процессы `smbd` этого пользователя из `smbstatus --brief --json`, проверенные по `comm`, получают `SIGTERM`.
- UID не переиспользуются: новый пользователь получает UID выше максимального из когда-либо выданных (`/var/lib/alpha/uid-high`), поэтому старые файлы и открытые соединения удалённого пользователя ему не достаются.
- Все изменения пользователей идут под общей блокировкой (`flock` на `/run/alpha-admin/users.lock`): проверка «последний администратор» и само изменение не перемешиваются между параллельными процессами помощника.
- Помощник считает ключи SSH без перехода по символическим ссылкам, только в обычных файлах владельца домашнего каталога и не больше 1 МиБ.

**Конфиг.** Настройки — `/var/lib/alpha/samba/settings.json`; рендер — `/etc/samba/smb.conf.d/kinolune.conf`, его подключает `include` в конце `[global]` статического `/etc/samba/smb.conf`. `alpha-samba-config.service` (до `smb.service`) рендерит файл заново при каждой загрузке и создаёт личные папки пользователей, так что новая версия шаблона приходит с обновлением ОС, а пользователь, созданный в консоли, получает свои папки. После изменения настроек помощник проверяет конфиг `testparm` и перечитывает его (`smbcontrol smbd reload-config`). В образе лежит отрендеренный файл по умолчанию (golden-тест сверяет его с кодом). SELinux: шарам задан тип `samba_share_t` (`file_contexts.local` в образе и `z` в `tmpfiles.d`).

**Firewall:** зона по умолчанию `home`; открыты только `http`, `https` (админка), `445/tcp` (SMB), `8487/tcp` (медиасервер), `mdns`, `ws-discovery` и `dhcpv6-client` (без него не работает IPv6 по DHCPv6 в домашних сетях). `ssh`, `samba-client` и порты NetBIOS 137–139 закрыты. Открытие `smb` в API теперь означает `445/tcp`, а при закрытии убирается и старый сервис `samba` установленных систем; новое открытие `ssh` — для SSH. Каждое изменение — сразу и в постоянной конфигурации.

**SSH выключен по умолчанию.** `sshd.service` выключен пресетом, `ssh` в firewall закрыт, вход по паролю запрещён (`/etc/ssh/sshd_config.d/40-kinolune.conf`: только ключи). Только на **свежей установке с ключами** `alpha-ssh-firstboot.service` один раз при первой загрузке включает SSH и открывает порт. Свежая установка с ключами — это метка установщика `/var/lib/alpha/ssh-keys-at-install` (ключи в файле ответов) или `bootc install --root-ssh-authorized-keys` без нашего установщика (нет `install.json`: разработка и CI). На обновлённой системе ничего не включается и не открывается: `sshd` остаётся включённым или выключенным, как был. Дальше SSH включается и выключается в админке (`PUT /api/v1/ssh`: помощник — `systemctl enable/disable --now sshd`, демон — открытие `ssh` в firewalld). Управление ключами из админки — вместе с веб-интерфейсом (DIST-014).

## Последствия

- Медиатека и личные файлы закрыты по умолчанию; телевизор без ввода пароля работает после одного переключателя в админке.
- Пароль Samba = пароль пользователя ОС, но живёт в отдельной базе: пароль, сменённый в консоли, попадёт в Samba после ближайшего входа в админку или смены пароля через неё.
- Ещё один корневой помощник; его поверхность — фиксированный набор операций с проверкой имён и паролей, команды запускаются без shell, пароли идут только через stdin.
- Существующие установки после обновления: состояние `sshd` не меняется. Но если файл зоны `home` локально не менялся, он заменяется новым, где `ssh` нет, и порт 22 закрывается — снова открыть его можно через `PUT /api/v1/ssh`. Анонимное чтение `Media` пропадает, пока его не включат в админке.
- Права «только чтение медиатеки» для отдельных членов семьи и квоты Time Machine — позже, отдельными настройками.

## Решения мейнтейнера

- Анонимного доступа по умолчанию нет; чтение медиатеки без пароля — переключатель в админке, по умолчанию выключен (подтверждено владельцем 2026-11-26).
- Все пользователи NAS могут писать в `Media` (подтверждено владельцем 2026-11-26).
- Изменения пользователей требуют пароль администратора (подтверждено владельцем 2026-11-26).
- SSH включается автоматически только при свежей установке с ключами (подтверждено владельцем 2026-11-26; поведение при обновлении уточнено по итогам ревью безопасности).
