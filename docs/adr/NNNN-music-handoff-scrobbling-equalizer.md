# ADR-NNNN: Музыка на другом устройстве, скробблинг Last.fm/ListenBrainz, эквалайзер

- **Статус:** Предложен
- **Дата:** 2026-11-24
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** `MUS-015`, `MUS-003` ([ADR-0063](0063-music-queue-per-profile-prefs.md)), `SYNC-003` ([ADR-0044](0044-playback-handoff.md)), `UI-027` (сообщение `input`), `SYNC-010` (контейнер `seal`), `PLAY-004` (фильтры звука), `MUS-009` (bit-perfect), [ADR-0018](0018-metadata-providers-blocking-http.md) (ключ сборки), `docs/api/sync-protocol.md` §7.5, `docs/legal/providers.md`

## Контекст и проблема

MUS-015 просит три вещи: продолжить музыку на другом устройстве семьи «как Spotify Connect, но без облака» (очередь, трек и позиция; источник встаёт на паузу; плюс «Забрать сюда»), отправлять прослушивания в Last.fm и ListenBrainz (свой ключ пользователя или ключ сборки, офлайн-очередь) и 10-полосный эквалайзер для музыки. Ограничения проекта: никаких наших серверов, только LGPL-фильтры FFmpeg, секреты — в системной связке ключей, протокол синхронизации меняется только совместимо (§2).

Очередь живёт в Dart (`MusicQueue`, ADR-0063) и привязана к id треков *этой* медиатеки; у другого устройства свои id и пути. `pb.update` (SYNC-003) описывает один тайтл по ключу `tmdb:`/`file:` — для очереди из сотен треков он не подходит.

## Рассмотренные варианты

Перенос очереди:

1. Музыкальный `pb.update` на каждый трек + отдельная синхронизация очереди через журнал операций (ядро, миграция).
2. Новое эфемерное сообщение `music` (как `input` из UI-027): адресный кадр одному устройству, очередь — непрозрачный JSON приложения, запечатанный ключом семьи.
3. Общая «Сейчас играет» для всей семьи с heartbeat музыки и баннером.

Сопоставление треков: по id медиатеки; по URI; по тегам (исполнитель, альбом, название, длительность).

Скробблинг: в Dart (нужны `http` и `crypto` в приложении, ключ сборки всё равно в Rust) или в ядре (`ureq`, `md-5` уже в workspace).

Эквалайзер: `superequalizer` (18 фиксированных полос), `firequalizer`, по одному `equalizer` (biquad, `af_biquads`) на полосу.

## Решение

**Перенос — вариант 2, треки — по тегам, скробблинг — в ядре (`pa-scrobble`), эквалайзер — цепочка `equalizer` в `lavfi`.**

- **Сообщение `music`** (`pa_sync::music`, `proto::Message::Music`): `session`, `action` (`push` | `pull`, неизвестное — `other`, пропускается), `hlc`, `to` (одно устройство), `sealed`. `push` несёт JSON очереди, запечатанный `seal` для контекста `music:<session>`; лимит открытого текста 128 КиБ (`MAX_QUEUE_LEN`, `seal::seal_up_to`) — в кадр 256 КиБ входит с запасом. Узлы пересылают кадр один раз на стамп и **не хранят и не повторяют** его (передача — для устройства, которое в сети сейчас). Хаб на сервере пользователя (SYNC-008) пересылает его не читая. Поле и сообщение — по правилам §2: старые узлы отбрасывают неизвестное сообщение целиком, версия протокола не меняется.
- **«Продолжить на…»** (`MusicHandoffController.continueOn`): снимок `MusicPlayerController.snapshot()` (очередь, порядок, shuffle/repeat, источник, позиция) без истории — история остаётся на устройстве; плюс `playing` и `sentAtMs`. Длинная очередь обрезается: 20 треков до текущего и сколько влезет после. После отправки источник ставит паузу.
- **Приём:** треки ищутся в медиатеке приёмника по нормализованным (регистр, пунктуация) исполнителю + альбому + названию, затем исполнителю + названию при длительности ±3 с; публичный http(s)-поток берётся как есть; петлевые адреса чужого прокси и неизвестные треки выпадают. Если играбельного нет — очередь приёмника не трогается. Позиция = присланная + время в пути, пока источник играл (не больше 60 с, не дальше конца трека). Приёмник играет сразу и показывает плашку «Музыка с «…» играет здесь».
- **«Забрать сюда»** (`pullFrom`): `pull` устройству; если там загружена очередь, оно отвечает `push` в той же сессии и ставит паузу. Ответа нет 5 с — «На «…» сейчас ничего не играет».
- **UI:** кнопка «устройства» (`music-handoff-button`) на экране «Музыка» и поверх Now Playing (правый нижний угол; скрыта без сопряжённых устройств), лист с устройствами в сети. Файлы MUS-005 (#342: мини-плеер, верхняя панель Now Playing) не трогаются — кнопку в мини-плеер и верхнюю панель Now Playing перенесёт следующая правка после слияния #342.
- **Скробблинг (`core/crates/pa-scrobble`):** `rules::Tracker` (sans-IO): «сейчас играет» на старте; скроббл после прослушанных половины трека или 4 минут (что раньше); треки короче 30 с не считаются, неизвестной длины — после 4 минут; считается только движение позиции во время игры не быстрее часов (перемотка вперёд и пауза не считаются); повтор того же трека с начала — новое прослушивание; трек, переданный с другого устройства с середины, начинается «с позиции назад». `queue::Queue` на сервис — JSON-файл в папке данных, по порядку, пачками (Last.fm — 50, ListenBrainz — 100), пауза 30 с ×2 до 1 ч или сколько попросил сервис (`X-RateLimit-Reset-In`, ошибка 29 Last.fm — 5 мин); отозванный доступ держит очередь до нового входа; не больше 5000 скробблов. «Сейчас играет» не повторяется при ошибке (так требует Last.fm).
- **Last.fm:** десктопный вход (`auth.getToken` → страница `last.fm/api/auth` в браузере → «Готово» → `auth.getSession`), подпись MD5 по правилам API, ключ сессии бессрочный. Ключ: **свой ключ и shared secret пользователя** (поле в «Настройки → Скробблинг») или ключ сборки `PA_LASTFM_API_KEY`/`PA_LASTFM_SECRET` (`CARGO_PA_*` из Secrets, как TMDB; в `release-app.yml` уже передаются). Пока секретов в CI нет — пользователь вводит свой ключ.
- **ListenBrainz:** токен пользователя, проверка `GET /1/validate-token`, `playing_now`/`single`/`import`, заголовок `Authorization: Token …`, `User-Agent` с названием, версией и URL проекта.
- **Аккаунты** — у каждого профиля свои: один JSON в системной связке ключей (`scrobble_accounts_<профиль>`); в логах и `toString` секретов нет. До подключения аккаунта ничего никуда не уходит.
- **Эквалайзер** (`pa_player` `Equalizer` в `AudioProfile` музыки): 10 полос ISO (31 Гц…16 кГц, ±12 дБ), 10 пресетов + «Свой», предусиление ±12 дБ; фильтр `af` = `lavfi=[volume=…dB,equalizer=f=…:t=o:w=1:g=…,…,alimiter=limit=0.891:level=0]` — только полосы ≠ 0 дБ, ограничитель — только когда что-то поднимает уровень. `equalizer` (biquad), `volume`, `alimiter` — LGPL-фильтры FFmpeg, есть в нашей сборке. По профилю (`Preferences.musicEqualizer`), по умолчанию выключен; выключенный или плоский — пустой `af`. Включённый эквалайзер меняет сэмплы: **воспроизведение уже не bit-perfect** (подпись в настройках, `AudioProfile.bitPerfectCapable`). Видео эквалайзер не затрагивает (у видео свой `af` PLAY-004).

**Не входит:** «что играет на других устройствах» для музыки (баннер, heartbeat) — передача адресная и по запросу; перенос между профилями (только та же семья); синхронизация самих аккаунтов скробблинга между устройствами; импорт истории прослушиваний; эквалайзер на Apple (MUS-016) и в собственном движке (MUS-008).

### Последствия

- Хорошо: без миграций и без изменений журнала; протокол v1 совместим; очередь в сети запечатана ключом семьи — хаб не видит названия и пути.
- Хорошо: треки находятся на устройстве с другой медиатекой (другие пути, SMB-прокси с другим портом); недостающие выпадают, а не ломают очередь.
- Хорошо: правила скробблинга и офлайн-очередь — в одном месте ядра, одинаково на всех платформах; тесты на записанных ответах.
- Плохо: сопоставление по тегам ошибается на одноимённых треках одного исполнителя с одинаковой длительностью в разных альбомах без тега альбома; тогда играет первый найденный.
- Плохо: часы устройств не сверяются; добавка «времени в пути» ограничена 60 с.
- Плохо: Last.fm разрешает API только для некоммерческого использования; пожертвования в условиях не упомянуты — ключ сборки заводит и разрешает владелец (раздел PR «Решения владельца»), до этого — ключ пользователя.
- Нейтрально: «Забрать сюда» на ТВ ждёт ответа до 5 с; устройство, где приложение выгружено системой, не ответит (как и UI-027).

### Как проверяем соблюдение

- `core/crates/pa-sync/src/music.rs` (печать, привязка к сессии и семье, размер кадра, проверки), `core/crates/pa-sync/src/seal.rs` (`larger_limit`), `core/crates/pa-sync/tests/service.rs` (`music_handoff_push_and_pull`: два процесса, push, pull и ответ в той же сессии, чужой `to` не доходит).
- `core/crates/pa-scrobble/src/rules.rs` (половина / 4 мин / 30 с, перемотка и пауза, повтор, передача с середины), `src/queue.rs` (пауза, перезапуск, лимит), `tests/recorded.rs` (записанные ответы обоих сервисов: вход Last.fm и подпись, «сейчас играет», скроббл на половине, офлайн-очередь с повтором после перезапуска, отозванный доступ, отфильтрованные скробблы, проверка токена ListenBrainz).
- `clients/flutter/app/test/music_handoff_test.dart` (полезная нагрузка, обрезка, позиция старта, поиск треков, «Продолжить на…» и «Забрать сюда» между двумя устройствами), `clients/flutter/app/test/scrobbling_test.dart` (следование за плеером, аккаунты по профилям, вход), `clients/flutter/packages/pa_player/test/equalizer_test.dart` (строка фильтра, пресеты, JSON).
