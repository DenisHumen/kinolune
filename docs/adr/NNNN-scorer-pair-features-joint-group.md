# ADR-NNNN: Скорер v0 — признаки пары с ручными весами и совместное решение по группе

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** META-014 (эта задача), META-013, META-026, META-016, META-017, META-018; `docs/research/03-metadata-recognition.md` §4.2 [5], §6.2; [ADR-0022](0022-local-title-index.md)

## Контекст и проблема

Скорер META-026 выбирает работу, запись франшизы и эпизод для каждого файла отдельно и смотрит только на имя: название, год, тип, номера. Матчер медиатеки META-013 (`pa-catalog`, `match_search`) ранжирует результаты поиска TMDB тоже только по названию и году. Поэтому оба не различают ремейки и одноимённые работы без года в имени (категория A8: `Dune.mkv`, `Shameless.S09E14`), хотя файл знает свою длительность, а номер серии может не существовать у одного из кандидатов. Каждый файл сериала решается отдельно, хотя файлы одной папки — один сериал. Исследование 03 §4.2 [5] требует признаки пары (группа, кандидат) и совместный вывод по группе; done when META-014 — на A2, A3 и A8 ошибок минимум на 30 % меньше, чем у META-013.

## Факторы решения

- Нет обучающих данных, кроме синтетического корпуса v0: веса ручные, обученный и откалиброванный скорер — META-018.
- Тихие ошибки — главный KPI (03 §6.2): новый признак не должен делать авто из слабого сигнала.
- Sans-IO ядро: `pa-recognition` не ходит в сеть; детали провайдера приходят от вызывающего.
- Приложение не везёт anime-offline-database (ODbL), поэтому в `pa-catalog` скорер работает поверх результатов TMDB, а не локального индекса аниме.
- Подбор только на train и dev; test прогоняется один раз.

## Рассмотренные варианты

1. Признаки пары с ручными весами + совместное решение по папке (выбран).
2. Сразу логистическая регрессия на признаках корпуса v0.
3. Только длительность как «тай-брейкер» в META-013, без совместного вывода.

## Решение

Выбран вариант **1**: он закрывает категории A2, A3 и A8 без обучающей выборки, а признаки и их запись в `Signals` готовят META-018.

**Признаки пары** (`pa_recognition::score::pair`): длительность файла против runtime кандидата (фильм: ±5 % — +0.05, ±10 % — +0.02, 10–20 % — −0.03, дальше — −0.10; эпизод: только ±10 % — +0.02 и больше 45 % — −0.06, потому что runtime сериалов на TMDB — номинальный слот); каждый написанный `SxxEyy`, которого нет в списке сезонов кандидата, — −0.15; аудио на языке оригинала — +0.02. Эти три признака *относительные*: для файла их сумма сдвигается так, что лучший кандидат получает 0. Они разводят кандидатов, но не поднимают и не топят одинокого кандидата с неполными метаданными. Файл короче 40 % runtime (трейлер, сэмпл, часть) не сравнивается. Правила пользователя (`UserRule`: префикс папки → id работы) и подтверждённые хэши (`Hints::hashes`: OSHash/ed2k → id) — абсолютные: +0.5 названной работе, −0.3 остальным; работа, которую не нашло название, добавляется по id.

**Совместное решение** (`joint`): нумерованные файлы одной папки сериала (папка сезона сливается с родителем) решаются вместе. Голова франшизы (или западный сериал), которую поддерживает больше всего файлов (их лучшее прочтение через неё не хуже собственного лучшего на 0.15), забирает эти файлы. Цель — сумма их прочтений через голову минус 0.08 за каждое нарушение: два файла одного релиза на одном эпизоде, подряд идущие номера не на подряд идущих эпизодах (через границу записи тоже). Внутри головы прочтения выравниваются одним правилом, если так меньше нарушений. Отрыв группы от следующей головы на тех же файлах становится отрывом каждого файла. Остальные файлы папки решаются так же (свалка содержит несколько сериалов). Фильмы не объединяются: в одной папке может лежать оригинал и ремейк.

**Медиатека** (`pa-catalog`): та же оценка за прежним интерфейсом `match_search`. `WorkQuery` получил `evidence` (эпизоды, длительности, языки файлов работы из базы), `rank` добавляет признаки пары к оценке TMDB. Новый `match_search_with` при ничьей двух работ и непустых признаках запрашивает детали трёх лучших результатов (runtime, сезоны, язык) и ранжирует ещё раз. Ничью снимает отрыв ≥ 0.03 от признаков пары, поэтому язык аудио сам по себе авто не даёт. `Catalog::fetch_metadata` пользуется этим; детали выбранной работы запрашиваются и так.

**Замер** (`pa-eval errors`): ошибка — оцениваемый элемент, который распознаватель не решил сам верно на пороге авто: проверка или ручная очередь, неверная работа, неверный эпизод (верен, если совпала любая размеченная схема). Порог — `AUTO = 0.92` медиатеки. Тихие ошибки считаются отдельно и не должны расти. Базовая линия META-013 измерена кодом `main` до этого PR на всех типах: синтетический TMDB `title-catalog.jsonl` плюс новый `tmdb-anime-catalog.jsonl` (аниме-сериалы и фильмы так, как их держит TMDB). Без аниме-каталога у META-013 100 % ошибок на A2 и A3, это не сравнение. Отчёты лежат в `tools/recognition-eval/baselines/v0/meta014.md`.

Что **не** входит: нумерация в схеме TMDB для аниме (`SxxEyy` сезонов TMDB) — META-015; пороги и инбокс — META-016; создание правил из исправлений — META-017 (здесь только вход `UserRule`); обучение и калибровка — META-018; источник хэш-попаданий (AniDB `FILE`, краудбаза) — META-011/META-022, в офлайн-замере хэшей нет.

### Последствия

- Хорошо: на train + dev ошибок на A2 −75 %, A3 −91 %, A8 −41 % против META-013 при нуле тихих; на test (один прогон) −93 %, −93 %, −57 %. На test в A2/A3 5 тихих ошибок — те же файлы `Attack on Titan`, что у META-026 (порядок записей AniDB, META-015). Совместное решение исправляет файлы, которые по отдельности ничьи (`Shameless.S09E01` рядом с `Бесстыжие - 9 сезон 5 серия`). Матчер медиатеки снимает ничьи ремейков по длительности и сезонам (A8 −42 %, A7 −18 %, A15 −25 %).
- Плохо (цена решения): веса ручные и подобраны на синтетическом корпусе; длительности в корпусе отличаются от runtime на ±40 с, у реальных релизов разброс больше (PAL, обрезанные титры, режиссёрские версии), поэтому окна ±5 % / ±10 % — гипотеза до корпуса v1 (META-019). Ничья в медиатеке стоит до трёх запросов деталей TMDB.
- На пороге 0.75 (порог принятия META-013) A8 не улучшается по числу ошибок: META-013 «угадывает» ничьи ремейков (48 из 69 ошибок — тихие), скорер отдаёт их на проверку (0 тихих). Поэтому done when считается на пороге авто 0.92.
- Нейтрально: `model_version` остаётся `scorer_v0`; новые поля `TitleRecord` (`runtime_min`, `seasons`, `original_language`) необязательны и не ломают кэши и каталоги.

### Как проверяем соблюдение

Юнит-тесты `pa-recognition` (ремейк по длительности, сериал по списку сезонов и соседям, правило и хэш, подряд идущие номера через границу записи) и `pa-catalog` (`match_search_with` снимает ничью по длительности и сезонам, детали не запрашиваются без признаков). `baselines.sh` пересчитывает `meta014-errors*.md`; `pa-eval errors` выходит с кодом 1, если категория ниже цели или тихих ошибок стало больше.

## Открытые вопросы

- Возить ли anime-offline-database (ODbL, ~14 МБ) в приложении, чтобы локальный скорер работал и на устройстве — решение владельца; сейчас в приложении работает только ранжирование TMDB.
- Окна длительности подобрать заново на реальных релизах (META-019) и затем заменить ручные веса обученными (META-018).
