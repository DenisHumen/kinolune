# ADR-0130: Музыка с серверов — дерево файлов, как раньше; плейлисты сервера зеркалятся сканом в обычные аудиоплейлисты (только чтение); альбомы и плейлисты скачиваются офлайн-копиями NET-019; Plex — после NET-012

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** MUS-012, NET-012, NET-014, NET-015, NET-016, NET-019, MUS-004, LIB-012; [ADR-0067](0067-offline-copies.md), [ADR-0075](0075-jellyfin-client.md), [ADR-0081](0081-subsonic-client.md); `docs/research/01` §1.5 (музыка)

## Контекст и проблема

MUS-012: «удалённые музыкальные библиотеки в общей модели; загрузка альбомов и плейлистов через pa-jobs», готово, когда «альбом из Navidrome скачивается и играет офлайн».

Большая часть уже есть. Jellyfin/Emby (ADR-0075) и Subsonic (ADR-0081) читаются как дерево файлов `pa-vfs` (`Исполнитель/Альбом/NN - Трек.ext`, `cover.jpg`): сканер берёт теги оригиналов, треки попадают в те же таблицы, что и с локальной папки, и видны во всех видах раздела «Музыка». Офлайн-копии NET-019 (ADR-0067) копируют любой файл источника через очередь `pa-jobs`, а `SourceOpener` отдаёт копию раньше сети; кнопки «Скачать альбом» и «Скачать плейлист» в музыке уже есть.

Не хватало двух вещей. Первая — плейлистов сервера: у пользователя Navidrome или Jellyfin свои плейлисты, а в приложении их не было, и скачать «свой плейлист с сервера» было нельзя. Вторая — проверки на настоящем сервере, что альбом действительно скачивается и играет без сервера. Plex как источника в ядре ещё нет (NET-012 не сделан).

## Факторы решения

- Максимально просто для пользователя: добавил сервер — увидел свою музыку и свои плейлисты, нажал «Скачать», слушает без сети. Ни одного нового экрана и настройки.
- Один путь для музыки: не заводить второй, «серверный», каталог (ADR-0081, вариант 4).
- Плейлисты библиотеки — по профилю (`playlists.profile_id`), элементы — по `media_key` (отпечаток файла): так их понимают очередь, «Скачать плейлист» и M3U.
- Профили с белым списком папок (LIB-012) не должны видеть чужое.
- Без новых зависимостей и лицензий; секреты — как раньше, только в хранилище секретов.

## Рассмотренные варианты

Плейлисты сервера:
1. **Не показывать** — пользователь собирает плейлист заново руками.
2. **Живой запрос к серверу** на экране плейлистов — без сети пусто, офлайн-загрузка плейлиста не на чем строить, нужен второй путь в UI.
3. **Зеркало при скане**: после скана источника его плейлисты становятся обычными аудиоплейлистами библиотеки с отметкой «с сервера».
4. **Двусторонняя синхронизация** (правки в приложении уходят на сервер) — запись на сервер, конфликты, разные API у Subsonic и Jellyfin.

Кому видны:
5. Только активному профилю на момент скана.
6. **Каждому профилю, которому виден источник** (без белого списка или с папкой этого источника в нём).

Офлайн:
7. Отдельная «музыкальная» загрузка (транскод сервера, своя очередь).
8. **Офлайн-копии NET-019 как есть**: оригинал файла через `pa-jobs`, воспроизведение через `SourceOpener`.

Plex:
9. Делать клиента Plex здесь.
10. **Оставить на NET-012** (вход plex.tv, серверы, библиотеки); музыка Plex встанет в ту же схему, когда Plex станет деревом файлов, как Jellyfin.

## Решение

Варианты **3**, **6**, **8** и **10**.

- **Клиенты.** `pa-subsonic`: `getPlaylists`, `getPlaylist` (`Client::playlists`, `Client::playlist`, тип `Playlist`). `pa-jellyfin`: `Client::playlists` (`/Items?includeItemTypes=Playlist`) и `Client::playlist_items` (`/Playlists/{id}/Items` постранично, в порядке плейлиста; на Emby — `UserId`).
- **Источник.** `pa_sources::SourceManager::server_playlists(id)` → `Option<Vec<ServerPlaylist>>` (`remote_id`, имя, пути песен в дереве источника через `path_of` закэшированного дерева — того же, что сканировал). `None` — у вида источника нет плейлистов сервера. Песни вне дерева (другая библиотека, удалены) и видео пропускаются; видеоплейлисты Jellyfin не берутся — это музыка.
- **Каталог.** `Connector::server_playlists` (по умолчанию `None`; `SourcesConnector` спрашивает менеджер источников). `Catalog::scan` после отпечатков и распознавания зеркалит плейлисты источника: таблица `server_playlists` (миграция `202701060000_MUS-012_server_playlists`) отмечает строку `playlists`; для каждого профиля, которому виден источник, — своя строка; состав — треки по `media_key` в порядке сервера, каждый один раз; переименование и новый порядок обновляются, плейлист, которого больше нет на сервере (или профиль больше не видит источник), удаляется. Ошибка запроса плейлистов — обычное сообщение скана, скан идёт дальше; если сервер не ответил, зеркала остаются как были. Удаление источника удаляет его плейлисты (каскад + триггер `server_playlists_gone`). Песни, ещё без отпечатка, войдут со следующим сканом. Инкрементальные пересканы наблюдателя плейлисты не трогают — только полный скан.
- **Только чтение.** Переименовать, удалить, добавить или убрать трек в плейлисте сервера `Catalog` не даёт (`invalid`): следующий скан всё равно вернул бы версию сервера. Плейлист меняют на сервере (Navidrome, Jellyfin, Symfonium…). Свои плейлисты пользователя не меняются.
- **Мост и приложение.** `CorePlaylist.server` и `MusicPlaylist.server` — имя источника. В списке плейлистов у такого плейлиста значок облака и подпись «Navidrome · N треков», на его странице — «ПЛЕЙЛИСТ С СЕРВЕРА Navidrome»; в «Добавить в плейлист» его нет. Остальное — как у любого плейлиста: «Слушать», «Перемешать», «Экспорт M3U», «Скачать плейлист».
- **Офлайн.** Без изменений ADR-0067: «Скачать альбом»/«Скачать плейлист» ставят задачи `offline_copy` в `pa-jobs`, копируется оригинал (`stream?format=raw` у Subsonic, `static=true` у Jellyfin), уже скачанное пропускается; без сервера трек играет с копии через прокси, в музыке он «Загружено».
- **Plex** — остаток задачи, ждёт NET-012. Задача MUS-012 в ROADMAP не отмечена, остаток описан в ней.

## Последствия

- Хорошо: свои плейлисты с Navidrome, Gonic, Jellyfin и Emby видны без настройки и скачиваются одной кнопкой; офлайн работает без единой правки в плеере и загрузчике.
- Хорошо: «done when» проверен на настоящем Navidrome 0.58: альбом и плейлист скачаны очередью и сыграны через прокси с остановленным контейнером, байт в байт с оригиналом (`pa-offline/tests/navidrome.rs`).
- Плохо: изменения плейлиста на сервере видны после следующего полного скана, а не сразу.
- Плохо: у каждого профиля своя копия плейлиста сервера (так устроены плейлисты библиотеки); строк чуть больше, зато фильтры профилей работают как для своих плейлистов.
- Нейтрально: плейлист сервера нельзя изменить в приложении — сознательно; если понадобится, это отдельная задача с записью на сервер (вариант 4).
- Не сделано: Plex (NET-012); Jellyfin-альбом офлайн проверен только тем же кодом, что и для Navidrome (живой тест Jellyfin проверяет зеркало плейлиста, не загрузку); Emby — только тем же кодом, что Jellyfin.

## Как проверяем соблюдение

`cargo test -p pa-catalog --test server_playlists` (зеркало при скане: порядок сервера, без дублей и чужих песен, по копии на профиль, детский профиль без папки источника — без плейлиста, переименование и новый порядок, удаление на сервере, только чтение, удаление источника); `cargo test -p pa-sources playlists`; `core/crates/pa-subsonic/tests/navidrome/run.sh` (клиент — плейлисты в порядке; каталог — зеркало; `pa-offline/tests/navidrome.rs` — альбом и плейлист офлайн с остановленным Navidrome); `core/crates/pa-jellyfin/tests/server/run.sh` (зеркало плейлиста Jellyfin); `flutter test test/server_playlists_test.dart` (значок, подпись, заголовок, нет в «Добавить в плейлист», «Скачать плейлист»).
