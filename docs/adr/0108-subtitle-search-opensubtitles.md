# ADR-NNNN: Субтитры из интернета — OpenSubtitles по хэшу и ID, файл байт в байт рядом с видео или в кэше

- **Статус:** Предложен
- **Дата:** 2026-11-17
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** PLAY-008, PLAY-016, PLAY-004, PLAY-006, PLAY-007, LIB-004, NET-023, LEGAL-002; [ADR-0042](0042-subtitle-style-and-sidecars.md), [ADR-0104](0104-source-writes.md), [docs/legal/providers.md](../legal/providers.md)

## Контекст и проблема

PLAY-008: в меню субтитров плеера нужна кнопка «Найти субтитры»: поиск в OpenSubtitles по moviehash (это OSHash LIB-004, он уже есть у каждого файла в `files.oshash`) и по IMDb/TMDB ID, загрузка одним касанием и сразу выбор дорожки. Условия: ASS остаётся ASS со стилями (PLAY-006 их рисует); учитывать квоту скачиваний и показывать остаток; второй провайдер — только если можно без ключа и в рамках условий.

Ограничения: у OpenSubtitles REST v1 ключ (`Api-Key`) обязателен в каждом запросе; ключа проекта у владельца пока нет, в git ключей быть не может. Скачивания считаются: без входа — по адресу сети, со входом — по аккаунту. Своих серверов у проекта нет (ADR-0004): всё идёт с устройства пользователя.

Владелец поручил решать открытые вопросы самостоятельно по правилу «максимально просто для клиента».

## Факторы решения

- Пользователю ничего не нужно настраивать, когда в сборке есть ключ проекта; без него — один понятный путь (свой ключ в настройках).
- Ни одного секрета в git; ключ проекта — как у TMDB (переменная сборки из GitHub Secrets).
- Найденный файл совпадает с видео по времени чаще всего, если он сделан для этого же релиза (moviehash).
- Скачанные субтитры работают дальше как обычные sidecar-файлы (PLAY-007), на всех устройствах, без новой схемы БД.
- Тесты без сети (записанные ответы).

## Рассмотренные варианты

Ключ:

1. **Ключ проекта при сборке (`PA_OPENSUBTITLES_API_KEY` / `CARGO_PA_OPENSUBTITLES_API_KEY`) + свой ключ пользователя как запасной + логин пользователя для квоты.**
2. Только ключ проекта (без поля «свой ключ»): пока владелец не зарегистрировал приложение, функция не работает ни у кого.
3. Только ключ пользователя: каждый должен регистрироваться разработчиком — по вторичным данным OpenSubtitles такое не одобряет.

Куда сохранять:

1. **Рядом с видео, если источник доступен для записи (NET-023), иначе в кэш приложения по отпечатку файла.**
2. Всегда в кэш — субтитры не видны другим устройствам и плеерам, теряются при очистке кэша.
3. Новая таблица в БД со ссылкой на файл — миграция ради списка файлов в папке кэша.

Второй провайдер: Subdl (ключ API обязателен, выдаётся после регистрации), Podnapisi (нет документированного API и условий для сторонних клиентов).

## Решение

**Ключ** — вариант 1. `pa_metadata::key::Keys::opensubtitles_from_build()` читает ключ проекта на этапе компиляции, как TMDB; в `release-app.yml` он приходит из секрета `PA_OPENSUBTITLES_API_KEY` во все сборки (Linux, Android, Windows, macOS). Пока секрета нет, в «Настройки → Стиль субтитров → Субтитры из интернета» поле ключа называется «Ключ API OpenSubtitles» с подсказкой, где его взять; когда ключ проекта есть — «Свой ключ API (необязательно)». Свой ключ пользователя всегда важнее ключа проекта. Логин и пароль — необязательны: без них квота по адресу сети, с ними — по аккаунту; кнопка «Сохранить и проверить» входит и показывает «Осталось скачиваний сегодня: N из M». Логин, пароль и ключ лежат в защищённом хранилище устройства (`SecureStore`), в ядро передаются с каждым вызовом и живут там только в памяти вместе с JWT сессии. Это уточняет решение в docs/legal/providers.md («поле „свой ключ“ не делать»): поле есть, но в сборках с ключом проекта оно второстепенное.

**Запросы** (`pa_metadata::opensubtitles`): `GET /subtitles` с параметрами в нижнем регистре и по алфавиту (иначе API перенаправляет), IMDb без `tt`; фильм — `imdb_id` (или `tmdb_id`) + `moviehash` + `type=movie`; серия — `parent_tmdb_id` (или `parent_imdb_id`) + сезон и номер + `moviehash` + `type=episode`; если по ID ничего нет — ещё раз только по `moviehash`. Языки — языки субтитров профиля (PLAY-004) плюс английский. Поиск квоту не тратит. `POST /download` тратит одно скачивание и отвечает остатком и временем сброса; `406` — квота исчерпана (без повторов). Темп — не чаще раза в 250 мс, по одному запросу; `429` и `5xx` — повтор с `Retry-After`. `User-Agent: Kinolune vX.Y.Z`. Файл берётся по временной ссылке без ключа и токена и **не конвертируется**: `sub_format` не передаётся, байты сохраняются как пришли, расширение — из имени файла в ответе или по содержимому (`[Script Info]` → `.ass`).

**Ранжирование** (`pa_catalog::subtitle_search::rank`): сначала сделанные для этого файла (`moviehash_match`), затем по месту языка в списке профиля (прочие языки — после), затем человеческий перевод раньше машинного/ИИ, затем по числу скачиваний. Релизы на нескольких CD не показываются. В плеере у строки: язык и пометки («Точно для этого файла», «только надписи», «для слабослышащих», «машинный перевод»), ниже — релиз и число скачиваний; над списком — остаток квоты.

**Сохранение** — вариант 1. Источник доступен для записи (`pa_vfs::files::writability`) → файл `<имя видео>.<язык>[.forced][.sdh].<расш>` рядом с видео (занято — `.2`, `.3`), затем `Catalog::refresh_after_write` для папки: файл становится обычным sidecar (PLAY-007) — виден на всех устройствах и в других плеерах. Иначе (только чтение, сервер, ошибка записи) — в кэш приложения `<cache>/subtitles/<OSHash файла>/…`: привязка к содержимому файла переживает переименование и перенос; `Catalog::cached_subtitles` добавляет такие файлы к sidecar-списку при открытии. Новой таблицы нет. Скачанный файл сразу загружается в плеер с выбором (`addSubtitle(select: true)`) и запоминается для сериала, как ручной выбор дорожки.

**Второй провайдер** не добавлен: у Subdl ключ API обязателен (это регистрация — действие владельца), у Podnapisi нет документированного API и условий. Задача [P1] — PLAY-016.

### Последствия

- Хорошо: в сборке с ключом проекта поиск работает сразу, без регистрации; вход нужен только ради большей квоты.
- Хорошо: файл совпадает с видео по хэшу — в начале списка; ASS приходит со стилями и рисуется libass (PLAY-006).
- Хорошо: скачанное рядом с видео — обычный sidecar для всех устройств; на источниках только для чтения — кэш без миграции БД.
- Плохо: пока владелец не добавил секрет, в релизных сборках нужен свой ключ пользователя.
- Плохо: файлы в кэше не синхронизируются между устройствами (на втором устройстве их нужно скачать снова).
- Нейтрально: пароль OpenSubtitles хранится на устройстве; в логи, БД и записи тестов не попадает (`Debug` маскирует, кассеты синтетические).

### Шаг владельца

1. Зарегистрировать приложение (API consumer) на opensubtitles.com: Профиль → API consumers, имя `Kinolune`, указать, что это бесплатное open-source приложение, запросы идут с устройств пользователей.
2. Добавить ключ в GitHub Secrets окружений `release` и `store` как `PA_OPENSUBTITLES_API_KEY` (workflow уже передаёт его в сборку как `CARGO_PA_OPENSUBTITLES_API_KEY`).
3. Для локальных сборок — `PA_OPENSUBTITLES_API_KEY=` в `.env.local` (шаблон в `.env.example`).
