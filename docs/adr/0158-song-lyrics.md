# ADR-0158: Тексты песен — файлы через ядро, LRCLIB с устройства, LRC в клиенте

- **Статус:** Предложен
- **Дата:** 2026-11-24
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** `MUS-006`, `MUS-005` (экран «Сейчас играет»), [ADR-0020](0020-music-tags-lofty.md) (теги через `lofty`), [ADR-0156](0156-music-handoff-scrobbling-equalizer.md), `docs/legal/providers.md` (LRCLIB)

## Контекст и проблема

MUS-006: тексты песен на экране «Сейчас играет» — из тегов файла (USLT — простой текст, SYLT — по строкам со временем), из `.lrc` рядом с треком и из LRCLIB; построчная подсветка с точностью ±100 мс, переход по нажатию на строку, полноэкранный режим. Треки лежат и локально, и на SMB/WebDAV, клиент их не монтирует (LIB-018); приложение работает без наших серверов.

## Рассмотренные варианты

1. **Файлы — в ядре (новый крейт `pa-lyrics` поверх `pa-vfs` и `lofty`), LRCLIB и разбор LRC — в Dart.**
2. Всё в ядре, включая LRCLIB и разбор LRC (ещё один HTTP-клиент и кэш в Rust, новый FFI на каждую мелочь интерфейса).
3. Всё в Dart: теги через `audio_metadata_reader` — только локальные файлы, SMB/WebDAV не читаются.
4. Чтение лирики встроить в `pa-scanner` и хранить в базе медиатеки (лишний объём в базе, пересканирование ради текста; код сканера сейчас меняет другая задача).

## Решение

Выбран вариант **1**.

- `pa-lyrics::read_lyrics(vfs, path)` отдаёт SYLT (MP3; время в мс, MPEG-кадры переводятся по частоте), простой тег текста (USLT, Vorbis `LYRICS`/`UNSYNCEDLYRICS`, MP4 `©lyr`, APE) и текст `.lrc` с тем же именем (расширение в любом регистре; UTF-8/UTF-16 с BOM, иначе Windows-1251 или Latin-1). Читаются только блоки тегов, файл целиком не качается. Битый тег — не ошибка; ошибка — только недоступный источник. В мост — `CoreLibrary::track_lyrics(source_id, rel_path)`; сканер и VFS не меняются.
- Приоритет (клиент, `LyricsService`): SYLT → `.lrc` с метками → LRC-текст в теге → LRCLIB (синхронный) → простой текст (`.lrc` без меток, тег, LRCLIB). Синхронный источник всегда раньше простого.
- LRCLIB (lrclib.net, бесплатно, без ключа): `/api/get` по исполнителю, названию, альбому и длительности, иначе `/api/search` с ближайшей длительностью (±2 с). Без исполнителя не ищем (по одному названию — чужие тексты). `User-Agent: Kinolune/<версия> (https://github.com/DenisHumen/kinolune)` — без данных пользователя. Ответы, в том числе «ничего нет», кэшируются в кэше приложения (`lyrics/`); «ничего нет» — на 7 дней. Ошибки сети не кэшируются.
- Поиск в интернете **включён по умолчанию** и выключается в «Настройки → Музыка → Искать тексты песен в интернете»; подпись говорит, что уходит в LRCLIB (исполнитель, название, альбом, длительность). Простой путь по умолчанию — тексты «просто есть»; приватность — одним переключателем.
- Разбор LRC и «строка на позиции» — в `pa_player` (`parseLrc`, `lyricLineAt`): несколько меток на строке, `[offset:±мс]` (плюс — раньше), дроби `.x/.xx/.xxx` и `:xx`, слова расширенного LRC (`<mm:ss.xx>`) убираются. Подсветка берёт позицию плеера и досчитывает её по кадрам между отчётами движка, поэтому строка меняется в пределах кадра от своего времени.

### Последствия

- Хорошо: одинаково для локальных и сетевых источников; без новых зависимостей (lofty уже в дереве, HTTP через `dart:io`); точность подсветки не зависит от частоты отчётов движка.
- Плохо: тексты не индексируются и не ищутся по медиатеке; SYLT читается только в MP3 (ID3v2 в WAV/AIFF/DSF — нет); `Lrclib-App-Id` не отправляется, пока владелец его не зарегистрирует (повышенные лимиты, `docs/legal/providers.md` §3).
- Требует работы: очистка кэша текстов в «Хранилище»; отправка найденных текстов в LRCLIB — не делаем.

### Как проверяем соблюдение

`core/crates/pa-lyrics/tests/lyrics.rs` (SYLT в мс и MPEG-кадрах, USLT, FLAC `LYRICS`, `.LRC` в другом регистре и в cp1251, битый файл); `packages/pa_player/test/lyrics_test.dart` (разбор LRC, `lyricLineAt` ±100 мс, подсветка, нажатие и Enter на строке, полноэкранный режим, «Текст не найден»); `test/lyrics_service_test.dart` (приоритет источников, LRCLIB `get`/`search`, кэш, выключатель).
