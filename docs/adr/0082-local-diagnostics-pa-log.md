# ADR-0082: Локальная диагностика `pa-log`: логи и отчёты о сбоях только по opt-in, вырезание путей и токенов, zip-отчёт и issue вручную

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта
- **Связано:** `CORE-008`, `UI-017`, `CORE-006`, `CORE-007`; [ADR-0004](0004-no-project-servers-local-sync.md), [ADR-0038](0038-network-playback-loopback-proxy.md), [политика конфиденциальности §6](../legal/privacy-policy.md)

## Контекст и проблема

Чтобы чинить ошибки у пользователей, нужны логи и отчёты о сбоях. Своих серверов у проекта нет (ADR-0004), телеметрия без согласия запрещена (AGENTS.md), а политика конфиденциальности (§6) уже обещает: по умолчанию ничего не сохраняется, пути и токены вырезаются, отправка — только вручную. До этой задачи в ядре не было ни одного подписчика `tracing` (события `pa-sync` уходили в никуда), а приложение писало только `debugPrint` в консоль.

Нужно решить, где живут логи, как гарантировать отсутствие секретов, как ловить сбои Rust, Dart и нативного кода и как отчёт попадает к разработчикам.

## Факторы решения

- Ничего не пишется на диск без явного согласия; выключение удаляет написанное.
- В отчёте не должно быть домашних каталогов, паролей, токенов в URL, токена pa-proxy, OAuth-токенов Twitch.
- Никаких серверов и автоматической отправки.
- Минимум новых зависимостей; сигнал-безопасный код для нативных сбоев.
- Один механизм для ядра и приложения.

## Решение

Новый крейт `core/crates/pa-log` и фасад `pa-frb/src/api/diagnostics.rs`.

- **Согласие.** Файл-маркер `<данные приложения>/diagnostics/opt-in`. Пока его нет, `Diagnostics` ничего не создаёт: строки логов, события `tracing`, паники и отчёты Dart отбрасываются. Выключение удаляет `logs/`, `crashes/`, маркер и пустой каталог. Переключатель — «Настройки → Диагностика».
- **Логи.** `pa_log::install` ставит глобальный подписчик `tracing` (уровень INFO, без ANSI) и пишет события ядра в `diagnostics/logs/kinolune.log`. Приложение пишет туда же через `diagnosticsLog`: `debugPrint` перенаправлен, ошибки `FlutterError` попадают как строки ERROR. Ротация по размеру: 1 МиБ на файл, не больше 4 файлов (`kinolune.log`, `kinolune.1.log`…), своя реализация на 100 строк (у `tracing-appender` ротация только по времени).
- **Вырезание** (`Redactor`, `regex`) применяется к каждой строке перед записью и ещё раз при сборке отчёта. Правила жадные: потерять hex-идентификатор в логе дешевле, чем выложить токен в публичный issue.
  - домашние каталоги: известные (`$HOME`, `%USERPROFILE%`, переданные приложением) → `~`, с проверкой границы пути; любые другие `/home/<user>`, `/Users/<user>`, `X:\Users\<user>` (и в percent-encoding) теряют имя; UUID контейнера iOS → `<app>`;
  - user info в URL (`smb://user:pass@host`, также `%3A%2F%2F…%40`);
  - параметры запроса `access_token`, `token`, `api_key`, `key`, `X-Plex-Token`, `X-Emby-Token`, `sig`, `code`, `password`, Subsonic `u`/`p`/`t`/`s` и др.;
  - пары `ключ = значение` / `"ключ": "значение"` с ключами password, token, secret, cookie, pin, session…;
  - схемы `Bearer`, `OAuth`, `Basic`, `MediaBrowser`…, IRC `oauth:…` (Twitch);
  - первый сегмент пути loopback-URL (`http://127.0.0.1:<port>/<token>/…`, токен pa-proxy, ADR-0038);
  - JWT и любые hex-последовательности от 32 цифр (ключ TMDB, токены Jellyfin, токен прокси);
  - явно зарегистрированные секреты (`add_secret`).
  - Имена файлов вне домашнего каталога, адреса серверов в LAN и IP остаются: без них отчёт бесполезен (см. «Решения владельца»).
- **Сбои.**
  - Rust: panic hook (поверх хука FRB) пишет `crashes/crash-<время>-rust-panic.txt` с сообщением, местом, потоком и backtrace. Паники, пойманные `catch_unwind` (pa-jobs, pa-player-io), тоже записываются: это ошибки.
  - Dart: `PlatformDispatcher.onError` и `FlutterError.onError` (кроме `silent`) → `diagnosticsRecordCrash`.
  - Нативный код на Linux и macOS: обработчики SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGABRT. Обработчик только пишет маркер `crashes/native-pending` (`open`/`write` по заранее подготовленному пути — async-signal-safe), возвращает предыдущий обработчик (защиту стека Rust, действие по умолчанию) и выходит, сигнал повторяется у предыдущего обработчика. При следующем старте с согласием маркер превращается в отчёт «предыдущий запуск остановлен сигналом N».
  - Android: свои обработчики сигналов не ставятся — фатальные сигналы принадлежат ART (sigchain), а ART сам использует SIGSEGV. Вместо этого `DiagnosticsBridge` (канал `app.kinolune/diagnostics`) читает `ApplicationExitInfo` (Android 11+): `crash`, `native-crash`, `anr` прошлых запусков, для ANR — текст трассы. Dart записывает их как отчёты только при согласии и помнит последнюю метку времени.
  - iOS/tvOS, Windows: только паники Rust и ошибки Dart (системные отчёты Apple и WER остаются за ОС).
  - Хранится не больше 20 отчётов, старые удаляются.
- **Отчёт.** «Экспортировать диагностический отчёт» пишет `kinolune-diagnostics-<время UTC>.zip` (атомарно, через `.part`): `README.txt`, `versions.txt` (приложение, флейвор, ядро, ОС, Dart, локаль), `config.txt` (выбранные несекретные настройки; значения ключей, похожих на секреты, — `<redacted>`; история поиска, избранное, профили и PIN не берутся), `logs/`, `crashes/` (повторно вырезанные). Zip пишется без сжатия своим писателем на 150 строк (CRC-32, без zip64): отчёт — несколько мегабайт текста, отдельная зависимость не нужна. Без согласия экспорт тоже работает, но содержит только версии и настройки. Куда: «Загрузки» на десктопе; на Android 10+ копия в общие «Загрузки» через MediaStore; иначе — документы приложения.
- **Отправка.** Только вручную: диалог «Отчёт сохранён» показывает, где файл, и кнопку «Открыть issue на GitHub» — ссылка `…/issues/new?template=bug_report.yml` с заполненными полями «Платформа и версия» и «Логи» (имя файла и первая строка последнего сбоя, тоже вырезанные). Файл пользователь прикладывает сам. Ни ядро, ни приложение ничего не загружают.

### Рассмотренные варианты

- **`tracing-appender` + крейт `zip`.** Ротация только по времени, `zip` тянет компрессоры. Отказ.
- **Sentry/Crashpad/Breakpad.** Нужен сервер приёма и автоматическая отправка; противоречит ADR-0004. Отказ.
- **Обработчики сигналов и на Android.** Конфликт с ART (неявные null-проверки через SIGSEGV дали бы ложные отчёты). Отказ в пользу `ApplicationExitInfo`.
- **Вырезать и имена файлов, и адреса LAN.** Отчёт перестаёт помогать (какой файл не играет, какой сервер не отвечает). Оставлено решением по умолчанию, вынесено владельцу.

### Последствия

- Хорошо: соблюдается §6 политики конфиденциальности; тест (`pa-log/tests/report.rs`) проверяет, что в zip нет путей пользователя и токенов, и что без согласия ничего не сохраняется.
- Хорошо: у ядра впервые есть подписчик `tracing` — события `pa-sync` и будущие видны в логах.
- Плохо: жадные правила режут полезное (`#t=` в URL, hex-идентификаторы элементов Jellyfin, первый сегмент любого loopback-URL).
- Плохо: нативный сбой на Linux/macOS — только номер сигнала, без стека. Стек потребовал бы minidump и внешних инструментов.
- Ограничение: если когда-то движок Dart/Flutter на десктопе начнёт обрабатывать SIGSEGV сам, первый такой сигнал даст ложный маркер (обработчик после первого срабатывания снимается).
- Дальше: экран «Состояние» (UI-017) показывает логи и отчёты; фасад UniFFI (`pa-ffi`) для нативных плееров — по необходимости.
