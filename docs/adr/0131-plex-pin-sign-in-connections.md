# ADR-0131: Plex — вход кодом на plex.tv/link, автоматический выбор подключения, библиотеки сервера как дерево файлов

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** NET-012, NET-013 (воспроизведение, прогресс, транскод — следующая задача), NET-010 (обнаружение Plex по GDM, [ADR-0126](0126-lan-probes-wsd-netbios-gdm-jellyfin.md)), MUS-012 ([ADR-0130](0130-music-server-playlists-offline-albums.md)), [ADR-0075](0075-jellyfin-client.md) (клиент Jellyfin — образец), [ADR-0013](0013-pa-vfs-blocking-positional-reads.md), [ADR-0038](0038-network-playback-loopback-proxy.md), [ADR-0045](0045-split-movies-mpv-edl.md)

## Контекст и проблема

Plex — самый распространённый домашний медиасервер; без него паритет с Infuse не достигается (research 01 §1.5). NET-010 уже находит Plex в сети, но показывал его как «скоро». Нужно: вход через plex.tv так, как это делают приложения Plex на телевизорах, пользователи Plex Home, выбор одного из подключений сервера (локальное, удалённое, relay), библиотеки и метаданные в общей модели медиатеки. Решать за владельца ничего не нужно: правило — «максимально просто для клиента».

## Факторы решения

- Ввод пароля на ТВ неудобен, а пароль от учётной записи Plex приложению знать не нужно.
- Всё локально ([ADR-0004](0004-no-project-servers-local-sync.md)): токены — только в хранилище секретов, не в SQLite, логах и синхронизации.
- У сервера Plex несколько адресов, и какой из них работает, зависит от того, где сейчас пользователь; роутеры с защитой от DNS rebinding не отдают имена `*.plex.direct`.
- Медиатека, поиск, профили, офлайн-копии, прокси и плейлисты сервера уже построены на `pa-vfs` (ADR-0075, ADR-0130): второй путь для «серверных» элементов не нужен.
- Без аккаунта и claim-токена в CI: тесты не должны ходить на plex.tv.

## Рассмотренные варианты

1. **Вход:** (а) логин и пароль plex.tv в форме; (б) PIN-код plex.tv/link (`POST /api/v2/pins`, `strong=false`), как у приложений Plex для ТВ; (в) OAuth-страница app.plex.tv/auth в браузере (длинный PIN).
2. **Подключение:** (а) спрашивать пользователя; (б) выбирать самим: проверить все подключения сразу и взять лучшее отвечающее, а при работе переключаться на следующее при ошибке соединения.
3. **Медиатека:** (а) отдельная модель элементов Plex; (б) библиотеки как дерево файлов `pa-vfs`, как у Jellyfin (ADR-0075).
4. **Что хранить:** (а) токен учётной записи plex.tv; (б) токен сервера выбранного пользователя.

## Решение

**1б, 2б, 3б, 4б.**

- **Крейт `pa-plex`** (ureq + rustls/ring, как `pa-jellyfin`; свой небольшой клиент, только нужные поля, `null`/строки/числа в id читаются терпимо). Приложение представляется как `X-Plex-Product: Kinolune` с `X-Plex-Client-Identifier` — UUID v7, созданным при входе и хранящимся в `options_json` источника (не секрет). Секретов и ключей проекта в коде нет: PIN-вход Plex их не требует.
- **Вход кодом.** Форма сразу получает код (4 символа, живёт ~15 мин) и показывает его крупно с «plex.tv/link»; приложение проверяет код раз в 2 с. Код устарел — «Новый код». Пароль Plex в приложение не вводится нигде.
- **Plex Home.** Если в Home больше одного пользователя — шаг «Кто смотрит?». Защищённому пользователю (кроме владельца, который уже вошёл) — поле PIN; переключение — `POST /api/v2/home/users/{uuid}/switch`, сервера после этого перечитываются токеном этого пользователя (у него свои библиотеки и ограничения). Без Home или с одним пользователем шаг пропускается.
- **Сервер.** Если сервер один — добавляется без вопроса. Если несколько — список («Открыт для вас», «Не в сети», версия), заранее выбран тот, у которого есть подключение на IP сервера, найденного в сети по GDM (NET-010), иначе свой и онлайн.
- **Подключение — без вопросов.** `order_connections` упорядочивает подключения ресурса: **локальные → удалённые → relay**; внутри — HTTPS (`*.plex.direct`) раньше обычного HTTP, кроме сетей с защитой от DNS rebinding (флаг ресурса `dnsRebindingProtection`) — там сначала голый IP; IPv4 раньше IPv6. Для локальных HTTPS-адресов добавляется их «близнец» `http://<IP>:<порт>` (если сервер не требует HTTPS). **Обычный HTTP — только в локальной сети**: токен не уходит открытым текстом через интернет. При входе `probe_connections` одновременно опрашивает все адреса (`/identity`, 4 с, сверка `machineIdentifier`) и не даёт добавить сервер, если не отвечает ни один. Источник хранит весь упорядоченный список (основной адрес + `alt_addresses`) и работает как клиент Jellyfin: запрос идёт на адрес, ответивший последним; при ошибке соединения — на следующие по порядку. Поэтому дома используется локальное подключение, вне дома — удалённое или relay, без перенастройки.
- **Хранится токен сервера** выбранного пользователя (`accessToken` ресурса) — в хранилище секретов (`credential_ref`); токен учётной записи plex.tv используется только во время входа и забывается вместе с ним. Источник Plex не синхронизируется на другие устройства (как Jellyfin): на другом устройстве — свой вход. В `options_json` — только id сервера, id приложения, имя устройства, имя пользователя и список адресов.
- **Медиатека = дерево файлов** (`PlexFs`, как `JellyfinFs`): `Фильм (Год)/Фильм (Год).<ext>` с `movie.nfo` (TMDB/IMDb/TVDB из `Guid` при `includeGuids=1`), `poster.jpg`, `fanart.jpg`; сериалы `Сериал (Год)/Season NN/Сериал SxxEyy - Название.<ext>` с `tvshow.nfo`; музыка `Исполнитель/Альбом/NN - Трек.<ext>` с `cover.jpg`. Другие версии — `… - 4K.mkv`, фильм из нескольких файлов — `… - part1/part2` (склейка частей ADR-0045). Фото-библиотеки пропускаются. Список библиотеки — постраничный `/library/sections/{id}/all?type=…` (по 500), кэш 5 мин; файл читается диапазонами с ключа части (`/library/parts/…`), упреждение 2 МиБ. Картинки берутся только по путям сервера (не по внешним URL).
- **Музыка и плейлисты (MUS-012).** Музыкальные библиотеки Plex попадают в музыку через то же дерево; `SourceManager::server_playlists` для Plex читает `/playlists?playlistType=audio` и зеркалит их сканом в аудиоплейлисты, как у Jellyfin и Subsonic; «Скачать альбом/плейлист» работает через офлайн-копии без изменений.
- **В приложении:** «Сервер Plex» больше не «скоро» ни в выборе типа, ни в «В этой сети»; «Изменить» меняет только имя.
- **Тесты без аккаунта:** синтетические ответы plex.tv и сервера в форме из публичной документации Plex API (`pa-plex/tests/fixtures/`), локальный HTTP-сервер проверяет токены, заголовки `X-Plex-*`, страницы и диапазоны (`pa-plex/tests/plex.rs`, `pa-sources/tests/plex.rs`, `pa-catalog/tests/plex.rs` — скан в медиатеку, плейлист и поток через прокси побайтно). Plex Media Server в Docker без claim-токена не отдаёт библиотеки без входа в plex.tv, поэтому живого теста нет; это ровно вариант «или записанные ответы» из done when.

Не входит (NET-013): воспроизведение с транскодом по запросу, timeline/scrobble, синхронизация «просмотрено» и Continue Watching с сервером, видео-плейлисты; выбор библиотек в форме (опция `libraries` в ядре есть); обновление списка подключений с plex.tv после смены публичного адреса (сейчас — войти заново).

### Последствия

- Хорошо: вход занимает одно действие на телефоне; пароль Plex приложению неизвестен; подключение выбирается само и меняется само при уходе из дома.
- Хорошо: сервер Plex виден во всех существующих видах (главная, сетка, поиск, страницы, профили, музыка, офлайн-копии) без своего UI; плейлисты музыки — как у других серверов.
- Плохо: вне дома первый запрос после запуска ждёт таймаута локальных адресов (4 с на адрес), прежде чем перейти к удалённому; relay медленный (лимит Plex).
- Плохо: распознавание идёт нашим конвейером по дереву (как у Jellyfin, ADR-0075); метаданные Plex сверх внешних id и картинок не переносятся.
- Плохо: ответы plex.tv в тестах синтетические — расхождение с реальным API (например, формат `/api/v2/home/users`) обнаружится только у пользователя; разбор сделан терпимым (объект с `users` или массив, `authToken` или `authenticationToken`).
- Нейтрально: токен сервера владельца совпадает с токеном его учётной записи (так выдаёт plex.tv) — он хранится так же, как пароль любого источника.
