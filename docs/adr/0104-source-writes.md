# ADR-0104: Запись в источники — одно ядро операций над `VfsWrite`, корзина в самом источнике, докачка через `.part`

- **Статус:** Предложен
- **Дата:** 2026-11-17
- **Решают:** владелец проекта (направление: «максимально просто для клиента»), мейнтейнер (детали)
- **Связано:** NET-023, UI-035, UI-034; [ADR-0099](0099-auto-content-type-personal-place.md), ADR-0013 (синхронный `pa-vfs`)

## Контекст и проблема

До NET-023 `pa-vfs` только читал. ADR-0099 требует файлов «как в Nextcloud»: загрузка с телефона с докачкой, папки, перенос, копирование, корзина. Писать нужно в пять протоколов (локальная папка, SMB через libsmb2, WebDAV, SFTP, FTP), а ошибка здесь стоит дорого — это чужие файлы на NAS. Открытые вопросы владелец поручил решить самим по правилу «максимально просто для клиента».

## Факторы решения

- Одинаковое поведение во всех протоколах; правила безопасности не должны зависеть от бэкенда.
- Ничего не настраивать: только чтение определяется само.
- Удаление обратимо по умолчанию; ничего не удаляется за пределами корня источника.
- Обрыв на телефоне — обычное дело: загрузка продолжается, а не начинается заново.
- После записи медиатека обновляется сразу, без полного скана.
- Без новых зависимостей; libsmb2 по-прежнему подгружается в рантайме (LGPL).

## Рассмотренные варианты

1. Полный набор операций (перенос, корзина, конфликты) в каждом бэкенде.
2. **Маленький трейт примитивов `VfsWrite` в бэкендах и одно ядро операций `pa_vfs::files` над ним.**
3. Корзина в базе приложения: удалённое уходит в скрытую папку, а список хранится локально.

## Решение

Выбран вариант **2**. Бэкенды реализуют только примитивы. Правила живут в одном месте и одинаково проверяются контракт-тестом на всех серверах.

**Трейт и признак записи.**

- `Vfs::as_write()` возвращает `Option<&dyn VfsWrite>`. По умолчанию `None`: медиасерверы, NFS и прочее остаются только для чтения.
- Примитивы `VfsWrite`: `create_dir`, `write_file(path, offset, data, len)` (при `offset > 0` — дозапись), `rename` (без замены), `server_copy` (по умолчанию `Unsupported`), `remove_file`, `remove_dir` (пустой), `is_symlink`.
- `files::writability()` создаёт и удаляет на корне папку-пробу `.kinolune-write-probe`. Только чтение определяется само: недоступная запись, сервер в режиме read-only, общая папка без прав. Ошибкой считается только «нет связи» и «не пускают».
- В каталоге это `Catalog::source_writable`. UI скрывает кнопки записи, если ответ «нет».

**Операции (`pa_vfs::files`).**

- `create_folder`.
- `upload` с докачкой.
- `rename`.
- `move_within`: один серверный `rename`, а если протокол не умеет — копия, проверка размера, удаление.
- `copy_within`: `server_copy`, иначе через устройство.
- `copy_between` и `move_between`.
- `trash`, `restore`, `list_trash`, `purge_trash`, `empty_trash`, `delete_permanently`.

**Докачка.**

- Данные пишутся в `имя.part`, в конце он переименовывается в `имя`.
- После обрыва запись продолжается с длины `.part`. Сначала сравниваются последние 64 КиБ с данными: чужой `.part` не продолжаем.
- Размер итогового файла проверяется.
- WebDAV:
  - сервер, который принимает `PUT` с `Content-Range` (Apache `mod_dav`), получает файл кусками по 8 МиБ, и обрыв теряет не больше куска. Поддержку проверяет одна проба на источник;
  - остальные (nginx, `rclone serve`, Nextcloud) получают один потоковый `PUT`, а после обрыва загрузка начинается заново. Результат всё равно точный — это проверено.

**Корзина живёт в самом источнике: `/.kinolune-trash/<мс>-<nonce>/<имя>`.**

- Рядом лежит `.kinolune-origin` с исходным путём.
- Срок хранения — 30 дней (`TRASH_KEEP`). Очистка — `purge_trash(now)`, её вызывает приложение (UI-035) при открытии источника или по таймеру.
- Почему не база приложения (вариант 3):
  - корзина переживает переустановку приложения;
  - её видят другие устройства и сам NAS;
  - перенос внутри источника — это мгновенный `rename`.
- Сканер всегда пропускает `.kinolune-trash`, даже при `skip_hidden = false`.

**Безопасность.**

- По умолчанию удаление идёт в корзину. Полное удаление — отдельная функция `delete_permanently`.
- Корень источника и сама корзина не переносятся и не удаляются, папку нельзя перенести в саму себя.
- Новые имена — один компонент без `/`, `\` и управляющих символов. `VfsPath` и так не выражает `..`.
- Рекурсивное удаление не заходит в символические ссылки: удаляется сама ссылка.
- Перенос между источниками удаляет оригинал только после полной копии и проверки размеров.
- В логах и ошибках нет паролей: пишутся только пути и ответы серверов, как и раньше.

**Конфликты имён — `Conflict`.**

- `KeepBoth` (по умолчанию) — «имя (2).ext».
- `Replace` — старое уходит в корзину, а не стирается.
- `Skip`.
- Для `create_folder` при `Replace` существующая папка остаётся как есть. Перезаписывать целую папку из-за совпадения имени было бы неожиданно.

**Медиатека.**

- Каждая операция возвращает `Outcome::touched` — затронутые папки с признаком «целиком» (перенесённая или скопированная папка) или «только сама папка».
- `Catalog::refresh_after_write` переслушивает только их. Для этого у сканера есть новый режим `ScanOptions::shallow`: перечисляется одна папка. Строки под существующими подпапками не трогаются, а под исчезнувшими — помечаются пропавшими.
- Дальше идёт обычный конвейер `rescan_folders`.
- Анализ структуры папок выполняется под затронутыми папками. Для одного только корня он ждёт следующего скана: иначе это обход всего источника.

**SMB.**

- В `pa-smb2` добавлены `smb2_pwrite`, `smb2_get_max_write_size`, `smb2_mkdir`, `smb2_rmdir`, `smb2_unlink`, `smb2_rename`. Все экспортируются сборкой 6.3.2 и внесены в `SMB2_REQUIRED_SYMBOLS` (`tools/libsmb2/lib/smb2.sh`), так что лицензионная проверка их требует.
- Кэшированные дескрипторы чтения libsmb2 открыты без `FILE_SHARE_DELETE`, поэтому перед записью по пути они закрываются на всех свободных соединениях.

**FTP.** Листинг теперь запрашивает `LIST -a`, а если сервер его отвергает — обычный `LIST`. Иначе vsftpd скрывает файлы с точкой, и папку с `.DS_Store` или служебным файлом корзины нельзя удалить.

**Что не входит:** UI и FRB-обёртки (UI-035), автоочистка корзины по расписанию (её вызывает UI-035), серверное копирование SMB (`FSCTL_SRV_COPYCHUNK`) и SFTP (`copy-data`).

### Последствия

- Хорошо:
  - одно ядро, один контракт-тест (`pa_vfs::write_contract`), прогнанный на Samba, Apache `mod_dav`, `rclone serve webdav`, OpenSSH, vsftpd и локальной папке;
  - ни одной новой зависимости.
- Плохо:
  - на WebDAV без `Content-Range` (`rclone`, nginx, Nextcloud) докачки нет, после обрыва загрузка идёт заново. Позже можно добавить chunking v2 Nextcloud;
  - корзина видна как скрытая папка в самом источнике (на NAS её видно через другие клиенты);
  - символическая ссылка внутри общей папки SMB, которую Samba разворачивает сама (`follow symlinks`), выглядит для клиента обычной папкой. Удаление такой «папки» удалит содержимое цели, если цель внутри той же общей папки. Сервер не даёт выйти за пределы share (`wide links = no` по умолчанию).

## Подтверждение

- `core/crates/pa-sources/tests/write_servers/run.sh` поднимает свои контейнеры `pa-test-net023-*` и прогоняет:
  - весь `write_contract` на каждом сервере;
  - загрузку 1 ГиБ с обрывом посередине и докачкой;
  - вариант только для чтения;
  - переносы между пятью источниками.
- `pa-vfs/tests/write_local.rs` проверяет тот же контракт на локальной папке, а также ссылки, папку без прав и бэкенд без записи.
- `pa-catalog/tests/file_writes.rs` проверяет обновление медиатеки после загрузки, переноса и корзины.
