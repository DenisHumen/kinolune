# ADR-NNNN: Чат-replay VOD Twitch онлайн

- **Статус:** Принят
- **Дата:** 2026-11-25
- **Решают:** исполнитель TWI-016 (владелец делегировал решения); мейнтейнер — по PR
- **Связано:** TWI-016, TWI-012 (чат), TWI-023 (эмоуты 7TV/BTTV/FFZ), TWI-024 (фильтры), TWI-017 (загрузчик VOD), TWI-028 (офлайн-архив), TWI-030 / [ADR-0148](0148-twitch-native-config-rollout.md) (конфиг), [ADR-0041](0041-build-flavor-mechanism.md) (флейворы), `docs/research/06-twitch-integration.md` §2.5, §3.4

## Контекст

У VOD Twitch чат записи есть только в неофициальной GQL-операции `VideoCommentsByOffsetOrCursor` (06 §2.5): страница сообщений от заданной секунды (offset) или после курсора последнего сообщения. Официальной альтернативы нет, поэтому, как и нативный плеер, это только full-сборка и только за флагом подписанного конфига. Нужно:

1. показывать чат записи в такт с плеером: при перемотке перерисовывать, на паузе стоять, задержка ±N с;
2. не качать весь чат длинного VOD заранее — страницы вокруг позиции, с упреждением и кэшем;
3. рисовать сообщения как живой чат: бейджи, эмоуты Twitch и 7TV/BTTV/FFZ, фильтры зрителя; удалённые модераторами — не показывать;
4. работать и без сети для скачанного VOD: файл чата рядом с видео (наш `.chat.json.gz` или TwitchDownloader).

## Решение

### 1. Формат — JSON TwitchDownloader

`pa_twitch::chat_replay::td`: `streamer`, `video`, `comments[]` (`_id`, `content_offset_seconds`, `commenter{_id,name,display_name}`, `message{body,fragments[{text,emoticon{emoticon_id}}],user_badges[{_id,version}],user_color}`), `FileInfo` и `embeddedData` хранятся как есть; неизвестные поля сохраняются (`flatten`), id читаются и строкой, и числом. Ответы GQL переводятся в этот же формат, так что онлайн, загрузка и файл рядом с VOD — одна модель. Файл может быть сжат gzip (`.chat.json.gz`, как пишут TWI-017 и TWI-018). Рядом с видео ищем `<stem>.chat.json.gz`, `.chat.json`, `.json(.gz)`, `_chat.json`, `-chat.json`.

### 2. Страницы вокруг позиции (`OnlineReplay`)

- Запросы — по offset (стабильнее, 06 §2.5). Первый — с 20 с до позиции (окно сообщений после перемотки), продолжение — от последней секунды страницы (она могла оборваться; дубли отбрасываются по id). Если вся страница внутри одной секунды — продолжение по курсору; курсор отклонён (integrity) — остаток секунды пропускается.
- Кэш — интервалы `[from, to)`, где все сообщения есть; живёт, пока открыт плеер. Повторный запрос уже покрытого места не идёт в сеть. Один запрос за раз (`tokio::Mutex`).
- Перемотка далеко вперёд в плотном чате не листает весь разрыв: если до позиции больше страниц, чем осталось в лимите, запрос начинается заново прямо перед позицией.
- Упреждение делает Dart: когда до конца покрытого меньше 30 с, просит следующий кусок.

### 3. Синхронизация — в Dart, бинарный поиск

`ReplayChatFeed` (app, `features/twitch/chat/replay_feed.dart`) получает позицию движка на каждое её изменение. Время чата = позиция − задержка. Бинарный поиск по отсортированным строкам: при движении вперёд (до 10 с) добавляются строки между двумя тиками, при перемотке назад или прыжке вперёд — `LinesReplaced` с последними N строками до новой позиции. Пауза и скорость получаются сами: чат следует позиции. Это `ChatFeed`, поэтому панель, список, эмоуты и фильтры живого чата (TWI-012/023/024) работают без изменений; добавлено только событие `LinesReplaced` в контроллер.

Сообщения с одинаковой целой секундой (GQL отдаёт целые секунды) равномерно распределяются внутри неё — иначе плотный чат шёл бы рывком раз в секунду. Дробные смещения (наши записи) не трогаются.

### 4. Рендер в ядре

`CoreChatReplay` (pa-frb) превращает комментарий в `ChatMessage` живого чата (фрагменты → диапазоны эмоутов в символах, бейджи set/version, `/me`), применяет `ChatFilters` и рендерит `ChannelAssets` (CDN по id, Helix при входе, 7TV/BTTV/FFZ через `ThirdPartyWatcher` без EventAPI — набор у записи не меняется). Отрендеренные строки кэшируются по id и сбрасываются при смене фильтров или эмоутов. Картинки — тот же 24-часовой кэш чата, два потока загрузки.

### 5. Ошибки и выключение

- Флаг выключен, нет хэша, kill-switch `twitch.chat_replay` или store-сборка — у VOD нет панели и кнопок чата, запросов нет.
- GQL отказал (`gql_hash_invalid`, `integrity_required`, `not_found`, сеть) — «Чат записи недоступен», видео играет; повтор не раньше чем через 10 с.
- Удалённые модератором сообщения (`message: null`, `state: "deleted"`, `deleted`/`is_deleted`) отбрасываются ещё в ядре.

### 6. Флейворы

Модуль `pa_twitch::chat_replay` компилируется только при `cfg(pa_twitch_native)`; API `CoreChatReplay` одинаков во всех флейворах (одни привязки), в store каждый вызов — `store_build`. Dart-панель создаётся только при `AppFlavor.twitchNative` (константа — AOT выбрасывает её из store). `tools/flavor/full-only-patterns.txt` дополнен путём модуля.

### 7. UI

На компьютере чат сбоку от видео; ширину меняет полоска между ними (260–640 px), она запоминается (`twitch_chat_width`, и для live-чата). «Режим «театр»» кладёт чат поверх видео — это и есть вариант для полного экрана. В шапке чата — «Показывать чат раньше / позже» (±1 с, до ±30 с) и «Вернуть чат к видео»; подпись показывает текущую задержку. Ввода нет: чат записи только для чтения.

### 8. Загрузки

Тот же флаг включает хук `with_chat_replay` загрузчика TWI-017: после скачивания VOD весь чат сохраняется рядом как `.chat.json.gz` (до 20 000 страниц, ошибка чата не роняет загрузку — заметка в отчёте).

## Последствия

- Конфиг: в `tools/remote-config/remote-config.next.json` добавлен хэш `VideoCommentsByOffsetOrCursor` (как у TwitchDownloader); `twitch.chat_replay` оставлен `false` — включает владелец подписью после живой проверки (`real_twitch_chat_replay` в `pa-twitch/tests/real_twitch.rs`).
- Ответы GQL в тестах — рукописные по форме реальных ответов (вымышленные канал и пользователи), а не записанные с Twitch: живой Twitch днём не трогаем.
- Офлайн-проигрывание скачанного VOD с чатом в плеере библиотеки (не в плеере Twitch) — задача TWI-028; ядро (`CoreChatReplay::open_file`, `find_chat_replay_file`) для неё готово.
- Не сделано: отдельное окно чата (pop-out), чат рядом с официальным embed-плеером (позиция embed доступна только через JS-события; при включённом нативном плеере он не используется).
