# ADR-0109: Установщик Windows и автообновление на Windows, macOS и Linux

- **Статус:** Предложен
- **Дата:** 2026-11-17
- **Решают:** агент по поручению владельца («максимально просто для клиента»; открытые вопросы решать самим и записывать)
- **Связано:** PKG-022, PKG-024 (тихие обновления, раздел ниже), PKG-018 ([ADR-0088](0088-in-app-updates.md)), PKG-019 ([ADR-0089](0089-macos-app-packaging.md)), PKG-020 ([ADR-0093](0093-windows-app-packaging.md)), UI-026 ([ADR-0090](0090-in-app-notice-banners.md)), PKG-005, PKG-008, CORE-008

## Контекст и проблема

После PKG-018 приложение само обновлялось только на Android и в Linux AppImage. На Windows был лишь портативный zip, на macOS — DMG; обоим приложение показывало страницу релиза. Проверка шла раз в сутки, подпись `SHA256SUMS` была необязательной («спящий» хук до появления ключа). Владелец попросил: на всех десктопах ставить приложение один раз, дальше оно обновляется само, по правилам его другого проекта (Universal-Video-Downloader, `src/main/services/updater*.ts`). Ключ подписи релизов уже есть во встроенном удалённом конфиге (`updates.release_public_key`).

## Факторы решения

- Без прав администратора и без ручных шагов; без своих серверов (ADR-0004).
- Без подписи кода (PKG-005/PKG-008 ещё не сделаны) — поэтому подмена файла должна отсекаться подписью minisign, а не системой.
- Обновление не должно мешать: ни ошибок от фоновой проверки, ни перезапуска посреди фильма.
- Проверяемость в CI на раннерах `windows-2025` и `macos-26`.

## Рассмотренные варианты

1. **Свой код в Dart поверх PKG-018 + Inno Setup на Windows** (выбран).
2. MSIX + App Installer — без подписи MSIX не ставится; подпись — PKG-005.
3. WinSparkle/Sparkle — свои форматы фидов (appcast), подпись EdDSA отдельно от нашей minisign, на macOS Sparkle требует подписанное приложение для надёжной замены; ещё одна нативная зависимость на две платформы.
4. NSIS/WiX вместо Inno Setup — WiX (MSI) per-user неудобен и тяжелее; NSIS сравним, но Inno проще для per-user установки с удалением из «Приложений» и тихого режима.

## Решение

### Windows: установщик

- **Inno Setup 6.7.4**, скрипт `packaging/app/windows/kinolune.iss`, сборка `installer.sh` из готового zip (те же файлы, что проверил `package.sh`: LGPL libmpv/FFmpeg, лицензии в `licenses\`). В CI Inno Setup скачивается с GitHub-релиза `jrsoftware/issrc` и проверяется по закреплённому SHA-256 (`fetch-inno.sh`). Лицензия Inno Setup — собственная, свободная; для некоммерческого открытого проекта ограничений нет.
- `PrivilegesRequired=lowest`: установка в `%LOCALAPPDATA%\Programs\Kinolune`, ярлыки в «Пуске» пользователя и на рабочем столе (по умолчанию включены), запись удаления в `HKCU` — видна в «Параметры → Приложения». Папку выбрать нельзя (`DisableDirPage`) — меньше вопросов. Язык мастера — по языку системы (русский/английский). Данные приложения (`%APPDATA%\app.kinolune`) при обновлении и удалении не трогаются.
- `AppId` постоянный (`{C3AAEA23-…}`), поэтому новый установщик ставится поверх старого. Перед копированием удаляются `data\` и `*.dll` прежней версии — старые файлы не остаются.
- Файл релиза — `kinolune-<версия>-windows-x64-setup.exe`; портативный zip остаётся.

### Когда проверять (правила образца)

`update_rules.dart`: первая проверка через **5 с** после запуска, затем тик раз в 10 мин и проверка, если с последнего *ответа* GitHub прошло **6 ч** (по настенным часам); после неудачной — повтор через **30 мин**; после сна (между тиками больше 20 мин) или возврата приложения на передний план — через **60 с**. Время в будущем (часы перевели назад) считается давним. Фоновая проверка **тихая**: без «Проверяем…», ошибка только в журнал, предложение остаётся как было. Она не запускается поверх идущей загрузки, проверки, установки и состояния «Перезапустить». Переключатель «Проверять обновления автоматически» (прежний, с новым текстом) отключает расписание целиком — обещание политики конфиденциальности сохранено.

### Что делать с найденной версией

Настройка «Когда выходит новая версия»: **«Обновлять автоматически»** (по умолчанию) или **«Только сообщать»**. Показывается там, где приложение ставит обновление само в фоне (установленная Windows-копия, macOS, AppImage). Автоматически = скачать и проверить в фоне сразу после проверки, затем полоса «Перезапустить». Само приложение **не перезапускается**, пока открыто: перезапуск посреди просмотра хуже, чем лишний клик. На Windows подготовленный установщик ещё и запускается тихо при выходе из приложения (`onExitRequested`), так что «просто закрыл и открыл» тоже обновляет. Android не скачивает в фоне: системный диалог появился бы сам по себе.

Если фоновая загрузка не прошла проверку, это пишется в журнал, предложение остаётся, а в этой сессии тот же релиз в фоне больше не скачивается (подменённый файл не качался бы каждые 6 часов). «Скачать» пробует снова и показывает причину.

### Полоса в приложении

Одна полоса сверху (как в образце): «Доступна версия X», «Что нового» (changelog релиза раскрывается в полосе), **«Скачать»**, «Позже»; во время загрузки — прогресс; готово — **«Перезапустить»**; ошибка — текст и действия. Карточка уведомления UI-026 о новой версии убрана: две разные подсказки об одном и том же только путали (часть ADR-0090 про обновления заменена этим решением).

### Проверка файла

`SHA256SUMS` + подпись minisign (`SHA256SUMS.minisig`) ключом `updates.release_public_key` теперь **обязательны** во всём приложении: нет ключа или подписи, подпись неверна, файла нет в списке, хэш не совпал, размер не тот — файл удаляется, установка не начинается (`coreArtifactVerifier(requireSignature: true)`). Хук «без ключа — только суммы» из ADR-0088 больше не используется приложением.

### Установка по платформам

- **Windows (установленная копия** — рядом с exe есть `unins000.exe`): проверенный `…-setup.exe` ждёт в кэше; «Перезапустить» запускает его с `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE=1 /RELAUNCH=1` и закрывает приложение. `/UPDATE=1` — установщик до минуты ждёт, пока освободится мьютекс приложения (`Local\app.kinolune.Kinolune`), плюс `CloseApplications=force`; `/RELAUNCH=1` — в конце запускает новую версию.
- **Windows zip** — только сообщает, «Скачать» открывает zip новой версии; подсказка про установщик.
- **macOS:** DMG **своей архитектуры**; Intel-сборка под Rosetta (`sysctl.proc_translated = 1`) получает arm64. DMG монтируется `hdiutil` (только чтение, без Finder), `Kinolune.app` копируется `ditto` рядом с установленным во временное `.Kinolune.app.update-<pid>`, карантин снимается **только с этой проверенной копии**, затем одна системная операция `renamex_np(RENAME_SWAP)` меняет местами две папки — на диске в любой момент целое приложение. Старый бандл остаётся рядом до следующего запуска (работающий процесс ещё читает из него библиотеки), потом удаляется. «Перезапустить» — `open -n` новой копии. Если папку приложения нельзя писать (например, `/Applications` без прав) — как в образце: открывается проверенный DMG, пользователь перетаскивает приложение сам.
- **Linux:** AppImage — как в PKG-018. Пакеты (`.deb`/`.rpm` — файл `package-type` рядом с исполняемым; Flatpak, Snap) и tar.gz — только сообщают, «Скачать» ведёт на файл своего типа (для Flatpak/Snap — на страницу релиза). Раньше Flatpak/Snap не проверялись вовсе.

### Журнал

Каждое изменение статуса (без тиков прогресса), отказ проверки, ошибки фоновых проверок, переключение настроек и запуск («Running X (kind/arch), mode …») пишутся через pa-log (CORE-008, только при включённой диагностике).

### Проверка в CI

- `windows`: сборка установщика, тихая установка, проверка файлов, ярлыков и записи в «Приложениях», запуск 20 с, тихое удаление и проверка, что ничего не осталось.
- `windows-update` и `macos-update`: две сборки этого коммита (`0.0.1-e2e.1` и `0.0.1-e2e.2`) с `--dart-define=KINOLUNE_UPDATES_API` (локальный `http.server`) и `KINOLUNE_UPDATES_TEST_KEY` (одноразовый ключ rsign2, созданный в джобе; релизные сборки не задают ни то, ни другое). Старая версия ставится как у человека (установщиком / копией из DMG) и запускается; её плановая проверка находит релиз, качает, проверяет подпись и ставит. Переменная `KINOLUNE_UPDATE_SMOKE` даёт тесту журнал и заменяет нажатие «Перезапустить»; тест ждёт строку «Running 0.0.1-e2e.2» от перезапущенного приложения и сверяет установленную версию.

## Дополнение: тихие обновления (PKG-024, 2026-11-19)

Запрос владельца: без вопроса «Обновить?» — новая версия качается в фоне и ставится при следующем запуске или в простое; короткая заметка «Что нового» после обновления; на ТВ и во время просмотра — никогда не прерывать. Отдельный ADR не заводим: это изменение режима «Обновлять автоматически» из этого решения.

- **Что такое «играет».** В `pa_player` появился `PlaybackActivity.busy`: `MediaKitEngine` сообщает о себе сам — идёт воспроизведение (видео, музыка, книга, стрим) **или открыт фильм**, даже на паузе (перезапуск закрыл бы его). Музыка на паузе не держит. Трейлеры (WebView) и Twitch-встраивание не учитываются — это короткие ролики, а не «просмотр».
- **Загрузка.** В «Обновлять автоматически» найденный релиз скачивается и проверяется в фоне, как и раньше, но не во время воспроизведения: загрузка ждёт конца просмотра и тогда стартует сама. Полосы «Доступна версия X / Скачать» нет; если фоновая загрузка не прошла проверку — предложение возвращается, как в PKG-022.
- **Компьютеры (установщик Windows, macOS, AppImage).** Готовое обновление ставится без вопросов: macOS и AppImage уже заменены на диске, поэтому следующий запуск — новая версия; на Windows установщик тихо запускается при выходе. Кроме того, приложение само перезапускается в новую версию в **простое**: 10 минут без нажатий клавиш, кликов и касаний, ничего не играет и окно впереди (`mayApplyWhenIdle`). Окно позади других не всплывает — ждём следующего запуска. Конец просмотра считается активностью, так что перезапуска «сразу после титров» нет. В «О программе» — «Версия X готова. Она установится при следующем запуске или когда ничего не играет…» и кнопка «Перезапустить» для нетерпеливых.
- **ТВ.** Приложение никогда не перезапускается само (`tv: formFactor == tv`); обновление ждёт следующего запуска.
- **Android.** Системный диалог установки обойти нельзя, и мы его не обходим. По не тарифицируемой сети (Wi-Fi; `ConnectivityManager.isActiveNetworkMetered`, неизвестно = тарифицируемая) APK качается и проверяется в фоне, затем полоса «Версия X скачана и проверена.» с «Установить» — только когда ничего не играет. Перед передачей в PackageInstaller файл **проверяется ещё раз** (он ждал на диске). По мобильным данным — только предложение, как раньше.
- **«Что нового».** Перед установкой список изменений релиза (до 4000 символов) запоминается в настройках (`updates_whats_new`); первый запуск этой версии показывает короткую полосу «Kinolune обновлён до версии X» с «Что нового» и «Закрыть» (и пишет в журнал «Updated to X»). Не поверх плеера. Заметка для более старой версии удаляется.
- **Режим «Только сообщать»** — без изменений: полоса, «Скачать», «Перезапустить»; сам не перезапускается.
- **Пакеты (deb/rpm, Flatpak, Snap), tar.gz и портативный zip** — без изменений: только сообщают и ведут на файл или страницу релиза.
- **Проверка файла не менялась:** `SHA256SUMS` + minisign обязательны везде; тихий путь вызывает тот же `coreArtifactVerifier(requireSignature: true)`.
- **CI.** `windows-update` и `macos-update` больше не подменяют нажатие «Перезапустить»: приложение перезапускается само по правилу простоя. `KINOLUNE_UPDATE_SMOKE` только сокращает простой до 15 с и снимает условие «окно впереди» (на раннерах нет оконного менеджера; само правило покрыто unit-тестом). Добавлен такой же тест для AppImage — `linux-update` (Xvfb, `platforms: linux` для пробного запуска, `linux_only` в `libmpv.yml`/`libsmb2.yml`). Все три проверяют и заметку «Что нового» в новой версии.

## Последствия

- Windows-пользователь ставит приложение один раз; дальше обновления приходят сами. Портативный zip остаётся для тех, кто его хочет.
- Релиз без подписи `SHA256SUMS` теперь не ставится ни на одной платформе: подписывать нужно каждый релиз (шаг `Sign SHA256SUMS` в `release-app.yml` уже есть, секрет `MINISIGN_RELEASE_KEY`).
- Без подписи кода SmartScreen и Gatekeeper по-прежнему предупреждают при *первой* установке; обновления через приложение их не вызывают (установщик запускается из приложения, карантин с проверенной копии снят).
- Новая зависимость `ffi` (BSD-3-Clause, уже была транзитивной) — для `renamex_np`.
