# ADR-0134: Plex — прямое воспроизведение по умолчанию, прогресс через timeline, «просмотрено» через scrobble, транскод только по долгому нажатию

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** NET-013, NET-012 ([ADR-0131](0131-plex-pin-sign-in-connections.md)), NET-014 ([ADR-0075](0075-jellyfin-client.md) — клиент Jellyfin, образец отчётов и импорта), PLAY-003, PLAY-005, MUS-012 ([ADR-0130](0130-music-server-playlists-offline-albums.md)), [ADR-0038](0038-network-playback-loopback-proxy.md)

## Контекст и проблема

После NET-012 сервер Plex — источник медиатеки: библиотеки читаются деревом `PlexFs`, файлы играют через локальный прокси. Не хватает того, что делает Plex «своим» сервером: позиция, на которой остановились в Kinolune, должна появляться в «Continue Watching» Plex Web, а позиция и «просмотрено», выставленные в Plex Web или другом клиенте Plex, — в «Продолжить просмотр» Kinolune; нужны плейлисты сервера и транскод сервера для случаев, когда файл не тянет сеть. Done when задачи: «прогресс, выставленный в нашем клиенте, виден в веб-интерфейсе Plex, и наоборот». Решать за владельца ничего не нужно: правило — «максимально просто для клиента».

## Факторы решения

- В приложении уже есть точки, через которые Jellyfin получает отчёты, отметки и импорт состояния (`JellyfinReporter`, `setWatched`, `importUserData` после скана, `_serverStream` перед плеером); второй набор для Plex удвоил бы код приложения.
- libmpv декодирует почти любой контейнер и кодек: транскод сервера нужен только для слабой сети или редкого файла, а сервер Plex на слабом NAS транскодирует плохо.
- Токены — только в хранилище секретов (ADR-0131); в журналах, SQLite и синхронизации их нет.
- Аккаунта plex.tv и claim-токена в CI нет: проверка — на синтетических ответах.

## Рассмотренные варианты

1. **Способ воспроизведения:** (а) спрашивать сервер (`/video/:/transcode/universal/decision` с профилем клиента), как Jellyfin (`PlaybackInfo`); (б) всегда прямое воспроизведение через прокси, транскод — только по запросу пользователя или когда файл выше выбранного битрейта.
2. **Отчёты:** (а) `/:/timeline` (как плееры Plex), (б) только `/:/progress` без сессии.
3. **«Просмотрено» после досмотра:** (а) свой `scrobble` при выходе после 90 %, (б) порог сервера (timeline `stopped` дальше порога сервер отмечает сам).
4. **Где подключить к приложению:** (а) отдельный `CorePlex`-слой для воспроизведения и свой репортёр в Dart; (б) те же вызовы `CoreJellyfin` (по item id), которые сами смотрят вид источника.
5. **Видеоплейлисты:** (а) оставить на сервере; (б) зеркалить как музыкальные (MUS-012) в видеоплейлисты медиатеки только для чтения.

## Решение

**1б, 2а, 3б, 4б, 5б.**

- **Прямое воспроизведение по умолчанию.** «Смотреть» у элемента Plex играет файл (ключ части `/library/parts/…`) через прокси диапазонами, как в NET-012; сервер не транскодирует, токен в плеер не попадает. Так быстрее старт и лучше качество, и это не зависит от мощности сервера.
- **Транскод по долгому нажатию на «Смотреть».** Долгое нажатие (ПКМ, клавиша меню, удержание OK на пульте) на главной кнопке фильма или сериала у элемента медиасервера (Plex, Jellyfin, Emby) открывает «Транскодирование на сервере»: «Исходное качество», «1080p · 8 Мбит/с», «720p · 4 Мбит/с», «480p · 1,5 Мбит/с». Выбор открывает HLS универсального транскодера Plex `/video/:/transcode/universal/start.m3u8` (`path=/library/metadata/{id}`, `mediaIndex`, `partIndex`, `protocol=hls`, `directPlay=0`, `directStream=1` для исходного качества и `0` для пониженного, `maxVideoBitrate`, `videoResolution`, `location=lan|wan` по адресу подключения, `session`, `X-Plex-Client-Profile-Name=Generic` и цель HLS H.264/AAC); у Jellyfin — `PlaybackInfo` с `force_transcode`/`max_bitrate` (уже было в ядре). libmpv не умеет наши заголовки, поэтому в этом URL токен стоит параметром `X-Plex-Token`: URL не логируется, `Debug` его скрывает. У локальных и прочих сетевых файлов долгое нажатие ничего не делает. Автоматический транскод — только если пользователь задал предел битрейта, а файл выше него (`needs_transcode`); других условий нет: libmpv играет всё.
- **Отчёты — timeline Plex.** Сохранения прогресса плеера (PLAY-005: каждые 5 с, на паузе и выходе) — это `GET /:/timeline?ratingKey=…&key=/library/metadata/…&identifier=com.plexapp.plugins.library&state=playing|paused&time=…&duration=…`; закрытие плеера или переход к следующей серии — `state=stopped`, для транскода с `X-Plex-Session-Identifier` и затем `/video/:/transcode/universal/stop`. Сервер сам хранит позицию — её и показывает Plex Web в «Continue Watching» — и сам отмечает просмотренным после порога (90 % по умолчанию, настраивается на сервере); своего порога и лишнего `scrobble` нет, чтобы не удваивать счётчик просмотров.
- **«Просмотрено» и Continue Watching из приложения.** «Отметить просмотренным» / «непросмотренным» — `/:/scrobble` / `/:/unscrobble`; удаление из Continue Watching сервера — `PUT /actions/removeFromContinueWatching`, на старых серверах без него — `/:/progress` с `time=0`. Избранного у Plex нет: вызов для Plex ничего не делает.
- **С сервера в приложение.** После скана источника Plex приложение читает свежий листинг (`viewOffset`, `viewCount`, `lastViewedAt` элементов, `PlexFs::media_files` после `refresh`) и переносит в медиатеку позицию и «просмотрено», если они новее локальных (`lastViewedAt` против времени локального прогресса; без `lastViewedAt` позиция сервера заполняет только элемент без локального прогресса). Логика переноса вынесена из моста в `Catalog::import_server_state` и общая с Jellyfin/Emby. Снятие отметки на сервере не снимает её локально (как у Jellyfin): у сервера нет времени снятия.
- **Подключение к приложению (4б).** `CoreJellyfin` — вызовы по id элемента медиатеки — сам определяет вид источника: Jellyfin/Emby идут в `pa-jellyfin`, Plex — в новые `SourceManager::plex_*` (`plex_playback`, `plex_report`, `plex_set_played`, `plex_remove_from_resume`, `plex_user_data`). `JellyfinReporter`, `setWatched`, импорт после скана и выбор потока перед плеером в приложении не дублируются; новый вызов моста один — `is_server_item` (нужен ли диалог по долгому нажатию). Вход в Plex остаётся в `CorePlex` (NET-012).
- **Видеоплейлисты (5б).** `SourceManager::server_playlists` для Plex читает `/playlists?playlistType=audio` и `…=video`; `ServerPlaylist::video` отмечает видеоплейлист, его элементы — фильмы и серии дерева (песни и элементы вне библиотек пользователя пропускаются). Скан зеркалит его в видеоплейлист каждого профиля, который видит источник, по ключу фильма или серии (как «Добавить в плейлист»); такой плейлист только для чтения (`require_own` во всех правках, `PlaylistInfo::server`), в «Добавить в плейлист» не показывается; изменения приходят со следующим сканом. Видеоплейлисты Jellyfin остаются на сервере, как раньше.

Не входит: экран просмотра видеоплейлистов (его нет и для своих плейлистов — они живут в медиатеке и появятся, когда будет экран); пункт «Удалить из „Продолжить просмотр“» в интерфейсе (вызов есть в ядре и мосте, как у Jellyfin); живые обновления с сервера по WebSocket (`/:/websockets/notifications`) — состояние сервера приходит со сканом; транскод субтитров по выбору дорожки (транскодер решает сам, `subtitles=auto`); выбор качества по умолчанию в настройках.

### Последствия

- Хорошо: по нажатию «Смотреть» Plex-файл играет так же, как файл с SMB, — без нагрузки на сервер; позиция Kinolune появляется в Plex Web в течение 5 с (ближайший отчёт), позиция Plex Web — после следующего скана.
- Хорошо: в приложении нет второго набора точек для Plex; импорт состояния Jellyfin и Plex — одна функция каталога с тестом.
- Плохо: проверка «done when» в этом PR — против синтетического сервера (`pa-plex/tests/support/mock.rs` хранит позицию, счётчик и время просмотра как сервер и меняет их по timeline/scrobble/unscrobble/progress/removeFromContinueWatching). Живая проверка с Plex Media Server и Plex Web — у владельца (каталог: SRC-121…SRC-126, CARD-39). Расхождения с реальным API (например, нужен ли серверу профиль `Generic` для HLS, работает ли перемотка в HLS без `offset`) обнаружатся там.
- Плохо: изменения, сделанные в Plex Web, видны в Kinolune после скана (таймер наблюдателя для сетевых источников), а не мгновенно.
- Нейтрально: в URL транскода есть токен — так устроен Plex для внешних плееров; URL живёт только в памяти плеера.
