# ADR-NNNN: Ввод текста на ТВ с телефона — эфемерное сообщение `input` в pa-sync, текст только запечатанным, без своих серверов

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (задачу поставил владелец, этот ADR оформляет решения по ней)
- **Связано:** `UI-027`, `SYNC-003`, `SYNC-010`, `UI-026`, `TWI-009`, `TV-002`; [ADR-0004](0004-no-project-servers-local-sync.md), [ADR-0040](0040-app-pairing-and-lan-sync.md), [ADR-0044](0044-playback-handoff.md), [ADR-0057](0057-twitch-live-notifications.md), [ADR-0074](0074-source-list-sync.md), [ADR-0090](0090-in-app-notice-banners.md); `docs/api/sync-protocol.md` §7.3

## Контекст и проблема

Набирать адрес SMB, пароль, PIN или поисковый запрос пультом по экранной клавиатуре долго. Владелец попросил: когда на телевизоре открыто поле ввода, сопряжённый телефон предлагает ввести текст у себя, а текст сразу появляется на ТВ. Своих серверов у проекта нет (ADR-0004), push от Google/Apple через наш сервер невозможен. Есть LAN-синхронизация между устройствами одной семьи (SYNC-006, ADR-0040) с TLS, привязанным к ключам сопряжения, и эфемерные сообщения `pb.*` (SYNC-003, ADR-0044). Есть контейнер `sb1` для паролей источников с ключом семьи (SYNC-010, ADR-0074). Есть внутренние баннеры UI-026 (ADR-0090) и локальные уведомления TWI-009.

## Факторы решения

- Без серверов проекта; хаб на сервере пользователя (SYNC-008) не должен видеть текст.
- Пароль нигде не оседает: ни в журнале, ни в outbox, ни в логах, ни на телефоне после ввода.
- Без правок каждого экрана: полей ввода в приложении десятки.
- Пульт продолжает работать, пока телефон печатает.
- Совместимость протокола v1: только новое сообщение, старые узлы его пропускают (§2).

## Рассмотренные варианты

1. Новое эфемерное сообщение `input` в протоколе sync, текст в контейнере `sb1` ключа семьи.
2. Операция в журнале (`op`), как `source.upsert`.
3. Отдельное соединение телефон → ТВ (свой порт, свой TLS), минуя pa-sync.
4. Текст открытым в кадре (TLS линка и так шифрует).

## Решение

Выбран вариант **1**.

- **Протокол** (`pa_sync::input`, `Message::Input`, `docs/api/sync-protocol.md` §7.3). Сессия — одно поле в фокусе, id — свежий UUID. `request` (ТВ → вся семья: `field`, `label`, `secret`, `ttl_ms` ≤ 5 мин), `open` (телефон поднял экран ввода — ТВ узнаёт, кто печатает), `text` (весь текст, не разница: потерянный кадр не портит поле), `submit`, `cancel` (любая сторона). Узел пересылает кадр всем остальным связям один раз на `(session, hlc)`, не кладёт его в журнал и outbox. Открытый `request` узел держит и повторяет новым связям, пока не придёт `cancel`/`submit` или не истечёт TTL.
- **Шифрование.** Любой текст (в том числе исходное содержимое не секретного поля в `request`) идёт только в `sealed`: `sb1` с ключом семьи и контекстом `input:<session>`. Кадр с открытым текстом не проходит `validate`; `request` секретного поля не несёт текста вообще. Перенесённый в другую сессию контейнер не открывается. Сервис открывает текст для приложения; `Debug` событий (`RemoteInput`, `CoreRemoteInput`) не печатает текст; приложение логирует только тип ошибки.
- **Ядро.** `SyncService::input_request` (возвращает `None`, если синхронизация не идёт) и `input_send`; событие `ServiceEvent::Input` только для кадров этому устройству (`to`) или всем. `pa-frb`: `CoreSync::{input_request, input_send}`, `CoreSyncEventKind::Input` с `CoreRemoteInput`.
- **ТВ** (`TvRemoteInput`). Не трогает экраны: следит за `FocusManager` и находит `EditableText` в фокусе. Вид поля — по `obscureText`, `keyboardType`, `autofillHints`, `textInputAction` (пароль, PIN, адрес, имя пользователя, поиск, текст), подпись — `labelText` поля. Запрос уходит, если фокус пробыл на поле 400 мс: проход пультом по форме не будит телефоны. Пришедший текст вписывается через `userUpdateTextEditingValue` (срабатывает `onChanged`, поиск идёт сразу), `submit` выполняет действие поля (`onSubmitted`). Уход фокуса с поля шлёт `cancel`. Кто печатает — карточка UI-026 «Ввод с телефона: Pixel 8» с кнопкой «Отмена»; фокус она не забирает, пульт работает как раньше.
- **Телефон** (`PhoneRemoteInput`, `RemoteInputSheet`). Отвечают только устройства с форм-фактором «телефон». Приложение на экране — нижний лист ввода открывается сам (тип клавиатуры по виду поля, пароль скрыт с кнопкой показа, подсказка «Уходит зашифрованным и не сохраняется на телефоне»). Текст уходит при каждом изменении, по порядку, без очереди устаревших значений. «Готово» шлёт `submit`, «Отмена» или смахивание — `cancel`; `cancel` от ТВ закрывает лист. Контроллер поля очищается при закрытии.
- **Фон.** Пока процесс жив, приходит локальное уведомление «Ввести с телефона» (`flutter_local_notifications`, как TWI-009; канал `remote_input`, пропадает через 5 минут). Нажатие открывает приложение, и лист открывается для запроса, если он ещё открыт. Разрешение на уведомления спрашивается при первом открытом листе, а не при запуске.

**Честные ограничения (без своих серверов):**

- Если приложение на телефоне выгружено системой или закрыто пользователем, ничего не придёт: нет процесса — нет узла LAN-синхронизации.
- Android: процесс в фоне живёт, пока его не остановит система (Doze, App Standby, экономия заряда). Возможная доработка — опциональная фоновая служба (foreground service с постоянным уведомлением, отдельная задача) или UnifiedPush через сервер пользователя (SRV).
- iOS: работает, пока приложение открыто или недавно свёрнуто (секунды–минуты, пока iOS не приостановит процесс); фоновой сети для LAN у нас нет.
- Старые узлы (до этой версии) отбрасывают `input`: если ТВ и телефон связаны через такой хаб, запрос не дойдёт.
- Ответить может любой телефон семьи; ТВ пишет текст от любого и показывает последнего, кто печатает.

**Не входит:** tvOS (SwiftUI, свои поля — отдельная задача `TV-*`), Big Picture на десктопе (там клавиатура), фоновая служба Android, диктовка, история ввода.

### Последствия

- Хорошо: работает на всех экранах ТВ без правок, включая будущие; ничего не хранится; хаб не из семьи текста не видит.
- Хорошо: протокол v1 не меняется, сообщение пропускается старыми узлами.
- Плохо: зависит от живого процесса на телефоне (см. ограничения).
- Плохо: определение вида поля эвристическое; поле с нестандартной клавиатурой получит обычный текст. Поле может задать `keyboardType`/`autofillHints`, чтобы телефон показал нужную клавиатуру.
- Нейтрально: на ТВ кнопка «Отмена» карточки доступна по F6/вверх, когда фокус не в поле; уход с поля тоже отменяет ввод.

### Как проверяем соблюдение

- `core/crates/pa-sync/src/input.rs`: привязка текста к сессии и ключу, проверка «текст только запечатанным», TTL запроса.
- `core/crates/pa-sync/tests/service.rs` (`remote_input_from_tv_to_phone`): два сервиса по loopback — запрос с ТВ доходит до телефона, текст и пароль — до ТВ, пароль не печатается в `Debug` и не попадает в журнал, отмена с каждой стороны закрывает другую.
- `clients/flutter/packages/pa_core/test/sync_test.dart`: то же через привязки Dart.
- `clients/flutter/app/test/remote_input_test.dart`: ТВ (поиск в приложении, поле пароля, проход по полям без запросов), телефон (лист сам, ввод, отмена с ТВ, закрытие листа, уведомление в фоне), скриншоты `docs/screenshots/progress/ui-027/`.
