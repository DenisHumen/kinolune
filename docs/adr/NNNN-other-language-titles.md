# ADR-NNNN: Сравнивать название файла со всеми названиями кандидата TMDB, а не только с русским и оригинальным

- **Статус:** Предложен
- **Дата:** 2026-11-16
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** META-033 (эта задача, отчёт владельца по alpha.10 на Windows), META-013/014 (поиск и скорер), META-016 (пороги и очередь проверки), META-032 ([ADR-0094](0094-real-library-names.md)), LIB-023 ([ADR-0095](0095-fast-network-library-recognition.md))

## Контекст и проблема

Отчёт владельца (alpha.10, Windows, русский интерфейс, медиатека на SMB-диске): у многих известных фильмов и сериалов нет названия и постера — `12 Monkeys [Двенадцать обезьян] (1995)`, `Princess Mononoke 1997`, `Steamboy 2004`, `Millennium Actress 2001`, `Cowboy Bebop Knockin' on Heaven's Door`, `Escaflowne The Movie (2000)`, `Psycho-Pass Movie`, `Steins Gate The Movie`; папки `Darker than Black`, `Darling in the Franxx`, `Psycho-pass`, `Steins;Gate 0`, `Youjo Senki`, `Great Teacher Onizuka`, `NieA Under 7 Remux`, `No Guns Life`, `Tenjou Tenge`, `Desert Punk`, `Boogiepop and Others`. Русские имена и фильмы, у которых английское название — оригинальное (`Atonement`, `1984`), находятся.

Мейнтейнер проверил TMDB с ключом проекта и `language=ru-RU`: каждый из этих тайтлов — **первый** результат поиска, с постером. Причина в ранжировании:

- метаданные запрашиваются на языке интерфейса, поэтому у результата поиска только русское `title`/`name` и `original_title`/`original_name`;
- скорер сравнивает название файла с этими двумя: `12 Monkeys` против `12 обезьян` / `Twelve Monkeys` — 0,54, `Princess Mononoke` против `Принцесса Мононоке` / `もののけ姫` — 0,59, `Youjo Senki` против `Военная хроника маленькой девочки` / `幼女戦記` — 0,11 (замер на ветке);
- ниже порога принятия 0,75 работа получает `not_found` — без названия и постера, «молча»; от 0,75 до 0,92 — `auto_review`.

Кроме того, в `12 Monkeys [Двенадцать обезьян] (1995)` русское название в скобках парсер отбрасывал.

## Факторы решения

- Лимиты TMDB (20 запросов в секунду у клиента, ADR-0095): не умножать запросы для всех работ.
- Отображаемое название — на языке интерфейса (META-032), как раньше.
- Не создавать тихих ошибок: замер `pa-eval` на корпусе v0 не хуже.
- Без своих серверов (ADR-0004).

## Рассмотренные варианты

1. Второй поиск с `language=en-US` для каждой работы — +1 запрос на каждую работу, а ромадзи (`Youjo Senki`) в английском названии нет (`Saga of Tanya the Evil`).
2. **Названия на всех языках только для слабых страниц**: если после поиска ничто не набирает `auto` (0,92), у первых трёх результатов страницы (порядок TMDB) запрашиваются `/translations` и `/alternative_titles`, их названия добавляются к записи кандидата, страница ранжируется заново.
3. Названия из встроенной базы аниме и AniList — только для аниме и только после этапа аниме (ADR-0095), фильмы и сериалы не покрывает.

## Решение

Выбран вариант **2** (`pa_catalog::metadata::match_search_titled`).

- Дополнительные запросы — только для работ, у которых поиск не дал `auto`, не больше 2 × 3 на запрос-название; ответы кэшируются (`TtlClass::Stable`), а переводы победителя этап метаданных читает и так — для него запрос бесплатный. Обычная работа с хорошим совпадением не делает ни одного лишнего запроса.
- К названиям из переводов добавляется «голова» до подзаголовка через тире: `Steins;Gate: The Movie − Load Region of Déjà Vu` → `Steins;Gate: The Movie` (файлы часто называют так).
- Отображаемое название и описание не меняются: берутся из деталей на языке интерфейса.
- **Название в скобках в другой письменности** (латиница ↔ кириллица, только свободные слова): альтернативное название работы и отдельный поисковый запрос, не часть основного (`pa-recognition`, версия парсера 0.3.1 — уже распознанные автоматически файлы перепланируются, META-032).
- **Ниже порога принятия — не «ничего»**: если ни один результат не набрал 0,75, но лучший не спорный (без ничьей с другим тайтлом) набрал от `REVIEW` = 0,6, работа получает его название и постер в состоянии `auto_review` («проверьте», как META-016 для 0,70–0,92). Ниже 0,6 и при ничьей — по-прежнему `not_found`. Полная очередь проверки — META-016.
- **Журнал** (`tracing`, для диагностики CORE-008): одна строка INFO на решение поиска (`pa_catalog::metadata`: тип, название, год, запрос, топ-3 кандидата с годом и оценкой, решение и причина) и одна на записанный итог работы; WARN на ошибки HTTP, сетевые ошибки и паузы 429 (`pa_metadata`; только путь запроса, без параметров и ключа).

### Последствия

- Хорошо: все 19 названий из отчёта находятся на синтетических ответах в форме реальных (`pa-catalog/tests/other_language_titles.rs`): 18 — `auto` с оценкой 1,0, `Psycho-Pass Movie` (TMDB: `Psycho-Pass: The Movie`) — 0,74, `auto_review` с постером.
- Плохо: у слабых работ до 6 запросов больше (только при первом прогоне — дальше кэш); работы от 0,6 до 0,75 теперь показываются с названием кандидата и пометкой «проверьте» — среди них бывают неверные.
- Нейтрально: `pa-eval` получил запрос `tmdb/titles` (синтетический TMDB отвечает всеми названиями записи каталога); миграций нет.

### Как проверяем соблюдение

- `pa-catalog/tests/other_language_titles.rs`, `parse::tests::bracketed_title_in_another_script_is_an_alternative_title`.
- Замер `pa-eval` на корпусе v0 «до/после» — `tools/recognition-eval/baselines/v0/meta033.md`.

## Открытые вопросы

- Порог `REVIEW` = 0,6 — разумное значение по умолчанию; окончательные пороги и очередь проверки — META-016.
- Названия из встроенной базы аниме (META-030) как дополнительные запросы к TMDB для аниме — отдельная задача, если понадобится.
