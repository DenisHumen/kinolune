# ADR-NNNN: Раздел «Стримы» (Twitch) — избранное по логину без входа, выбор плеера в приложении, «Открыть на Twitch» через QR и ссылку

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** `TWI-013`, `TWI-001`, `TWI-002`, `TWI-004`, `TWI-005`, `TWI-007`, `TWI-008`, `TWI-014`, `UI-007`, `docs/research/06-twitch-integration.md` §1.5, §2.4, §6.2–6.3, `docs/research/01-product-ux-design.md` §2.6, [ADR-0011](0011-maintainer-decisions-release-0-1.md) §5 (DEC-006), [ADR-0039](0039-remote-config-minisign.md), [ADR-0041](0041-build-flavor-mechanism.md), [ADR-0047](0047-twitch-vod-chapters.md)

## Контекст и проблема

DEC-006 (ADR-0011 §5): вход через Device Code Flow, а без логина — локальное избранное. Но Helix отвечает только с токеном, а зарегистрированного client id у проекта пока нет. Без него нельзя ни войти, ни узнать по имени канала его `user_id`. При этом модель TWI-007 (`twitch_favorites`) хранит избранное по числовому `user_id`. Нужно решить:

1. как хранить избранное, добавленное по имени без входа;
2. где выбирается плеер: нативный (full-сборки, TWI-004), официальный embed (store-сборки, TWI-005) или «Открыть на Twitch»;
3. как сделать «Открыть на Twitch» на всех устройствах, включая TV;
4. как назвать раздел и как указать Twitch, не нарушая brand guidelines.

## Факторы решения

- Без логина избранное должно работать сразу: «done when» TWI-013.
- Своих серверов нет (ADR-0004); данные Twitch кэшируются не дольше 24 часов (TWI-007), избранное — данные пользователя, не кэш.
- Store-сборки не играют Twitch нативно и не скачивают (ADR-0011 §5).
- Плееры (TWI-014, TWI-005) делают другие задачи; раздел не должен их ждать.
- Новые зависимости — только при необходимости; на TV ссылку открыть нечем.

## Решение

1. **Избранное по логину.** Приложение хранит избранное в своих настройках (`twitch_favorites`: логин, `user_id`, если известен, имя, аватар, время добавления, «закреплено»). Канал, добавленный по имени (`login`, `@login` или ссылка `twitch.tv/login`), сначала не имеет `user_id`. Как только Helix доступен (есть client id и вход), `TwitchService.refresh` находит канал по логину, дописывает `user_id`, имя и аватар и зеркалит избранное в `pa-library` (`CoreTwitch.set_favorite`). Оттуда его синхронизирует `pa-sync` (TWI-007). Без входа поиск идёт по избранному и кэшу библиотеки, а любой канал можно добавить по точному имени. Порядок (`сначала в эфире`, `по зрителям`, `по имени`, `недавно добавленные`, `по последнему эфиру`) и фильтр (`все / в эфире / не в эфире`) сохраняются; закреплённые всегда сверху.
2. **Выбор плеера — `decideTwitchRoute`.** Нативный плеер — только в full-сборке, только если подписанный конфиг разрешает (`twitch.gql_playback`, `player = native`, есть GQL client id, нет kill-switch) и плеер зарегистрирован (`TwitchService.nativePlayer`, TWI-014). Иначе — embed (`embedPlayer`, TWI-005). Если нет ни того ни другого — диалог «Открыть на Twitch». Sub-only VOD всегда ведут на Twitch: замок на карточке и ссылка (06 §2.4).
3. **«Открыть на Twitch» — QR-код и ссылка.** Диалог показывает QR-код страницы `twitch.tv` и ссылку с кнопкой «Скопировать». На телефоне https-ссылка открывает приложение Twitch (universal/app links). Так работает и на TV, и без новой зависимости (`url_launcher`) — так же, как ссылки в «О программе» (UI-016).
4. **Брендинг.** Раздел называется «Стримы» / «Streams» (ключ `navTwitch`), логотипа Twitch нигде нет. Twitch упоминается текстом: строка атрибуции внизу раздела, страниц канала и категории («Каналы, записи и эфиры — с Twitch. Kinolune не связан с Twitch»), кнопки «Открыть на Twitch» и «Смотреть на Twitch».
5. **Ядро.** `pa-frb` получает `CoreTwitch`: Helix и вход (`pa-twitch`), кэш, главы и «Продолжить» (`pa-library::twitch`). Сетевые вызовы идут на собственном current-thread runtime tokio объекта; reqwest требует tokio, а FRB вызывает функции на своих потоках. Client id задаётся при сборке: `--dart-define=KINOLUNE_TWITCH_CLIENT_ID`; по умолчанию его нет.
6. **«Продолжить».** Начатые VOD (`twitch:vod:<id>`) попадают в общий ряд главной через `HomeFeed.continueSources` (UI-007), пока раздел включён в настройках. Нажатие идёт через тот же выбор плеера.

## Последствия

- Без client id раздел полностью работает на избранном, но статуса эфиров, новых VOD и расписания нет: раздел честно об этом пишет. Всё остальное заработает, когда владелец зарегистрирует приложение Twitch.
- Избранное, добавленное по имени до входа, синхронизируется между устройствами только после разрешения в `user_id`: до этого оно живёт в настройках устройства.
- TWI-014 и TWI-005 подключают плееры одной строкой: присваивают `nativePlayer` или `embedPlayer`, экраны раздела менять не нужно.
- Тесты раздела используют фейковый Helix с выдуманными каналами (`lib/fakes/fake_twitch.dart`) и в сеть не ходят.

## Рассмотренные варианты

- **Миграция `pa-library` с избранным по логину.** Отклонено: `pa-library` — горячая общая зона, а модель TWI-007 намеренно привязана к `user_id` (стабилен при смене ника). Ожидающие разрешения логины — временное состояние одного устройства.
- **GQL без логина для поиска и статуса эфира.** Отложено до TWI-003 (прототип и оценка рисков); только full-сборки.
- **`url_launcher` для «Открыть на Twitch».** Можно добавить позже как дополнительный путь на телефоне и десктопе. QR-код и ссылка всё равно нужны для TV.

## Решения владельца

- Зарегистрировать приложение Twitch (публичный client id для DCF, без секрета) и решить, вшивать ли его в сборки (`KINOLUNE_TWITCH_CLIENT_ID` в CI выпуска).
- Нужен ли `url_launcher` (прямое открытие ссылки на телефоне и десктопе) в дополнение к QR-коду.
