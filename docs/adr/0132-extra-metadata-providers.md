# ADR-0132: Дополнительные провайдеры — TVmaze для ежедневных шоу, TheTVDB со своим ключом, Fanart.tv, OpenSubtitles moviehash → ID

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (поручил решать по правилу «максимально просто для клиента»), мейнтейнер
- **Связано:** META-012, META-009, META-013, META-016 ([ADR-0101](0101-review-inbox.md)), PLAY-008 ([ADR-0108](0108-subtitle-search.md)), UI-012 ([ADR-0128](0128-fix-match-paste-id-whole-folder.md)); `docs/research/03-metadata-recognition.md` §3.1, §4.4 (A11); `docs/legal/providers.md`

## Контекст и проблема

META-012 просит ещё четыре источника поверх TMDB/AniList/Shikimori: TheTVDB v4 (только ключ пользователя), TVmaze (ежедневные шоу, CC BY-SA), Fanart.tv (clearlogo и clearart; ключ проекта плюс личный ключ) и OpenSubtitles (moviehash → ID). Критерий готовности: тесты на записанных ответах; ежедневные шоу (A11, `The.Daily.Show.2025.03.14.Guest.Name.1080p`) матчатся по дате.

До этой задачи файл с датой вместо номера становился «эпизодом без номера», и **все** такие файлы одного шоу сходились в одну строку `episodes` (поиск строки шёл по `season/episode/absolute IS NULL`); дата из имени никуда не записывалась. Клиент OpenSubtitles (PLAY-008) умел искать субтитры по хэшу, но не отдавал, чей это файл. Ключа TheTVDB у проекта нет и быть не может (ToS TheTVDB, `docs/legal/providers.md`); ключа Fanart.tv и OpenSubtitles владелец ещё не завёл.

## Факторы решения

- Максимально просто для клиента: всё, что можно, работает само; настройка — только необязательный ключ TheTVDB (и необязательный личный ключ Fanart.tv).
- Никаких своих серверов и аккаунтов проекта, которых нет (ADR-0004): без ключа функция просто молчит.
- Приватность: наружу уходит минимум — название или ID шоу и дата; ID фильма; 16-значный хэш файла.
- Лицензии: TVmaze — CC BY-SA 4.0 (атрибуция со ссылкой), TheTVDB — атрибуция, Fanart.tv — права у авторов картинок.
- TMDB остаётся главным источником и порядком нумерации; новые источники только дополняют.

## Решение

### 1. Ежедневные шоу по дате (A11)

- **Распознавание.** Эпизод без номера, но с датой в имени получает `episodes.air_date` из имени и ищется **по дате** (`ensure_episode`): одна строка на дату, и после того как провайдер выдал ей номер, повторный скан находит ту же строку. «Забыть данные провайдера» (META-016) дату из имени не стирает.
- **TMDB, когда шоу найдено.** К сезонам работы добавляются сезоны TMDB, которые покрывают даты (сезон с самой поздней датой начала не позже даты эпизода, без S00). Строка с датой получает номер **эпизода TMDB того же дня** (первого, если их несколько), дальше на неё пишутся название, описание, кадр — как на любую нумерованную.
- **TVmaze — даты, которых нет в TMDB** (или все даты, если TMDB без ключа). Без ключа. Шоу ищется по TheTVDB или IMDb ID (из TMDB `/external_ids` или NFO), иначе поиском по названию — принимается только результат **с тем же названием** (`TitleKey`). `/shows/{id}/episodesbydate` → название, описание (HTML снимается), длительность. Номера TVmaze в `episodes` **не пишутся**: у ежедневных шоу TVmaze нумерует сезоны годами, а колонка хранит порядок TMDB.
- **TheTVDB — что осталось**, только с ключом пользователя: `/series/{id}/episodes/default?airDate=` → название, описание; номер в aired-порядке — в `episode_mappings` (`tvdb_aired`, источник `tvdb`).
- Без ключа TMDB ежедневные шоу всё равно идут в прогон (TVmaze есть всегда): работа остаётся «не найдена» (её найдёт TMDB, когда появится ключ), но эпизоды уже названы.
- ID шоу у TVmaze и TheTVDB сохраняются в `external_ids` (`tvmaze`, `tvdb/series`).

### 2. TheTVDB v4 — только свой ключ

- Ключа проекта нет. Поле «Ключ TheTVDB (свой)» и необязательное «PIN подписчика TheTVDB» в «Настройки → Метаданные → Дополнительные источники»; хранятся в защищённом хранилище (`SecureStore`, как ключ TMDB), в ядро идут через `CoreMetadataSettings`.
- `POST /login` → bearer-токен на месяц, только в памяти; продлевается через 25 дней или после 401 (один повтор). Ключ, PIN и токен не попадают в ключи кэша, логи и кассеты.
- Используется для ежедневных шоу (выше). Остальные применения TheTVDB (DVD-порядок, A16) — не в этой задаче.

### 3. Fanart.tv — clear logo и clear art

- Ключ проекта читается при сборке из `PA_FANART_API_KEY` / `CARGO_PA_FANART_API_KEY` (GitHub Secret, как TMDB и OpenSubtitles; добавлен в `release-app.yml`). Личный ключ пользователя — поле «Личный ключ Fanart.tv»: с ключом проекта идёт как `client_key`, без него — как `api_key`. Нет ни того ни другого — Fanart.tv выключен.
- Фильм — по ID TMDB, сериал — по ID TheTVDB (из TMDB `/external_ids`). Берётся лучший логотип и арт: язык метаданных → английский → без текста → любой; HD раньше SD; больше лайков раньше.
- Логотип пишется как `artwork.kind = 'logo'` (его уже показывает заголовок карточки, UI-009), арт — новый вид `clearart` (миграция `202701080000_META-012_clearart_contract`: пересборка `artwork` с расширенным CHECK; по правилам LIB-002 пересборка таблицы идёт в миграции `_contract`, хотя ни одна колонка не удаляется и старые сборки читают таблицу как раньше). `ItemDetails.clearart_url` доступен приложению; отдельного места в интерфейсе для арта в этой задаче нет.

### 4. OpenSubtitles: moviehash → ID

- Фильм или сериал, который TMDB **не нашёл по названию**, проверяется по OSHash его файлов (уже считается при скане, LIB-004; до двух самых больших файлов): `GET /subtitles?moviehash=…`, голосуют только субтитры с `moviehash_match`. Ответ — ID TMDB фильма или сериала (для эпизода — `parent_tmdb_id`); вид должен совпасть с видом работы.
- Дальше работа читается из TMDB по этому ID. Уверенность: **0,93 (авто)**, если не меньше двух субтитров за и ни одного против, иначе **0,8 («проверьте»)**. «Почему?» показывает «файл узнан по отпечатку в OpenSubtitles».
- Нужны ключ OpenSubtitles сборки (`PA_OPENSUBTITLES_API_KEY`) и ключ TMDB. Квоту скачиваний поиск не тратит. Аниме не проверяется (у него свой путь — база аниме, AniList, кадры).

### 5. Общее

- Сбой любого из этих источников не делает работу «ошибкой» и не останавливает прогон: то, что он добавил бы, будет запрошено в следующий раз.
- Кэш — общий `ProviderCache`: TVmaze — неделя (поиски) и месяц (даты), TheTVDB — неделя, Fanart.tv — месяц. Темп: TVmaze 2 запроса/с, TheTVDB 5/с, Fanart.tv 2/с, OpenSubtitles как в PLAY-008.
- Атрибуции: в «О программе» — TVmaze (CC BY-SA 4.0, ссылка), TheTVDB, Fanart.tv, OpenSubtitles; в `pa_metadata::attribution`; строки в политике конфиденциальности (ru + en).

## Рассмотренные варианты

- **Номера TVmaze в `episodes`.** Отклонено: TVmaze нумерует сезоны ежедневных шоу годами (`2025×31`), TMDB — по сезонам вещания; смешение ломает сезоны TMDB, когда ключ появится позже.
- **Сопоставлять даты, скачивая все сезоны TMDB.** Отклонено: у ежедневного шоу десятки сезонов по 150 эпизодов; достаточно сезонов, покрывающих даты.
- **TheTVDB с ключом проекта.** Невозможно: ключ в открытом коде противоречит ToS TheTVDB.
- **Хэш-поиск для каждого файла.** Отклонено: лишние запросы и утечка; только для работ, которые TMDB не нашёл.
- **Отдельный переключатель для каждого источника.** Отклонено правилом «максимально просто»: источники без ключа безвредны и работают сами, отключаются удалением ключа.

## Последствия

- Ежедневные шоу показываются по эпизодам с названиями; эпизоды сортируются по номеру, затем по дате эфира.
- Без ключей Fanart.tv и OpenSubtitles в сборке эти функции молчат (так собирают F-Droid и контрибьюторы). Владельцу нужно завести секрет `PA_FANART_API_KEY` (см. PR).
- Новая миграция пересобирает `artwork` (на нее ничего не ссылается).
- Не сделано: DVD-порядок и другие применения TheTVDB (A16), переводы названий эпизодов TheTVDB, место для clear art в интерфейсе, проверка на живых API (только синтетические кассеты, ключей нет).
