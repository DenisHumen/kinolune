# ADR-NNNN: Профили в приложении — «PIN родителя», общий лимит попыток, App Lock и Search Lock, скрытые «Стримы» и «Музыка»

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта
- **Связано:** `UI-015`, `LIB-012` (ADR-0055), `TWI-009` (ADR-0057); исследование 01 §1.5, §2.5 п.2, §3 п.2 и п.6

## Контекст и проблема

ADR-0055 оставил приложению две вещи: ядро не запрещает профилю с ограничениями управлять профилями, и ядро не ограничивает число попыток PIN. Кроме того, Twitch и музыка рейтингами не фильтруются. Нужно решить, что такое «PIN родителя», где и когда его спрашивать, как ограничивать подбор и что прятать в навигации детского профиля, не меняя API ядра.

## Факторы решения

- Ребёнок не должен выйти из детского профиля, открыть настройки или ослабить ограничения без родителя — ни перезапуском приложения, ни сменой экрана ввода PIN.
- Одинаковое поведение на телефоне, десктопе и TV (пульт, D-pad).
- Без изменений ядра и FRB.

## Решение

- **PIN родителя** — PIN любого профиля без ограничений (`!isKid && !isRestricted`). Отдельного «мастер-PIN» нет. Профиль с ограничениями, App Lock и Search Lock нельзя включить, пока такого PIN нет (приложение предлагает задать его текущему взрослому профилю), а последний PIN родителя нельзя убрать или удалить вместе с профилем, пока они ему нужны.
- **Где спрашивается.** Выход из профиля с ограничениями (в другой профиль, в том числе в выборе при запуске); раздел «Настройки» профиля с ограничениями — вместо страниц раздела показывается PIN-пад, страницы не строятся вовсе, после ухода из раздела замок возвращается; «Управление профилями» и выключение блокировок — в любом профиле, если PIN родителя существует. PIN, введённый на входе в «Настройки», действует до ухода из раздела или ухода приложения в фон.
- **Лимит попыток** — один на все PIN-пады приложения, хранится в Preferences (перезапуск не сбрасывает): 5 ошибок подряд без паузы, затем 30 с, и каждая следующая ошибка удваивает паузу до 1 ч; верный PIN обнуляет счётчик. Во время паузы PIN не проверяется вовсе (ни один экран), пад показывает обратный отсчёт.
- **App Lock** — PIN при запуске и при возвращении из фона (`AppLifecycleListener.onHide`); подходит PIN родителя или PIN активного профиля. **Search Lock** — PIN родителя перед «Поиском», до ухода в фон или смены профиля.
- **Скрытые разделы.** «Стримы» (Twitch) скрыты для профилей с ограничениями по умолчанию (решение владельца); родитель может разрешить их для профиля — настройка на устройстве (`profiles_hide_twitch_<sync_id>`). Уведомления «X в эфире» (ADR-0057) следуют той же настройке и перезапускаются при смене профиля. «Музыка» скрыта, если у профиля белый список папок и ядро не отдаёт ему ни одного трека.
- **Выбор профиля при запуске** — если профилей два и больше; выключается в настройках.
- **История поиска** — своя у каждого профиля.
- **PIN-пад** — сетка 3×4 из фокусируемых клавиш (D-pad ходит по ним, OK пульта нажимает), цифры клавиатуры и пульта, Backspace; Enter после набранных с клавиатуры цифр подтверждает ввод.

### Последствия

- Хорошо: защита держится только на приложении, но в одном месте (`ProfileController`), и покрыта тестами, в том числе на настоящем ядре (`profiles_rust_test.dart`).
- Плохо: лимит попыток и настройки блокировок — на устройстве, не синхронизируются; удаление данных приложения сбрасывает их (как и сам доступ к медиатеке).
- Плохо: в профиле с ограничениями источники и браузер папок отфильтрованы ядром, поэтому новые папки белого списка удобнее выбирать из профиля родителя (экран это подсказывает).
- Ограничение: API ядра по-прежнему позволяет управлять профилями из любого профиля; это защита UI, а не ядра.

## Рассмотренные варианты

1. **PIN любого профиля без ограничений — PIN родителя (выбрано).** Без новых сущностей и API ядра.
2. Отдельный мастер-PIN в Preferences или секретном хранилище — ещё один секрет, который нужно хешировать в приложении и синхронизировать.
3. Лимит попыток на каждый экран отдельно — переключение экранов давало бы новые попытки.
