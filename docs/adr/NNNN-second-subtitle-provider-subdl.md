# ADR-NNNN: Второй источник субтитров — SubDL (не Podnapisi), общий список с OpenSubtitles, ZIP распаковывается на устройстве

- **Статус:** Предложен
- **Дата:** 2026-11-24
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** PLAY-016, PLAY-008, LEGAL-002; [ADR-0108](0108-subtitle-search-opensubtitles.md), [docs/legal/providers.md](../legal/providers.md) («Subdl, Podnapisi»)

## Контекст и проблема

«Найти субтитры» (PLAY-008) ищет только в OpenSubtitles. Для многих релизов (особенно свежих сериалов и не английских языков) там пусто, а у OpenSubtitles дневная квота скачиваний. PLAY-016: второй источник рядом с OpenSubtitles — SubDL или Podnapisi — с общим ранжиром (совпадение хэша, языки профиля, загрузки); условия сначала прояснить; ZIP распаковывать, ASS оставлять ASS.

Ограничения проекта: своих серверов нет (ADR-0004), запросы идут с устройства пользователя; секретов в git нет; лицензии зависимостей — по allow-list ADR-0005 (никакого GPL).

## Факторы решения

- Условия провайдера позволяют стороннее приложение (или хотя бы не запрещают, и есть программа для разработчиков).
- Пользователю ничего не нужно настраивать, когда в сборке есть ключ проекта.
- Отказ одного источника не должен ломать выдачу другого.
- Файл субтитров — байт в байт (ASS со стилями рисует libass, PLAY-006); у пака сезона — файл нужной серии.
- Без новых зависимостей, если можно; тесты — на записанных ответах, без сети.

## Рассмотренные варианты

Провайдер:

1. **SubDL** — публичный REST API с ключом, раздел для сторонних приложений, бесплатный ключ (~2000 запросов в сутки), поиск по IMDb/TMDB ID, сезону и серии; архивы ZIP.
2. **Podnapisi** — документированного API и условий для сторонних клиентов нет (только неофициальные обёртки над сайтом).
3. Оба.

Распаковка ZIP:

1. **Свой минимальный разборщик** (центральный каталог, stored/deflate через `flate2`, который уже в дереве; CRC и лимит размера).
2. Крейт `zip` — тянет новые зависимости (и проверку лицензий каждой) ради чтения пары файлов.
3. Просить у API распакованный файл (`unpack`) — поле экспериментальное и есть не у всех результатов.

Где сливать результаты:

1. **В ядре** (`pa_catalog::subtitle_search`): оба поиска параллельно, один ранжир, ошибки — по провайдерам.
2. В Dart: два вызова, слияние в приложении — ранжир пришлось бы держать в двух местах.

## Решение

**Провайдер — SubDL** (вариант 1). Podnapisi не подключаем, пока у него нет документированного API и условий (docs/legal/providers.md). Страницы условий SubDL для автоматических запросов закрыты Cloudflare; то, что не удалось прочитать (кэш, атрибуция, коммерческое использование), помечено [не подтверждено] и сверяется владельцем; делаем по осторожному правилу: ответы поиска не кэшируем, подпись «SubDL.com» под списком и в «О программе».

**Ключ** — как у OpenSubtitles (ADR-0108): `Keys::subdl_from_build()` читает `PA_SUBDL_API_KEY` / `CARGO_PA_SUBDL_API_KEY` при компиляции; в `release-app.yml` ключ приходит из **secret репозитория** `PA_SUBDL_API_KEY` во все сборки (Linux, Android, Windows, macOS). Пока ключа в сборке нет (сборки из исходников, F-Droid), в «Настройки → Стиль субтитров → Субтитры из интернета» есть поле «Ключ API SubDL (необязательно)»; ключ лежит в защищённом хранилище устройства (`subdl_api_key`) и передаётся в ядро с каждым вызовом. Без ключа в SubDL ничего не отправляется.

**Запросы** (`pa_metadata::subdl`): `GET /api/v1/subtitles` с `api_key` в query (параметр учётных данных: не попадает в логи, канонический вид и кассеты). Фильм — `imdb_id` (`tt…`, иначе `tmdb_id`) и `type=movie`; серия — ID сериала, `type=tv`, `season_number`, `episode_number`; если по ID ничего (или ID нет) — `film_name` (кавычки и скобки → пробел) и год фильма. Языки — профиля плюс английский (`EN`, `RU`, `BR_PT`…), `subs_per_page=30`, `releases=1`, `comment=1`, `hi=1`. Темп — не чаще раза в секунду, по одному; `429 rate_limit`/`service_busy` и `5xx` — до двух повторов с `Retry-After`; дневной лимит (`daily_limit`, `quota_exceeded`…) и отказ ключа — без повторов. `{"status":false,"error":"Can't find…"}` — пустой ответ, не ошибка. У серии остаются результаты этой серии и паки, чей диапазон её включает (`full_season`, `episode_from`–`episode_end`).

**Ранжир** — общий (`pa_catalog::subtitle_search::rank_offers`): сделанные для этого файла (хэш есть только у OpenSubtitles), место языка в профиле, человеческий перевод раньше машинного, загрузки (у SubDL обычно неизвестны — 0), при прочих равных OpenSubtitles раньше. `Catalog::search_subtitles_from` спрашивает оба источника параллельно (`std::thread::scope`); упавший источник попадает в `failures`, предложения другого остаются. Для Dart ошибка поиска — только когда не ответил ни один источник (и «нет ключа» — только когда ключа нет ни у одного). Каждое предложение несёт `provider`; в плеере во второй строке — релиз, загрузки (если известны) и «OpenSubtitles» / «SubDL», внизу — «OpenSubtitles.com · SubDL.com». Ошибка скачивания называет свой источник.

**Скачивание** (`Catalog::download_subdl_subtitle`): архив с `dl.subdl.com` (только хосты `*.subdl.com`), до 16 МиБ; распаковка — свой разборщик `pa_metadata::zip_archive` (вариант 1: без ZIP64 и шифрования, CRC и лимит 10 МиБ на файл — защита от «ZIP-бомбы»). Файл выбирается так: пропускаются папки, `__MACOSX/`, `._*`, VobSub `.sub` рядом с `.idx`; у пака — файл, в имени которого (парсер `pa-recognition`) эта серия и сезон; при выборе SDH — SDH-файл; ASS раньше SRT. Нет файла серии — понятная ошибка; RAR — ошибка «не поддерживается». Дальше — как у OpenSubtitles: байт в байт рядом с видео (`<имя>.<язык>[.forced][.sdh].<расш>`) или в кэше по OSHash.

### Последствия

- Хорошо: больше находок, особенно по сериалам и не английским языкам; квота OpenSubtitles расходуется только на его варианты.
- Хорошо: отказ или лимит одного источника не прячет другой.
- Хорошо: ни одной новой зависимости (`flate2` уже в дереве), cargo-deny не меняется.
- Плохо: у SubDL нет хэша файла — его варианты никогда не «Точно для этого файла», синхронность не гарантирована.
- Плохо: RAR-архивы старых загрузок не открываются.
- Нейтрально: в SubDL уходят ID и (без ID) название с годом — отражено в политике конфиденциальности и docs/user/*/11-privacy.md.

### Шаг владельца

- Сверить вручную в кабинете subdl.com условия (кэш, атрибуция, коммерческое использование) — пункты [не подтверждено] в docs/legal/providers.md.
