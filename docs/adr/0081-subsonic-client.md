# ADR-0081: Клиент Subsonic/OpenSubsonic — свой небольшой клиент, песни сервера как дерево файлов `pa-vfs`, пароль в хранилище секретов, scrobble из музыкального плеера

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** NET-016, NET-011, NET-014, NET-015, MUS-003, MUS-012, MUS-015; `docs/research/01` §1.5 (музыка); [ADR-0013](0013-pa-vfs-blocking-positional-reads.md), [ADR-0037](0037-platform-secret-stores.md), [ADR-0038](0038-network-playback-loopback-proxy.md), [ADR-0075](0075-jellyfin-client.md), [ADR-0077](0077-emby-client.md)

## Контекст и проблема

Паритет с музыкальными клиентами (Symfonium, Substreamer, play:Sub) требует серверы Subsonic как источник музыки (research 01 §1.5): артисты, альбомы, треки, стриминг и scrobble; самый распространённый сервер — Navidrome, дальше Gonic, Airsonic-Advanced, Ampache. Все говорят на одном REST API Subsonic 1.16.1, многие — с расширениями OpenSubsonic (`openSubsonic: true`, список `getOpenSubsonicExtensions`, вход по `apiKey`).

В приложении уже есть музыка (MUS-004: главная, альбомы, артисты, плейлисты), очередь и плеер (MUS-003), сканер с тегами (`pa-scanner`, lofty), прокси воспроизведения (ADR-0038) и офлайн-копии (NET-019). Серверы Jellyfin и Emby попадают в них как дерево файлов `pa-vfs` (ADR-0075, ADR-0077). Нужно решить, как выглядит клиент Subsonic, как сервер попадает в музыку, что хранить вместо пароля и откуда брать scrobble.

## Факторы решения

- Медиатека, музыка, поиск, профили и офлайн-копии уже построены на `pa-vfs` и каталоге; второй путь для «серверных» треков удвоил бы ядро и UI.
- Аутентификация Subsonic: `u` + `t = md5(password + salt)` + `s = salt` (1.13+). Токен одноразовый по соли, поэтому **для каждого запроса нужен сам пароль** — в отличие от Jellyfin, токена доступа, который можно хранить вместо пароля, нет. Некоторые серверы (пользователи LDAP) токен не проверяют (ошибка 41) — тогда только `p=enc:<hex>`, то есть пароль почти открытым текстом. OpenSubsonic добавляет `apiKey` (расширение `apiKeyAuthentication`), отзываемый на сервере.
- Всё локально ([ADR-0004](0004-no-project-servers-local-sync.md)); секреты — только в `pa-secrets` (ADR-0037), не в SQLite и не в логах; URL запросов Subsonic всегда содержат учётные данные.
- Слой источников синхронный (ADR-0013); новых лицензий и OpenSSL не добавлять (deny.toml): `ureq` + rustls и `md-5` уже в lock-файле.
- Плеер — libmpv: оригинальный файл (FLAC, MP3, Opus…) он играет сам, транскод сервера не нужен.
- Scrobble — событие музыкального плеера (Dart), а не чтение файла: прокси видит только диапазоны байтов, а не «прослушано».

## Рассмотренные варианты

Клиент:
1. **Сгенерированный клиент** по схеме OpenSubsonic — схема неофициальная и неполная, большая часть серверов отдаёт поля по-своему (числа строками, одиночный объект вместо массива).
2. **Свой небольшой клиент** (`pa-subsonic`): ~15 вызовов, терпимые к серверам DTO.

Как сервер попадает в музыку:
3. **Отдельный путь «серверная музыка»** в каталоге и UI (треки из `getAlbum` без файлов) — новые экраны, свой поиск, свои офлайн-копии.
4. **Дерево файлов** `SubsonicFs: pa_vfs::Vfs` (`Артист/Альбом/NN - Трек.ext`, `cover.jpg`), файлы — оригиналы сервера (`stream?format=raw` с диапазонами). Сканер читает теги оригиналов как у локальной папки.

Секрет:
5. **Пароль один раз, хранить токен** — невозможно: Subsonic не выдаёт токен доступа.
6. **Пароль в хранилище секретов** (как у WebDAV/SMB), на провод — только соль и md5; при ошибке 41/42 — откат на `enc:hex`. Источник без имени пользователя хранит вместо пароля API-ключ OpenSubsonic.

Scrobble:
7. В ядре по чтению файла прокси — не отличает перемотку, предзагрузку и офлайн-копию от прослушивания.
8. **В приложении** по состоянию `MusicPlayerController`, через мост ядра по id трека.

## Решение

Варианты **2**, **4**, **6** и **8**.

- **Крейт `pa-subsonic`** (ureq + rustls/ring, `md-5`, `getrandom`): `Client` с `Credentials::{Password, ApiKey}`, режимы `AuthMode::{Token, HexPassword, ApiKey}`; новая соль на каждый запрос; ответ `f=json`, конверт `subsonic-response`, коды ошибок Subsonic → `Error` (40/44 — неверные данные, 41–43 — способ входа не поддерживается, 50 — нет прав, 70 — не найдено). Ошибки 41/42 при токене — один повтор с `enc:hex`, режим запоминается. Вызовы: `ping`, `getOpenSubsonicExtensions`, `getArtists`, `getArtist`, `getAlbum`, `getSong`, `getAlbumList2`, `search3`, `getCoverArt`, `stream`, `scrobble`, `getNowPlaying`. `Secret` не печатается в `Debug`, тексты ошибок не содержат URL.
- **Медиатека = дерево файлов.** `SubsonicFs` строит дерево из всех песен: быстрый путь — `search3` с пустым запросом по 500 (Navidrome и другие OpenSubsonic-серверы), иначе обход `getAlbumList2` + `getAlbum`. Папка — исполнитель альбома (`displayAlbumArtist`, иначе исполнитель альбома из `getAlbumList2`, иначе трека) и альбом; два альбома с одним названием — `Альбом (#2)`; диск 2+ — `2-01 - …`. Файл читается диапазонами с `stream?id=…&format=raw` (без транскода, упреждающее чтение 1 МиБ; если сервер не назвал размер, он узнаётся первым диапазоном). Дерево кэшируется на 5 минут. Так сервер сканируется (теги оригиналов, обложки `cover.jpg`), показывается в разделе «Музыка», ищется и играет через прокси без новых экранов.
- **Вид источника `subsonic`** в `pa-sources`: адрес `http(s)://host[:port][/base]` (вставленный `/rest` отбрасывается), имя пользователя, пароль — в хранилище секретов (`credential_ref`), никогда в SQLite. Источник без имени пользователя — API-ключ. `subsonic_probe` проверяет сервер до добавления; `subsonic_scrobble(id, rel_path, submission, time)` шлёт scrobble песни по её пути. Источник может синхронизироваться на другие устройства семьи, как WebDAV (SYNC-010: пароль только в сквозном шифровании).
- **Мост `CoreSubsonic`**: `probe(address, username, secret)` и `scrobble(item_id, submission, time_ms)`; для треков других источников — ничего.
- **Приложение**: Subsonic в окне «Добавить источник» — обычная форма источника (адрес, пользователь, пароль) с переключателем «Войти по API-ключу»; перед сохранением форма проверяет сервер (`probe`), неверный пароль виден сразу. `MusicScrobbler` слушает музыкальный плеер: «сейчас играет» при старте трека, «прослушано» после половины длины или 4 минут (правило Last.fm, которое серверы передают дальше), только для треков от 30 с; перемотка не считается. Повтор трека — новое прослушивание.
- **Тесты против Navidrome** — скриптом `core/crates/pa-subsonic/tests/navidrome/run.sh` (образ `deluan/navidrome:0.58.0`, GPL-3.0 — только как внешний тестовый сервер в Docker, его код не используется; песни генерируются ffmpeg из того же образа; контейнер и файлы удаляются после). Navidrome не требует принятия лицензии и не проприетарен, так что, в отличие от Emby (ADR-0077), скрипт можно запускать и в CI; включение в CI — решение владельца.

Не входит: транскод на сервере (`format=mp3&maxBitRate=`) и его выбор в настройках — libmpv играет оригиналы, для мобильной сети это отдельная задача; звёзды/рейтинги и синхронизация избранного; плейлисты сервера; подкасты, интернет-радио, тексты песен (`getLyricsBySongId`); выбор музыкальных папок сервера (`musicFolderId`); самоподписанные сертификаты (как у WebDAV — отдельно); вход по API-ключу проверен только юнит-тестами (Navidrome 0.58 ключей ещё не выдаёт).

### Последствия

- Хорошо: сервер Subsonic виден во всех существующих видах музыки (главная, альбомы, артисты, поиск, очередь, офлайн-копии NET-019) без отдельного UI; клиент ~1 500 строк вместе с юнит-тестами.
- Хорошо: пароль не уходит в сеть (только соль и md5), не лежит в SQLite; 5 интеграционных тестов против настоящего Navidrome: вход, обзор, дерево файлов байт в байт, scrobble, скан в медиатеку и стрим через прокси.
- Плохо: пароль хранится (в хранилище секретов ОС), а не одноразовый токен — так устроен Subsonic; md5 со солью — слабая защита от перехвата по HTTP, поэтому для доступа извне нужен HTTPS (как и для WebDAV). API-ключ OpenSubsonic это снимает, когда сервер его выдаёт.
- Плохо: скан читает теги каждого трека по сети (диапазоны начала файла); на большой медиатеке первый скан дольше, чем у Jellyfin, где хватает метаданных сервера. Повторные сканы инкрементальные (размер и время добавления).
- Нейтрально: изменения на сервере видны после пересканирования или истечения кэша дерева (5 мин).
