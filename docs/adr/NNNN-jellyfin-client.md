# ADR-NNNN: Клиент Jellyfin — свой небольшой типизированный клиент, библиотеки сервера как дерево файлов `pa-vfs`, решение о транскоде — за сервером

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** NET-014, NET-011, NET-015 (Emby), NET-010 (обнаружение Jellyfin по UDP), PLAY-005, PLAY-015; `docs/research/01` §1.5; [ADR-0013](0013-pa-vfs-blocking-positional-reads.md), [ADR-0038](0038-network-playback-loopback-proxy.md), [ADR-0048](0048-trickplay-previews.md), [ADR-0055](0055-profiles-parental-filters.md), [ADR-0061](0061-import-skip-markers.md)

## Контекст и проблема

Паритет с Infuse требует сервер Jellyfin как источник (P0, research 01 §1.5): вход (в том числе Quick Connect), пользователи и библиотеки, «Продолжить просмотр» с удалением из него, избранное, вторичные адреса, отчёты о воспроизведении, DirectPlay/DirectStream/Transcode HLS и trickplay сервера. Приложение уже умеет медиатеку (скан, распознавание, сетка, поиск, страницы), воспроизведение через локальный прокси (ADR-0038), превью перемотки (ADR-0048) и импорт меток пропуска (ADR-0061) — для файлов источников `pa-vfs`. Нужно решить, как клиент выглядит и как сервер попадает в эти виды, не дублируя их.

## Факторы решения

- Медиатека, поиск, профили (ADR-0055), офлайн-копии (NET-019), превью и метки уже построены на `pa-vfs` и каталоге; второй путь для «серверных» элементов удвоил бы UI и ядро.
- Всё локально ([ADR-0004](0004-no-project-servers-local-sync.md)): токен — в хранилище секретов, пароль не хранится.
- Слой источников синхронный (ADR-0013); новых лицензий и OpenSSL не добавлять (deny.toml).
- Разные версии серверов у пользователей (10.8–10.11): лишние и пустые поля не должны ломать разбор.
- Плеер — libmpv/FFmpeg: декодирует почти всё, поэтому по умолчанию — DirectPlay.

## Рассмотренные варианты

1. **Генерация клиента из OpenAPI** (openapi-generator, progenitor): десятки тысяч строк на ~30 нужных вызовов, async-рантайм или свои шаблоны, перегенерация на каждый релиз сервера; строгие типы падают на `null` и новых значениях enum.
2. **Свой небольшой клиент** по схеме OpenAPI 10.10: только нужные эндпоинты и поля, `null` → значение по умолчанию, неизвестные поля игнорируются.
3. Для медиатеки: **отдельная модель «серверных» элементов** (запросы к серверу на каждом экране).
4. Для медиатеки: **библиотеки сервера как дерево файлов `pa-vfs`**, которое сканирует и распознаёт существующий конвейер.
5. Решение о способе воспроизведения: **своя таблица кодеков на клиенте** против **профиля устройства, по которому решает сервер** (`PlaybackInfo`).

## Решение

Варианты **2**, **4** и «профиль устройства» из **5**.

- **Крейт `pa-jellyfin`** (ureq + rustls/ring, как `pa-metadata`): `Client` с заголовком `Authorization: MediaBrowser …` (Client, Device, DeviceId, Version, Token), пути 10.9+ (`/UserViews`, `/UserItems/Resume`, `/UserFavoriteItems/{id}`, `/UserItems/{id}/UserData`, POST `/QuickConnect/Initiate` с откатом на GET для 10.8). DTO читают только нужные поля; `Token` не печатается в `Debug`, тексты ошибок не содержат URL (в URL бывает `api_key`). Тесты закреплены на образе `jellyfin/jellyfin:10.10.7`.
- **Вторичные адреса.** Источник хранит основной адрес и список других; запрос идёт на адрес, ответивший последним, при ошибке соединения (не HTTP-статусе) — на следующие по порядку, первый ответивший становится текущим. Таймаут соединения 5 с.
- **Вход.** Пароль или Quick Connect; на устройство — свой `DeviceId` (UUID v7 при входе, хранится в `options_json`), имя устройства — ОС. В хранилище секретов (`credential_ref`) лежит **токен**, пароль используется один раз. Новый вид источника `jellyfin` в `pa-sources` (`JellyfinOptions`: user id, server id, device id и имя, другие адреса, необязательный список библиотек); правка источника в форме сохраняет вход.
- **Медиатека = дерево файлов.** `JellyfinFs` реализует `pa_vfs::Vfs`: библиотека → `Название (Год)/Название (Год).<ext>` с `movie.nfo` (TMDB/IMDb/TVDB), `poster.jpg`, `fanart.jpg`; сериалы `Сериал (Год)/Season NN/Сериал SxxEyy - Название.<ext>` с `tvshow.nfo`; музыка `Исполнитель/Альбом/NN - Трек.<ext>` с `cover.jpg`. Файл читается диапазонами с `/Videos|Audio/{id}/stream?static=true` (окно упреждающего чтения 2 МиБ). Дерево одной библиотеки — один постраничный запрос `/Items`, кэшируется на 5 мин. Так сервер сканируется, распознаётся (ид из NFO решают совпадение), показывается, ищется, фильтруется профилями и играет через прокси без новых экранов. Версии элемента — отдельные файлы (`… - 4K.mp4`), каталог сводит их в версии (LIB-010).
- **Trickplay и сегменты сервера — как сайдкары.** Trickplay `/Videos/{id}/Trickplay/{w}/{n}.jpg` отдаётся папкой `<stem>.trickplay/<w> - <c>x<r>/<n>.jpg` — ровно то, что читает `pa-trickplay` (ADR-0048); Media Segments — файлом `<stem>.jellyfin.json`, который уже импортирует PLAY-015 (ADR-0061). Эти файлы и картинки скачиваются при открытии и в листинге имеют размер 0 (размер известен только после загрузки); `ByteSource::size` открытого файла точный.
- **Способ воспроизведения решает сервер.** `DeviceCapabilities::libmpv()` строит `DeviceProfile` (DirectPlay: все распространённые контейнеры и кодеки; транскод — HLS MPEG-TS H.264 + AAC; текстовые субтитры — внешние, PGS/DVB — вжигаются) и отправляет его в `POST /Items/{id}/PlaybackInfo`. Ответ: `SupportsDirectPlay` → **DirectPlay** (файл через наш прокси, токен не попадает в плеер); `TranscodingUrl` с причинами только про контейнер → **DirectStream** (ремукс в HLS); иначе → **Transcode**. Для HLS плееру отдаётся URL сервера с `api_key` (libmpv не умеет наш заголовок; URL не логируется). Ограничение битрейта и «транскод по запросу» — параметры запроса.
- **Отчёты.** Сохранения прогресса плеера (PLAY-005, раз в 5 с, на паузе и выходе) — это `POST /Sessions/Playing` (первое) и `/Sessions/Playing/Progress`; закрытие плеера или переход к следующей серии — `/Sessions/Playing/Stopped` (и остановка транскода). Сервер сам ставит позицию продолжения и «просмотрено».
- **Состояние пользователя.** После скана источника приложение переносит в медиатеку позиции, «просмотрено» и избранное сервера (новее локальных). Избранное и «просмотрено», выставленные в приложении, уходят на сервер. Удаление из Continue Watching сервера — сброс `PlaybackPositionTicks` (так делают клиенты Jellyfin; отдельного флага у сервера нет).

Не входит: обнаружение серверов по UDP 7359 (NET-010), Emby (NET-015, адаптер поверх этого клиента), выбор библиотек в форме (опция есть в ядре), пункт «Удалить из „Продолжить просмотр“» в интерфейсе (его нет и для локальных файлов; в ядре и мосте вызов есть), синхронизация избранного сериалов (не файлов), самоподписанные сертификаты (как у WebDAV — отдельно), живое ТВ и записи.

### Последствия

- Хорошо: сервер Jellyfin виден во всех существующих видах (главная, сетка, поиск, страницы, профили, офлайн-копии) без отдельного UI; превью и метки сервера работают через уже проверенные пути.
- Хорошо: клиент небольшой (~2 900 строк вместе с юнит-тестами, против десятков тысяч у сгенерированного) и терпим к версиям сервера; тесты против настоящего Jellyfin в Docker со сгенерированной медиатекой.
- Плохо: распознавание идёт по нашему конвейеру, а не берётся у сервера целиком: при отсутствии TMDB-ид у элемента сервера название распознаётся по имени файла дерева (оно строится из метаданных сервера, поэтому совпадает с ними).
- Плохо: изменения на сервере видны после пересканирования (таймер наблюдателя для сетевых источников) или по истечении кэша дерева, а не мгновенно (нет WebSocket).
- Нейтрально: размер 0 у сайдкаров в листинге — отступление от буквы контракта `Vfs` (размер в `stat` и в открытом файле разный); потребители (сканер, trickplay, импорт меток) размер из листинга для них не используют.
