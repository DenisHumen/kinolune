# ADR-NNNN: Эмоуты 7TV, BetterTTV и FFZ в чате Twitch

- **Статус:** Принят
- **Дата:** 2026-11-24
- **Решают:** владелец проекта (приоритет и «включено по умолчанию», 2026-11-20), исполнитель TWI-023
- **Связано:** TWI-011 (эмоуты Twitch, `AssetStore`), TWI-012 (отрисовка чата, бюджет CPU), TWI-024 (настройки чата), [docs/legal/providers.md §2.4](../legal/providers.md)

## Контекст

Почти у каждого стримера есть эмоуты 7TV и BetterTTV, часто и FFZ. Без них чат показывает слова вроде `catJAM` текстом и выглядит сломанным. Twitch сообщает только свои эмоуты (диапазоны в сообщении); сторонние — это просто слова, которые клиент сам сопоставляет со списками провайдеров. Условия провайдеров проверены (providers.md §2.4): запрета на показ в стороннем чат-клиенте Twitch нет, FFZ запрещает хостинг и перераздачу своих картинок.

## Решение

1. **Где:** ядро, крейт `pa-twitch-chat`, модуль `third_party`. Парсеры ответов — чистые функции (sans-IO), тесты на записанных ответах.
2. **Запросы — прямо с устройства к провайдеру** через тот же HTTP-транспорт, что у Helix (`pa_twitch::Transport`). Без ключей, без токенов Twitch, только `User-Agent`. Эндпоинты: 7TV `7tv.io/v3/emote-sets/global` и `/users/twitch/{id}`; BTTV `/3/cached/emotes/global` и `/3/cached/users/twitch/{id}`; FFZ `/v1/set/global` (только `default_sets`) и `/v1/room/id/{id}`. 404 для канала — «у канала нет эмоутов».
3. **Сопоставление по словам.** Текст между эмоутами Twitch режется по пробелам, каждое слово ищется в одной хеш-таблице кода → эмоут. Эмоуты Twitch всегда главнее. Порядок среди сторонних: **наборы канала главнее глобальных; внутри одного уровня 7TV > BetterTTV > FFZ** (7TV сейчас самый распространённый). Регистр важен, пунктуация, приклеенная к коду, — не код.
4. **Zero-width.** 7TV: флаг активного эмоута `1` или флаг данных `256`. BTTV: известный список наложений (`cvMask`, `cvHazmat`, `SoSnowy`…; у API нет флага). Если zero-width эмоут идёт сразу после эмоута (через пробелы), пробелы убираются, а фрагмент помечается `overlay`; клиент рисует его поверх предыдущего (`Stack`). Без предыдущего эмоута он рисуется обычным. Текстовые модификаторы BTTV (`h!`, `w!`…) и эффекты FFZ (`ffzSpin`…) не поддерживаем — остаются текстом.
5. **Картинки.** 7TV — WEBP (анимированный и `_static`), BTTV — оригинал (GIF/PNG) и `static/…webp`, FFZ — `urls` и `animated` (WEBP). Масштабы 1×/2×/4× (у BTTV 3×). Ключ картинки — `<провайдер>:emote:<id>`, одна декодировка на ключ, как у эмоутов Twitch. Картинки идут в тот же кэш чата (≤ 24 ч).
6. **Кэш списков** — сырые ответы на диске (`<кэш>/twitch-emote-sets`), не старше 24 ч. Чат открывается с эмоутами из кэша, потом приходит свежий список.
7. **Обновление набора канала** — `ThirdPartyWatcher` в своём потоке: 7TV — через документированный EventAPI (`emote_set.update` набора и `user.update` владельца; после события ждём 3 с и забираем набор один раз); BTTV и FFZ — раз в 10 минут (их ответы маленькие); 7TV тоже раз в 10 минут, если EventAPI недоступен. Глобальные наборы — раз в 6 часов. Новый словарь подменяется в работающей сессии (`ChatSession::set_assets`) только если он изменился.
8. **Анонимный чат** узнаёт id канала из первого сообщения (тег `room-id`); до этого действуют глобальные наборы.
9. **Настройка:** «Эмоуты 7TV, BetterTTV и FFZ» в «Настройках чата → Расширенные», **включено по умолчанию**, хранится в профиле вместе с остальными настройками чата (TWI-024) и применяется на лету.

## Последствия

- Цена на сообщение — одна хеш-проверка на слово, без аллокаций, если слово не эмоут. Замеры — в PR TWI-023.
- Большой канал 7TV отдаёт ~2,4 МБ JSON (300 КБ в gzip). Поэтому 7TV обновляется по событию, а не по таймеру, и reqwest в `pa-twitch` получает фичу `gzip`.
- API 7TV v3 в режиме поддержки — при переходе 7TV на новый API нужен новый парсер; канареечный тест Twitch (TWI-020) можно расширить и на провайдеров.
- Если провайдер попросит не использовать его API, он убирается из `THIRD_PARTY_PROVIDERS` / `ThirdPartyConfig::providers` без изменений остального кода.

## Альтернативы

- **Прокси или наш сервер-агрегатор** — против принципа «никаких наших серверов».
- **Таймер для 7TV** — ~29 МБ в час без gzip на большом канале; отвергнуто в пользу EventAPI.
- **Сопоставление в Dart** — дублировало бы рендер ядра и ломало «одну декодировку на ключ»; отвергнуто.
