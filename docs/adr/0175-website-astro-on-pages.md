# ADR-0175. Сайт: Astro в `docs/site`, общий артефакт GitHub Pages с репозиториями APT/DNF

- Статус: **принят** (SITE-001)
- Дата: 2026-11-26
- Задача: SITE-001 · связано: DEC-001, DSN-003, DSN-017 ([палитра v2](../design/palette-v2.md)), PKG-023, SITE-002…SITE-006

## Контекст

Нужен сайт проекта: что такое Kinolune, загрузки из GitHub Releases, установка из APT/DNF, открытый код, пожертвования; языки uk, en, ru. ROADMAP оставлял выбор генератора (Astro или mdBook) и места (`docs/site/` или отдельный репозиторий) на ADR.

Ограничения:

- по DEC-001 у проекта один публичный репозиторий;
- GitHub Pages репозитория уже раздаёт `/apt`, `/rpm` и `/kinolune.asc` (PKG-023, `linux-repo.yml`). У репозитория один сайт Pages и один артефакт на деплой: второй workflow со своим `deploy-pages` затёр бы репозитории пакетов;
- цвета — только из семантических токенов (`design/tokens` → `tokens.css`), чтобы палитра v2 менялась без правок сайта;
- проект обещает приватность: без cookies, счётчиков и сторонних скриптов и шрифтов;
- дальше на сайт придут документация и API (SITE-003), манифесты (SITE-004), донаты и прогресс из ROADMAP (SITE-005), страница загрузок с автоопределением платформы (SITE-002).

## Решение

1. **Astro** (статическая сборка, без серверной части и без клиентских фреймворков). Версия закреплена точно, зависимости — в `docs/site/package-lock.json`, `npm ci --ignore-scripts`, телеметрия Astro выключена в CI. mdBook хорош для книги документации, но лендинг, локализованные страницы с общим шаблоном и генерируемые страницы (прогресс, загрузки) в нём делаются плохо; Astro покрывает и их, и в SITE-003 подключит Markdown из `docs/user`.
2. **Код в `docs/site/`** основного репозитория (DEC-001), без отдельного репозитория.
3. **Один артефакт Pages.** Сайт собирается в том же workflow, что и репозитории пакетов (`linux-repo.yml`, имя — «Pages (website and Linux repositories)»): сначала `dist/` сайта, поверх — `/apt`, `/rpm`, `/kinolune.asc`. Workflow запускается после релиза (как раньше), вручную и теперь при пуше в `main`, который меняет сайт, токены или ассеты бренда. Проверка `docs/site/scripts/check.mjs` роняет сборку, если сайт что-то кладёт в пути репозиториев.
4. **Адреса:** `https://denishumen.github.io/kinolune/` — выбор языка (запомненный выбор → языки браузера → English), страницы `/uk/`, `/en/`, `/ru/`, `404.html`. Базовый путь и адрес задаются `SITE_BASE`/`SITE_URL`, чтобы переехать на свой домен (SITE-006) без правок страниц.
5. **Цвета** — только `var(--pa-*)` через слой `--site-*` в `src/styles/site.css`; литерал цвета в стилях сайта роняет проверку. `tokens.css`, логотип, иконки и скриншоты копируются из `design/` и `docs/screenshots/` перед сборкой (`scripts/sync-assets.mjs`), в git не дублируются. Стекло и мягкие световые пятна — по требованиям палитры v2, с запасным вариантом при «Уменьшить прозрачность» и без движения при «Уменьшить движение».
6. **CI:** `site.yml` на PR (сборка + проверка: ключи всех языков совпадают, нет литералов цвета, все внутренние ссылки и якоря живые, нет сторонних скриптов, стилей и шрифтов, нет путей репозиториев пакетов).

## Последствия

- Сайт публикуется вместе с репозиториями пакетов: любой деплой пересобирает обе части. Если сборка сайта упала, пакеты тоже не обновятся — это сознательно, частичный артефакт стёр бы одну из частей.
- Пуш в `main` с правкой сайта пересобирает и репозитории пакетов из последних релизов (несколько минут CI, подписывается тем же ключом).
- Шрифт Inter не встраивается: сайт пишет `Inter, system-ui…` и берёт системный шрифт, если Inter не установлен (без запросов к сторонним CDN). Встраивание самохостингом — по решению при редизайне.
- Ссылки на донаты появятся после COMM-001 (SITE-005); до тех пор раздел «Поддержать» ведёт к issues и Discussions.
