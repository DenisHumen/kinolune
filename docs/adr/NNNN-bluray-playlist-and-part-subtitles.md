# ADR-NNNN: Blu-ray по самому длинному плейлисту `.mpls`; субтитры частей — дорожка EDL с длинами частей из глав mpv

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** LIB-021, LIB-017, LIB-020, PLAY-007, PLAY-006; [ADR-0042](0042-subtitle-style-and-sidecars.md), [ADR-0043](0043-disc-main-title-and-iso.md), [ADR-0045](0045-split-movies-mpv-edl.md), [ADR-0056](0056-subtitles-rendered-by-libmpv.md)

## Контекст и проблема

ADR-0043 выбрал основным потоком Blu-ray самый большой `BDMV/STREAM/*.m2ts`: диски с seamless branching (фильм из многих клипов по плейлисту) играли один клип, а бонусный фильм крупнее основного подменял его. ADR-0045 склеил части (`cd1`/`cd2`, VOB) одной шкалой через EDL mpv, но субтитры частей не склеивал: приложение подгружало только субтитры первой части.

Нужно (LIB-021):

1. Основной поток Blu-ray — по самому длинному плейлисту `.mpls`, клипы склеиваются через EDL (ADR-0045).
2. Смена выбора основного потока не теряет совпадения и прогресс (они висят на файле, ADR-0043).
3. Субтитры поздних частей (`Movie.cd2.srt`) показываются со сдвигом на длительность предыдущих частей в общей шкале.

## Факторы решения

- Без новых зависимостей и без GPL: libbluray в сборках нет (ADR-0043), разбор MPLS — свой, по публичному описанию формата.
- Анализ папок не открывает видеофайлы; читать маленькие служебные файлы он уже умеет (NFO).
- Совпадение, сделанное пользователем, и «Продолжить просмотр» переживают обновление.
- Субтитры: любые форматы и кодировки, которые читает mpv (SRT, ASS, VobSub, PGS; cp1251 в старых релизах), локально и по сети через прокси (ADR-0038); точные длины частей, даже когда `pa-probe` не работал.

## Рассмотренные варианты

Субтитры частей:

1. **Одна дорожка `edl://` из файлов субтитров частей**: каждый файл — сегмент длиной своей части (`length=`), часть без субтитров — отрицательный `start=` у следующего файла. Длины частей — из глав, которые mpv сам ставит на начало каждой части EDL.
2. Склейка текста в один файл со сдвигом меток времени (свой разбор SRT/ASS/VTT) и `sub-add` через `hex://` или временный файл.
3. `sub-delay` по сегментам: менять задержку при переходе через границу части.
4. Субтитры внутри EDL видео (`!new_stream`).

Перенос совпадений при смене основного потока:

1. **Шаг скана перед распознаванием**: совпадение диска (пользовательское первым, иначе самое старое) копируется на новые файлы основного потока, совпадения со «старых» потоков (теперь `ignore`) удаляются, строки под старым ключом `file:` переезжают на новый.
2. Миграция SQL при обновлении схемы: выбор потока зависит от плейлистов на диске, SQL его не знает.
3. Держать совпадение на старом потоке и прятать его из элементов: ключ прогресса и выбор пользователя расходятся с новыми частями.

## Решение

### Основной поток Blu-ray

`pa_scanner::mpls` разбирает плейлист: пункты (`PlayItem`), имя клипа, `IN_time`/`OUT_time` (45 кГц); у пункта с несколькими ракурсами берётся первый (имя в самом пункте); STN, подпути, метки не читаются. Анализ папок (`analyze_folders`) листает в `BDMV/` теперь `STREAM/` и `PLAYLIST/` (не `BACKUP/`), читает `.mpls` (до 512 КиБ, мусор пропускается) и передаёт их в `structure::analyze_with`.

Основной поток (`disc_titles`) — клипы самого длинного плейлиста (сумма `OUT − IN`), у которого все клипы есть в `STREAM/` и ни один не повторяется; при равной длине — меньше клипов, затем меньшее имя. Один клип — `main`, несколько — `part` 1..N в порядке плейлиста; дальше всё как у частей DVD (ADR-0045): `play_parts` отдаёт клипы, приложение склеивает их в `edl://`. Без годного плейлиста — прежнее правило ADR-0043 (самый большой `.m2ts`). Выбор зависит только от листинга и плейлистов, поэтому не меняется после `pa-probe`.

Клипы играют целиком: `IN`/`OUT` плейлиста в EDL не передаются (для них нужен `presentation_start_time` из `CLIPINF/*.clpi`). У фильмов клипы обычно используются целиком; если плейлист берёт часть клипа, лишние секунды на стыке будут видны.

### Перенос совпадений и прогресса

`pa-catalog` (`main_title::follow`) после отпечатков и до распознавания проходит диски источника: если на потоке, ставшем `ignore`, есть живое совпадение или файлы основного потока без совпадения соседствуют с совпавшими, «совпадение диска» (`user_set`/`user_confirmed` первым, затем самое старое) копируется на файлы основного потока без совпадений (вместе со `state`, `decided_by`, эпизодами) и заменяет на них автоматические совпадения с другой работой; совпадения на потоках `ignore` удаляются. Если ключ работы без TMDB (`file:<отпечаток>`) от этого сменился, строки `progress`, `favorites`, `collection_items`, `playlist_items` под старым ключом переносятся на новый (`UPDATE OR IGNORE`: если у нового ключа уже есть своя строка, она остаётся). Ключ `tmdb:movie:` от файлов не зависит и не трогается.

### Субтитры частей

Вариант **1**. Проверено на нашем libmpv (mpv 0.42): mpv принимает `edl://` в `sub-add`, читает каждый сегмент своим демультиплексором (кодировка определяется по каждому файлу), обрезает строки на границе сегмента и сдвигает метки на начало сегмента; отрицательный `start` расширяет сегмент влево, и метки файла отсчитываются от начала его части. Главы EDL mpv называет строкой части из EDL, поэтому длины частей берутся точно из `chapter-list` и `duration`, без `pa-probe`.

- Библиотека (`RustLibrary.sidecarSubtitles`): для фильма из нескольких частей берёт sidecar-субтитры каждой части (те же части, что в `playParts`) и объединяет их функцией `joinPartSubtitles`: файлы одного вида (расширение, язык, forced, SDH) по порядку в каждой части — одна дорожка с `SidecarSubtitle.parts` (файл на часть или `null`); субтитры папки и только первой части остаются обычными.
- Плеер (`MediaKitEngine.addSubtitle`): для `ExternalSubtitle.parts` строит `partSubtitlesUri(files, partLengths(…))` и добавляет его `sub-add` с прежним названием и языком; если шкала не EDL или главы не прочитаны — только файл первой части (или ничего, если её нет).
- `sub-delay` пользователя действует на всю дорожку, как раньше.

Вариант 2 требует своего разбора форматов, ломает кодировки (cp1251) и не работает для растровых субтитров. Вариант 3 — гонки при перемотке, `sub-delay` один на плеер. Вариант 4 смешивает дорожки субтитров с видео-EDL, а выбор и флаги внешних дорожек (ADR-0042) теряются.

### Последствия

- Хорошо: Blu-ray с seamless branching и диски, где бонус больше фильма, играют фильм целиком; совпадение пользователя, прогресс и избранное остаются.
- Хорошо: субтитры `cd2` видны в нужный момент — локально и по сети, в любой кодировке; путь проверен тестом на libmpv (`pa_player/test/edl_libmpv_test.dart`).
- Плохо: на дисках с «обфускацией» (сотни плейлистов одной длины в разном порядке клипов) выбирается плейлист с меньшим именем — не обязательно правильный.
- Плохо: анализ читает все `.mpls` диска при каждом проходе (по сети — по запросу на файл, обычно десятки файлов по несколько КиБ).
- Плохо: дорожка из файлов разных форматов получает кодек первого файла: части пары склеиваются только с тем же расширением.
- Нейтрально: другие устройства, где прогресс хранится под старым ключом `file:`, после синхронизации не найдут элемент по нему; ключ `tmdb:` не меняется.
- Нейтрально: нативные плееры (PLAY-AND, PLAY-APL) получат тот же список частей и файлов субтитров по частям; сдвиг они делают своими средствами.
