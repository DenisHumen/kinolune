# ADR-0178. Kinolune OS: варианты Server и Desktop/TV, раздача ISO и зеркала

- Статус: **принят как направление** (решение владельца 2026-11-27; детали — в задачах при реализации)
- Дата: 2026-11-27
- Задачи: DIST-020, DIST-024, DIST-028…031, DIST-036, DIST-037, DSN-022, SITE-007 · связано: [ADR-0010](0010-nas-os-phase0.md)

## Контекст

Kinolune OS сейчас — один headless-образ на `fedora-bootc` (NAS) с атомарными обновлениями и откатом (bootc/ostree, BUG-031). Владелец хочет, кроме сервера, систему для телевизора и компьютера: KDE Plasma с нашим брендингом (по образу Bazzite/Aurora из Universal Blue — тоже Fedora atomic/bootc) и рядом нашу собственную оболочку. ISO ОС должны лежать в GitHub Releases, откуда их будет брать и наш сайт.

## Решение

1. **Два варианта образа из одного репозитория:**
   - **Kinolune OS Server** — нынешний headless-образ на `fedora-bootc` (NAS, медиасервер, админка);
   - **Kinolune OS Desktop/TV** — на базе Fedora Kinoite (KDE Plasma, bootc). Брендинг в `/usr`: глобальная тема Plasma, цвета из токенов (DSN-022, palette-v2), оформление окон, иконки, курсоры, обои, SDDM, plymouth (DIST-037); настройки по умолчанию для новых пользователей. Пользовательские настройки в `/home` переживают обновления.
2. **Своя оболочка рядом** — отдельная Wayland-сессия (gamescope или cage, выбор — ADR задачи DIST-028), выбирается на экране входа; переключение «Kinolune ↔ Рабочий стол» из оболочки (как «Игровой режим ↔ Рабочий стол» в Bazzite) — DIST-029/030.
3. **Откат** — тот же bootc/ostree; greenboot (DIST-011) дополнительно проверяет, что SDDM и сессия поднялись, иначе автооткат.
4. **Видеокарты:** AMD и Intel — в основном образе; NVIDIA — отдельный вариант (DIST-020).
5. **Стабильность темы:** версия Plasma закреплена вместе с базой; перед публикацией CI проверяет вход в сессию скриншотом.
6. **Бренды:** идеи и устройство Bazzite/Aurora/Apple берём, их названия, логотипы и ассеты — нет; Fedora — только фактическое «основано на Fedora Linux». Темы KDE под GPL/LGPL допустимы.
7. **Раздача ISO:** основной источник — **GitHub Releases** (отдельные релизы на теги `os-v*`, ISO + `.sha256` + подпись minisign), сайт берёт ссылки оттуда (DIST-024, SITE-007).
8. **Если GitHub не подходит** (например, ISO Desktop больше лимита 2 GiB на файл): после сборки ISO выгружается на **наше зеркало на VPS**, сайт даёт ссылку на него, **без ограничения скорости**. Позже, при необходимости, — несколько VPS-нод с балансировкой (Kubernetes, настраиваем вручную; ориентир — Linode). Решаем ближе к завершению проекта, с минимальными расходами.
9. **Эксплуатация (идея на будущее):** минимальная постоянно работающая «консольная» нода, с которой агент имеет доступ к остальным нодам 24/7 для правок, и мониторинг всего через Grafana. Аккаунты, доступы и оплату владелец заводит сам; без владельца ничего не покупаем и не разворачиваем.

## Последствия

- Сборка и CI удваиваются по вариантам (Server, Desktop; позже NVIDIA); слои rechunk держат обновления небольшими.
- ISO Desktop, скорее всего, превысит 2 GiB — нужен план раздачи (п. 8) до первого публичного ISO Desktop.
- Server остаётся простым и маленьким; всё графическое — только в Desktop.
- Сроки: Desktop и брендинг — после основного функционала и вместе с редизайном (DSN-017, DSN-022); первый шаг — образ Desktop на Kinoite с минимальным брендингом и проверка в Proxmox (вход, Plasma, откат).
