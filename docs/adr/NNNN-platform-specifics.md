# ADR-NNNN: Особенности платформ — ссылки `kinolune://`, один экземпляр, меню-бар macOS, заголовки окон

- **Статус:** Предложен
- **Дата:** 2026-11-18
- **Решают:** владелец проекта (мейнтейнер); решения приняты агентом по правилу «максимально просто для клиента», владелец делегировал их
- **Связано:** `UI-022`, `UI-002`, `UI-035`, `PKG-019`, `PKG-020`, `PKG-022`, `PLAY-AND-009`; `docs/research/01-product-ux-design.md` §2.3–2.4, §4.10; ADR-0109, ADR-0110

## Контекст и проблема

UI-022 собирает то, чем приложение должно ощущаться «своим» на каждой платформе: меню-бар macOS, нативные заголовки окон Windows 11, GNOME и KDE, один экземпляр приложения, deep links, sidebar на iPad, «Поделиться» на Android, Files на iOS, web-upload [P1] и виджеты [P2].

Что уже было до этой задачи:

- **Windows:** один экземпляр через мьютекс (PKG-020). Второй запуск поднимал окно, но аргументы терял.
- **Android:** ссылки `kinolune://play|item|twitch` из лаунчера Android TV (PLAY-AND-009). Их маршрутизация работала только на ТВ; «Поделиться → Kinolune» уже сделан (UI-035).
- **Linux:** раннер был `G_APPLICATION_NON_UNIQUE`, то есть каждый запуск открывал вторую копию на той же базе. `app.kinolune.desktop` объявлял видео-типы с `%U`, но Dart аргументы не читал, поэтому «Открыть с помощью» ничего не делало.
- **macOS:** меню из шаблона Flutter (MainMenu.xib), схемы ссылок нет.
- **iOS:** у Flutter-приложения нет iOS-раннера (`clients/flutter/app/ios` отсутствует), и подписи Apple у проекта нет (PKG-012).

В ROADMAP схема записана старым именем `projectalpha://`. Продукт теперь называется Kinolune (ADR-0011), и `kinolune://` уже используется на Android TV.

## Факторы решения

- Просто для пользователя: одна схема ссылок, одно окно, привычные сочетания клавиш.
- Один путь в Dart для всех платформ. Нативный код только принимает и передаёт аргументы.
- Ничего, что требует подписи Apple, своих серверов или новых зависимостей.
- Ссылка из чужого источника (веб-страница) может только открыть страницу или поиск. Удалять и менять она ничего не может, блокировки приложения и профиля соблюдаются.

## Решение

### 1. Ссылки `kinolune://` на всех платформах

Схема одна — `kinolune://`. `projectalpha://` не регистрируем. Формат:

| Ссылка | Что делает |
|---|---|
| `kinolune://item/<id>` | страница фильма или сериала поверх главной |
| `kinolune://play/<id>` | продолжить просмотр (карточки Watch Next) |
| `kinolune://channel/<login>` | страница канала Twitch; при скрытом разделе «Стримы» (настройка или ограниченный профиль) ничего не делает |
| `kinolune://twitch/vod/<id>?t=<мс>` | запись Twitch с позиции |
| `kinolune://search?q=<текст>` | «Поиск» с запросом |

Кроме ссылок, аргументом запуска может быть абсолютный путь к файлу или `file://`. Такой файл играет вне медиатеки: аудио — в музыкальном плеере, видео — в полноэкранном плеере без сохранения прогресса, как в файловом браузере. Так работает «Открыть с помощью Kinolune». Опции (`-…`), относительные пути и папки игнорируются.

Разбор ссылок и переходы находятся в `lib/platform/app_links.dart` (`AppLink`, `openAppLink`). Код Android TV пользуется тем же разбором.

Регистрация схемы:

- **Android** — intent-filter `VIEW` для `kinolune://` с хостами `play`, `item`, `twitch`, `channel`, `search`. Ссылки принимаются на всех Android-устройствах, а не только на ТВ (канал `app.kinolune/tv`).
- **Windows** — установщик Inno Setup пишет `HKCU\Software\Classes\kinolune`. Портативный zip ничего не регистрирует.
- **Linux** — `x-scheme-handler/kinolune` в `app.kinolune.desktop`.
- **macOS** — `CFBundleURLTypes` в `Info.plist`, Apple Event `kAEGetURL`.
- **iOS** — после появления раннера (UI-038).

### 2. Один экземпляр и передача аргументов

Повторный запуск поднимает открытое окно и передаёт ему аргументы. Dart получает их по одному протоколу на канале `app.kinolune/links`:

- `take` — аргументы, пришедшие до того, как Dart начал слушать;
- `open(list)` — новые аргументы. Dart отвечает `true`, когда забрал их; иначе они ждут `take`.

Аргументы первого запуска приходят в `main(args)` и обрабатываются один раз за процесс. Новая оболочка после смены профиля их не повторяет.

- **Windows** — тот же мьютекс `Local\app.kinolune.Kinolune` (его ждёт установщик ADR-0109). Второй процесс находит окно, поднимает его и шлёт аргументы одним `WM_COPYDATA` (UTF-8 строки, каждая заканчивается `\0`, `dwData = "KLNK"`). Относительные пути он перед этим делает абсолютными.
- **Linux** — `GApplication` с `G_APPLICATION_HANDLES_COMMAND_LINE` вместо `NON_UNIQUE`: имя `app.kinolune` на сессионной D-Bus. Командная строка второго запуска приходит в первый процесс (`command-line`), он вызывает `gtk_window_present` и передаёт аргументы в Dart. Без сессионной шины каждый запуск работает сам по себе, как раньше. Перезапуск после обновления AppImage (`sleep 1`, затем новый процесс) не мешает: старый процесс к этому моменту уже вышел и освободил имя.
- **macOS** — один экземпляр обеспечивает LaunchServices. Ссылка приходит Apple Event'ом, окно выходит вперёд. `LSMultipleInstancesProhibited` не ставим: он запрещает вторую копию и другим пользователям Mac.
- **Android** — activity `singleTop` с `onNewIntent` и общий движок процесса (ADR-0068), как в PLAY-AND-009.

### 3. Меню-бар macOS

Меню строится через Flutter `PlatformMenuBar` (`lib/platform/app_menu.dart`) над всем приложением и действует на оболочку активного профиля. Системные пункты — `PlatformProvidedMenuItem`.

| Меню | Пункты и сочетания |
|---|---|
| Kinolune | О программе Kinolune · Настройки… ⌘, · Службы · Скрыть ⌘H · Скрыть остальные ⌥⌘H · Показать все · Завершить ⌘Q |
| Файл | Источники… ⌘O · Поиск ⌘F · Закрыть окно ⌘W |
| Вид | Главная ⌘1 · Фильмы ⌘2 · Сериалы ⌘3 · Стримы ⌘4 · Музыка ⌘5 · Книги ⌘6 · Личное ⌘7 (только показанные разделы, номера за разделами закреплены) · Назад ⌘[ · Полноэкранный режим ⌃⌘F |
| Воспроизведение | Воспроизвести/пауза ⌘P · Остановить ⌘. · Следующий ⌥⌘→ · Предыдущий ⌥⌘← |
| Окно | Свернуть ⌘M · Масштаб · Все окна — на передний план |
| Справка | Справка Kinolune (README проекта) · Сообщить о проблеме… (новый issue) |

Почему такие сочетания:

- **Пробел и ⌘←/⌘→ не занимаем.** Сочетание из меню перехватывается раньше поля ввода. Пробел сломал бы ввод в поиске, ⌘←/⌘→ — переход к началу и концу строки. Плеер по-прежнему сам обрабатывает пробел и стрелки.
- **«Воспроизвести/пауза» на ⌘P.** Печати в приложении нет, сочетание свободно.
- **Меню «Правка» нет.** ⌘C, ⌘V и ⌘A в полях ввода обрабатывает сам Flutter.

Команды «Воспроизведения» идут в `SystemMediaSession` (pa_player) тому, кто сейчас играет: видео, музыке или аудиокниге. Это тот же путь, что у системных медиакнопок. Если ничего не играет, команда ничего не делает.

Пока нет оболочки (онбординг, выбор профиля), пункты приложения неактивны, системные работают. «Закрыть окно» вызывает `performClose` через канал `app.kinolune/window`. Окно одно, поэтому приложение завершается, как и раньше при закрытии окна.

### 4. Заголовки и рамки окон

Рамку рисует система, свою не рисуем.

- **Windows 10/11** — тёмный заголовок всегда (`DWMWA_USE_IMMERSIVE_DARK_MODE`): приложение только тёмное, и светлая тема Windows не должна давать белую полосу над тёмным окном. На Windows 11 цвет заголовка — фон приложения `#0B0B0F` (`DWMWA_CAPTION_COLOR`). Snap-раскладки и скругления остаются системными.
- **Linux** — в GNOME-подобных средах (`XDG_CURRENT_DESKTOP` содержит GNOME, Unity, Pantheon или Budgie) окно получает GTK-шапку `GtkHeaderBar` «Kinolune», потому что там заголовок рисует приложение. В KDE Plasma, Xfce, Cinnamon, MATE и без среды остаётся системный заголовок оконного менеджера. `KINOLUNE_HEADER_BAR=1|0` переключает принудительно. GTK просит тёмную тему (`gtk-application-prefer-dark-theme`), поэтому шапка и системные диалоги выбора файлов тоже тёмные.
- **macOS** — стандартное окно с меню-баром.

Заголовок окна всегда «Kinolune». Его не меняем по содержимому: по этому заголовку второй запуск на Windows находит окно.

### 5. iPad

Остаётся адаптивная оболочка UI-002 — она и есть sidebar iPadOS. В альбомной ориентации (ширина ≥ 1024) — полное боковое меню. В портретной (744–1024) — узкая панель, как свёрнутый sidebar iPadOS. Отдельной ветки кода для iPad нет. Проверка на устройстве — после iOS-раннера (UI-038).

### 6. iOS: Files, web-upload, виджеты — следующими задачами

- **Files (UI-038).** У приложения нет iOS-раннера, ставить ключи `Info.plist` (`UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`, `CFBundleDocumentTypes`, `CFBundleURLTypes`) некуда. Раннер (`flutter create --platforms=ios`, плагины, LGPL-сборка libmpv для iOS — PLAY-APL-013) — отдельная работа; без подписи его можно собрать только для симулятора. Dart-часть (ссылки, «Открыть в Kinolune» файлом) уже общая.
- **Web-upload [P1] (UI-039).** Нужен HTTP-сервер в приложении с одноразовым кодом и страницей загрузки. Это не «просто», и делать это нужно вместе с UI-035 (очередь загрузок в «Личное»).
- **Виджеты [P2] (UI-040).** «Продолжить просмотр» на домашнем экране: WidgetKit требует App Group, а значит подписи (PKG-012). На Android — App Widget по тем же данным, что Watch Next.

### Последствия

- Хорошо: ссылка или файл из браузера, файлового менеджера и терминала открывается в уже запущенном окне. Вторая копия не открывает ту же базу (на Linux раньше это было возможно). Привычное меню на Mac. Заголовки окон не выбиваются из тёмного интерфейса.
- Плохо (цена решения): на Linux без сессионной D-Bus один экземпляр не обеспечивается. На Windows аргументы не дойдут, если окно зависло дольше 5 с (`SMTO_ABORTIFHUNG`). Сочетания клавиш разделов (⌘1…⌘7, ⌘F, ⌘,) есть только на macOS. Ctrl-аналоги на Windows и Linux можно добавить отдельно, если понадобятся.
- Нейтрально: файловые ассоциации Windows (видео → Kinolune) и `CFBundleDocumentTypes` macOS не регистрируем: пользователь выбирает «Открыть с помощью» сам.

### Как проверяем соблюдение

- `test/app_links_test.dart` — разбор ссылок и аргументов, передача от второго запуска (`take`/`open`), переходы.
- `test/app_menu_test.dart` — меню, сочетания, действия, меню на канале `flutter/menu`.
- `test/android_tv_test.dart` — общий разбор ссылок на ТВ.
- Каталог проверок: DESK-11…DESK-16, MAC-01…MAC-14, LINK-01…LINK-05. `tools/qa/check_catalog.py` требует строку для каждого `PlatformMenuItem`.

## Рассмотренные варианты

1. **Ссылки:** оставить `projectalpha://` из ROADMAP или поддерживать обе схемы. Отклонено: старое имя продукта, лишняя регистрация.
2. **Один экземпляр:** свой сокет или файл-замок в Dart (плагин вроде `windows_single_instance`). Отклонено: дублирует то, что ОС уже даёт (D-Bus GApplication, мьютекс, LaunchServices), и добавляет зависимость.
3. **Меню macOS:** править `MainMenu.xib` в Swift. Отклонено: меню не знает о скрытых разделах и профилях, его не проверить тестами на Linux CI.
4. **Заголовки:** свой заголовок без рамки (`window_manager`, `bitsdojo_window`) с кнопками в стиле платформы. Отклонено: research 01 §4.10 прямо говорит, что окна системные, а свой заголовок ломает Snap, тени и поведение KWin.
