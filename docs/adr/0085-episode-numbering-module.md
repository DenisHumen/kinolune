# ADR-0085: Модуль нумерации эпизодов — каноническое пространство AniDB/TMDB и проекции

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** META-015 (эта задача), META-008, META-014, META-016, META-017, META-018, META-025, META-029; [ADR-0046](0046-episode-display-order.md) (порядок серий на странице сериала), [ADR-0084](0084-scorer-pair-features-joint-group.md); `docs/research/03-metadata-recognition.md` §4.2 [6], §4.3

## Контекст и проблема

Релизёры нумеруют аниме тремя способами: сквозным счётом (`Shingeki no Kyojin - 38`), номером внутри куска AniDB (`… Season 3 Part 2 - 05`) и сезонами TMDB (`S03E15`). Скорер META-026/META-014 выбирал запись AniDB по догадке о франшизе (общий базовый ключ названия, порядок по году) и писал в схему TMDB то, что было написано в имени. Поэтому у скорера на train + dev точность эпизода в схеме TMDB была 0 % на A1, 9 % на A3 и около 60 % на A2 и A16, а пять файлов `Attack on Titan - 38…47` на test уходили в авто с неверной записью (ADR-0084). Медиатека (`pa-catalog`) вовсе не переводила сквозной счёт в сезоны TMDB: эпизод `- 38` оставался «абсолютным 38» без сезона, а `Season 3 Part 2 - 05` — «S03E05», и два разных эпизода сливались в одну строку при слиянии работ. Done when META-015: точность эпизода на A1–A4 и A16 ≥ 97 % в обеих схемах.

## Факторы решения

- Канон: AniDB для аниме, TMDB для остального (03 §4.2 [6]); порядок отображения выбирается на уровне серии.
- Данные нумерации — Anime-Lists `anime-list-master.xml` (сезон и смещение TVDB/TMDB, `mapping-list`) — без лицензии: только скачивание на устройство (META-008), в репозитории и бандле их нет. Тесты не ходят в TMDB, TVDB и TheXEM; ключей нет.
- Sans-IO ядро, детерминизм; тихие ошибки — главный KPI.
- Пользовательские решения нельзя перетирать новой моделью (решение владельца по ADR-0084: пересчитываются только автоматические неподтверждённые матчи).

## Рассмотренные варианты

1. Отдельный модуль нумерации с моделью «серия → записи AniDB → размещения в каждом порядке» поверх Anime-Lists и размеров сезонов TMDB, общий для скорера и медиатеки (выбран).
2. Чинить догадку о франшизе в скорере (порядок записей, отсечение лишних) без данных нумерации.
3. Писать в базу только TMDB-нумерацию и строить проекции по требованию из `episode_mappings` (META-029) — без канонического эпизода в распознавании.

## Решение

Выбран вариант **1**.

**Модуль** `pa_recognition::numbering` (sans-IO):

- `Canonical` — эпизод AniDB (запись, тип AniDB, номер) или TMDB (сезон, эпизод). Типы AniDB: regular, special (`S`), credit (`C`), trailer, parody, other.
- `Series` — серия TMDB/TVDB: записи AniDB по порядку, у каждой размещение в TMDB, TVDB aired и TVDB DVD (сезон + смещение или абсолютный порядок `a`), явные пары (`mapping-list`, место для TheXEM), размеры сезонов TMDB, эпизодные группы TMDB, связи TheXEM. `SeriesBook::from_mappings` собирает серии из Anime-Lists (записи с общим TVDB, иначе TMDB); `Series::infer_counts` выводит размеры записей из размещений и сезонов TMDB, когда счётчиков anime-offline-database нет (на устройстве).
- `Written` → `resolve` → `Canonical`: сквозной номер — запись с наибольшим смещением ниже номера; `SxxEyy` — сначала размещения TMDB, затем TVDB aired; номер внутри названной записи, больше её длины, — переливается в следующие. `read_parsed` выбирает чтение по имени: запись, которую называет заголовок (совпадение ключа названия), сезон из `SxxEyy`/папки, сезонный квалификатор заголовка, иначе сквозной счёт.
- `project` → `Projections`: AniDB, TMDB, TVDB aired/DVD, TVDB absolute (смещение записи + номер), эпизодные группы TMDB, scene (TheXEM). `Projections::display(DisplayOrder)` — порядок серии: TMDB, TVDB aired, TVDB DVD, абсолютный, AniDB (каждая запись — сезон, спешлы — сезон 0), группа TMDB, scene.
- `classify` — типы AniDB по имени: `.5`, `SP`, `Special`, `OVA` после ТВ-названия — спешлы; NCOP/NCED — credit, то есть extras, никогда не обычный эпизод; рекап остаётся обычным номером (AniDB так нумерует большинство рекапов). Спешлы попадают в TMDB/TVDB только через явные пары, а не «в S00 тем же номером»; номер `.5` неизвестен — проекции нет, не угадываем.

**Скорер** (`Scorer::with_series`): аниме-кандидат, чья запись AniDB есть в известной серии, берёт франшизу из серии (записи по размещениям, OVA из сезона 0 вне сквозного счёта), а не из догадки по названиям; явный сезон читается через размещения TMDB/TVDB (+0.02 к чтению по претензиям заголовков); OVA/ONA/спешл-записи нумеруют эпизоды внутри записи. Решение несёт `FileMatch::numbering` — проекции каждого эпизода. Веса и пороги скорера не менялись.

**Медиатека** (`pa_catalog::numbering`, приложение): после совпадения аниме-работы с сериалом TMDB прогон метаданных строит `Series` из деталей TMDB (размеры сезонов) и, если на устройстве есть скачанный Anime-Lists, записей AniDB; перечитывает имена файлов работы и переводит их эпизоды в номера TMDB (сквозной номер сохраняется в `absolute_number`), докачивает сезоны TMDB, куда они попали, — названия, кадры и порядок AniDB (META-029) доходят до верных эпизодов. Без списка работает только сквозной счёт через сезоны TMDB; номер внутри второго кура остаётся как написан. Явные `SxxEyy` не меняются; не-аниме работы не перенумеровываются. Миграций нет.

**Пересчёт и `model_version`** (решение владельца): `MODEL_VERSION = scorer_v1`. Прогон метаданных берёт работу снова, если у неё есть автоматический матч скорера старой версии. Пересчитываются только «пересчитываемые» матчи: `state` `auto` или `auto_review` и файл не под правилом папки пользователя (`folder_rules`, META-017; префикс пути источника). Матчи `user_confirmed`/`user_set` и под правилом не меняются ни по работе, ни по нумерации, ни по `model_version`. Работа, за которую говорят только автоматические матчи старой модели, ищется в TMDB заново (её TMDB id тоже был решением модели); работа с пользовательским или NFO-матчем сохраняет id, её автоматические матчи перенумеровываются и получают новую `model_version`.

**Замер** (`pa-eval episodes`): точность эпизода по категории и схеме — верных среди решённых авто на пороге 0.92 (решение владельца: done when на 0.92), верно = авто, верная работа, те же позиции в схеме; полнота — среди размеченных. Данные нумерации — синтетический список в формате Anime-Lists `baselines/v0/anime-lists-synthetic.xml` (`catalog.py --anime-lists`): правила мейнтейнера из `titles.yaml`, по которым размечен корпус; TVDB id синтетические (≥ 9 000 000) и только группируют записи. Это **не** данные Anime-Lists. `tmdb-anime-catalog.jsonl` получил размеры сезонов TMDB.

**Что не входит.** Данные TVDB DVD, эпизодных групп TMDB и TheXEM: модель и проекции есть, источников нет (ключей нет, условия не проверены) — проекции пустые. Новые порядки (TVDB, группы) в UI не добавлены: приложение уже даёт выбор порядка на уровне серии (TMDB / абсолютный / AniDB, ADR-0046), остальные — когда появятся данные. Запись `episode_mappings` для TVDB-порядков — там же.

### Последствия

- Хорошо (train + dev, порог 0.92, отчёт `baselines/v0/meta015.md`): у скорера со списком точность эпизода 100 % в AniDB и TMDB на A1, A2, A3, A4, A16 (было TMDB: 0 %, 59,3 %, 8,9 %, 14,6 %, 60,3 %; AniDB A4: 45,2 %); ошибок по категориям: A4 −71 %, A2 −4,5 %, все −31 %, тихих 0 → 0. Медиатека: TMDB 99,0–100 % без списка и 100 % со списком; ошибок A1 −67 %, A2 −61 %, A3 −89 %, A16 −78 % при тех же тихих.
- Test (один прогон после заморозки кода): скорер 100 % в AniDB и TMDB на всех пяти категориях; пять тихих ошибок `Attack on Titan - 38…47` → 0 (всего тихих 6 → 1, оставшаяся — вне аниме); медиатека TMDB 100 %. Тихие ошибки медиатеки на train + dev не изменились (44, из них 42 — OVA в A4, работа, а не нумерация).
- Плохо (цена решения): числа измерены со списком, построенным по тем же правилам, что и разметка, поэтому это точность распознавания *при верных маппингах*, а не качество настоящего Anime-Lists; сверка разметки с TMDB/TVDB — META-025. Перенумерация меняет строки эпизодов существующих библиотек при первом прогоне `scorer_v1`.
- Нейтрально: полнота ограничена Coverage работы (A2 89,6 % в AniDB): нерешённые работы уходят в проверку, а не в авто.

### Как проверяем соблюдение

Юнит-тесты `pa_recognition::numbering` (сквозной номер по записям и проекция в TMDB, `SxxEyy` во второй кур, запись по названию, типы AniDB, порядок отображения, западная серия в TMDB, серия из Anime-Lists со спешлом и OVA в сезоне 0), скорера (`Attack on Titan - 38…47` → Season 3, эп. 1–10, S03E01–10, абсолютные 38–47; OVA внутри записи), `pa_catalog::numbering` и интеграционные `pa-catalog/tests/numbering.rs` (сквозной счёт без списка, запись по названию со списком, пересчёт только автоматических неподтверждённых матчей и `scorer_v1`), `pa-eval episodes`. `baselines.sh` пересчитывает `meta015-*.md`; `pa-eval episodes` выходит с кодом 1, если точность ниже 97 %.
