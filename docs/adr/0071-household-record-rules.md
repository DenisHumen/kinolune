# ADR-0071: Правила записи Twitch принадлежат дому, а не профилю на экране: монитор с двумя потребителями

- **Статус:** Предложен
- **Дата:** 2026-11-15
- **Решают:** владелец проекта (решение принято владельцем, этот ADR его оформляет)
- **Связано:** `TWI-019`, `TWI-009`, `TWI-018`, `LIB-012`, `UI-015`; [ADR-0055](0055-profiles-parental-filters.md), [ADR-0057](0057-twitch-live-notifications.md), [ADR-0059](0059-profiles-ui-locks.md), [ADR-0065](0065-android-media-session-bridge.md), [ADR-0068](0068-android-background-music-engine.md), [ADR-0069](0069-twitch-storage-naming-import.md)

## Контекст и проблема

AutoRecord (ADR-0069) слушает монитор «X в эфире» (TWI-009) через `follow_live`. Монитор же останавливается при активном детском профиле (ADR-0057: `live_monitor` отвечал `Restricted`, приложение не запускало наблюдатель и перезапускало его при каждой смене профиля). Вместе с монитором останавливалась и автозапись: запланированный эфир пропадал, пока устройством пользуется ребёнок. Кроме того, приложение держало монитор только для правил активного профиля и только для каналов из избранного этого профиля.

Владелец решил: правила записи принадлежат дому (устройству), а не зрителю на экране.

## Факторы решения

- Автозапись не зависит от того, кто сейчас смотрит.
- Детскому профилю не показываются уведомления «X в эфире», раздел «Стримы» и записи.
- Детский профиль не может менять правила (защита ядра ADR-0055, токен родителя).
- Смена профиля не останавливает монитор.

## Решение

Один монитор, два потребителя.

- **Потребитель записи** (`CoreTwitchDownloads::follow_live` → `AutoRecord`). Наблюдатели монитора получают каждое событие, какой бы профиль ни был активен. Правила читаются для всех профилей (`record_rules(None)`). Новый вызов `recorded_channels()` возвращает каналы с включённым правилом любого профиля (логин и имя из библиотеки, `notify = false`). Приложение держит монитор, пока есть хотя бы одно такое правило, даже если канала нет в избранном активного профиля и уведомления выключены.
- **Потребитель уведомлений.** `CoreTwitch::live_monitor` больше не отказывает детскому профилю. Вместо этого у монитора есть шлюз уведомлений (`AlertGate`): для каждого `MonitorEvent::Alert` ядро перечитывает активный профиль (`activate_recent`) и не отправляет событие в Dart, если профиль детский или с фильтрами. Наблюдатели записи получают событие до шлюза. В приложении `LiveNotificationController` получает `notifyAllowed` (тот же признак профиля). Пока он ложен, монитор смотрит только каналы правил без колокольчика, а уведомления не показываются. При смене профиля вызывается `profileChanged()`: каналы обновляются на работающем мониторе, перезапуска и остановки нет. Монитор останавливается, только когда не осталось ни колокольчиков, ни правил. `restart()` остаётся только для смены входа в Twitch. Фоновая проверка Android (`check_live_once`) только показывает уведомления, поэтому детскому профилю по-прежнему ничего не показывает.
- **Что скрыто для детского профиля.** Уведомления «X в эфире» (выше). Раздел «Стримы» (UI-015, без изменений). Записи, сохранённые файлы, правила и настройки хранилища: `AppServices.visibleArchive` равен `null` для любого профиля под надзором и для профиля со скрытыми «Стримами». Все точки входа (карточка и кнопка в «Стримах», кнопка «Запись» на канале, плитка настроек, экраны архива) берут его. Даже если родитель показал ребёнку «Стримы», записей ребёнок не видит.
- **Изменение правил.** `set_record_rule` и `delete_record_rule` принимают `parent_token`. Проверку делает тот же `Catalog` (`Catalog::authorize_parent`, тот же токен и те же правила, что у управления профилями в ADR-0055). Для этого `CoreTwitchDownloads::open` получает `CoreLibrary` той же базы. Без токена при активном профиле под надзором ядро отвечает `denied`, Dart получает `ProfileAccessDenied`. `RustLibrary.parentToken` отдаёт токен, а `CoreTwitchArchive` передаёт его сам.

Не входит: запись без запущенного приложения (по-прежнему SRV-016 / сервис Android), перенос правил из профиля в «дом» в схеме базы (столбец `profile_id` остаётся: владелец правила и группа retention).

### Последствия

- Хорошо: эфир по правилу записывается, пока на экране детский профиль; переключение профиля не рвёт EventSub и не теряет события.
- Хорошо: правила защищены тем же токеном родителя, что и профили; отдельного механизма нет.
- Плохо: монитор работает при детском профиле, если есть правила. Сеть и батарея расходуются так же, как у взрослого с правилами.
- Плохо: шлюз уведомлений на каждое уведомление берёт блокировку соединения `CoreTwitch`. Уведомления редки, задержка не заметна.
- Ограничение: как и в ADR-0055, без PIN родителя детский профиль не защищён: ядро не может отличить родителя. ADR-0059 не позволяет приложению попасть в это состояние.
- Ограничение: если трансляция началась при детском профиле, уведомление о ней не придёт и после возврата к родителю: ядро показывает одно уведомление на трансляцию, а это уже отброшено.
- Ограничение: `set_settings` (папки, квоты, шаблоны) токен не проверяет: приложение применяет шаблоны при каждом запуске, в том числе при детском профиле; экран настроек хранилища детскому профилю недоступен. Решение за владельцем.

## Как проверяем соблюдение

- `cargo test -p pa-frb --features full --lib -- twitch`:
  - `twitch::kid_profile_gets_no_live_notifications`: монитор доступен, шлюз закрывается и открывается вместе с профилем без перезапуска.
  - `twitch_live::gated_alerts_still_reach_the_record_consumer`: детский профиль не пропускает уведомление в Dart, но наблюдатель записи получает все события.
  - `twitch_archive::a_kid_profile_keeps_auto_record_queuing`: при активном детском профиле `stream.online` канала с правилом родителя ставит задачу `twitch_live_record`, а `recorded_channels` отдаёт этот канал.
  - `twitch_archive::rule_changes_need_the_parent_token_in_a_kid_profile`.
- `cargo test -p pa-catalog --test parent_guard`: `authorize_parent` отказывает без токена и принимает верный.
- `flutter test test/twitch_autorecord_profiles_test.dart` (и с `--dart-define=KINOLUNE_FLAVOR=full`):
  - после смены на детский профиль наблюдатель не останавливается и смотрит канал правила без колокольчика, уведомлений нет;
  - записи скрыты (`visibleArchive`, карточка в «Стримах»);
  - изменение правила без токена — `ProfileAccessDenied`.
  - Скриншоты: `docs/screenshots/progress/twi-019-kid/`.
