# ADR-0112: Каждое исправление учит папку: правило папки с шаблонами релиза, без запросов к провайдерам и без путей в синхронизации

- **Статус:** Предложен
- **Дата:** 2026-11-17
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** META-017 (эта задача), META-016 ([ADR-0101](0101-review-inbox.md)), META-034, META-015 ([ADR-0085](0085-episode-numbering-module.md)), LIB-007, SYNC-001, SYNC-010, `docs/research/03-metadata-recognition.md` §4.6

## Контекст и проблема

Пользователь исправляет распознавание в инбоксе «На проверку» и в «Исправить распознавание» (META-016, META-034), но исправление касается только уже найденных файлов одной работы. Новая серия в той же папке распознаётся заново по имени: снова уходит в поиск, снова может попасть не туда и снова получает номер «как написано», а не тот сдвиг, который пользователь уже подтвердил. Таблица `folder_rules` и операция синхронизации `folder_rule.set` заложены в схему с LIB-001 и SYNC-001, но ничего их не заполняло. Исследование 03 §4.6: исправление распространяется на группу (папку), становится правилом папки (`path_prefix`, сущность, схема нумерации, сдвиг, тип) и паттерном релиза; правила синхронизируются на устройства семьи.

## Факторы решения

- Максимально просто для пользователя: ничего не настраивать, правило появляется само из того, что он уже сделал.
- Новый файл в папке получает ту же серию, тот же маппинг и тот же сдвиг локально, без сети.
- Правило никогда не забирает чужие файлы (другой сериал в той же папке, решения NFO, решения пользователя о другой работе).
- В синхронизации нет путей: только стабильная ссылка на папку.
- Без новых экранов: дизайн общий, редизайн позже.

## Рассмотренные варианты

1. Правило только по префиксу пути: всё в папке — эта работа.
2. **Правило папки + шаблоны релиза, выученные из исправленных имён; правило применяется к файлу, если совпал шаблон или название файла — одно из названий работы.**
3. Только шаблоны релиза без правила папки (краудбаза «скелет имени → серия», 03 §4.8).

## Решение

Выбран вариант **2**: вариант 1 забирает чужие файлы из общей папки (`Anime/` с несколькими сериалами), вариант 3 не покрывает файлы с другим именованием в той же папке.

**Когда появляется правило** (`pa_catalog::folder_rules`). Любое исправление пользователя: «Верно» (`review_confirm`), другой результат или ручной поиск (`review_choose`), «Исправить распознавание» (`fix_match`), нумерация (`set_numbering`: сезон, сдвиг, абсолютный счёт) и тип (`set_work_kind`: фильм, сериал, аниме). Правило — на самую глубокую папку источника, в которой лежат все живые файлы работы (`Anime/Frieren`; корень источника — если файлы разбросаны). Если у этой папки уже есть правило другой работы, первое остаётся, новое не создаётся (несколько исправленных сериалов россыпью в одной папке): решения пользователя по файлам всё равно окончательны, новые файлы находят работу по названию.

**Шаблон релиза** — имя файла в нижнем регистре словами, где номер серии заменён на `{n}` (`S02E05` — на `s{s}e{n}`), а CRC32 — на `{crc}`: `grp sousou no frieren {n} 1080p {crc}`. Для каждого шаблона запоминается, куда попадает номер, как это видно по исправленным файлам сейчас: сезон, сдвиг, сдвиг абсолютного номера или абсолютный счёт (`tvdb_absolute`). Если метаданные уже перенумеровали `- 29` в S02E01 (META-015), «Верно» запоминает «сезон 2, сдвиг −28». Хранится до 8 самых частых шаблонов (`folder_rules.templates_json`); схема, сезон и сдвиг самого частого — в `scheme`, `season_override`, `episode_offset`. Нумерация, заданная пользователем, заменяет цель у всех шаблонов. Тип, заданный пользователем, — `kind_override`.

**Применение.** Правило покрывает файл в своей папке, если совпал шаблон или главное название файла по разбору — одно из названий работы (у фильма ещё и год, если он есть у обоих). Альтернативные названия не считаются: среди них бывает имя папки, общее для всех её файлов. Из нескольких правил решает самое глубокое. Файл получает матч `user_set`, `decided_by = 'rule'`, уверенность 1, `scheme_used` и `explanation_json = {"folder_rule": id}`; номер — из шаблона, иначе из разбора со сдвигом правила. Сразу после исправления правило заново решает все файлы папки (вся группа, а не только исправленная работа), кроме решённых по NFO и решённых пользователем о другой работе; при скане оно решает новые файлы раньше разбора. Такие матчи не пересчитывают ни скан, ни новый парсер, ни скорер (`numbering::recomputable!` уже исключал файлы под правилом).

**Сеть.** Распознавание по правилу не обращается к провайдерам. Новый файл, как и раньше, заставляет прогон метаданных перечитать работу — по её ID, через кэш провайдеров на устройстве: название новой серии приходит без запроса, если ответ сезона ещё в кэше, иначе одним запросом за свежими данными. Тест META-017 держит это: после исправления скан и прогон с провайдером, который падает на любом вызове, дают новому файлу ту же серию, тот же маппинг и сдвиг и не делают ни одного запроса; с пустым кэшем маппинг тот же, неудачное обновление ничего не меняет.

**Синхронизация** (`folder_rule.set`, без изменений протокола). Ключ правила — `<sync id источника>:<первые 128 бит SHA-256 от sync id и папки>`: пути в операции нет. Тело — работа по ID провайдеров (`tmdb`, `anilist`, `imdb`, `tvdb`, `anidb`, `mal`) плюс название, тип и год, чтобы создать её там, где её ещё нет; тип, схема, сезон, сдвиг, шаблоны. Отправляются только правила синхронизируемых источников (SYNC-010, `sync_mode > 0`): у остальных на другом устройстве другой `sync_id`. Получатель ищет папку среди своих папок того же источника по хэшу; работу — по ID, иначе по названию (создаётся с ID, следующий прогон метаданных читает её по ID); затем решает файлы папки. Если папки ещё нет (не сканировалась), правило ждёт в `folder_rule_sync` (`received`) и применяется следующим сканом источника. Последний пишущий побеждает по штампу операции (`folder_rule_sync.stamp`); применённое правило не отправляется обратно. Выход из семьи забывает отправленное, после новой пары правила уходят снова.

**Удаление.** Без отдельного интерфейса: исправление заново заменяет правило (тот же ключ папки). `Catalog::forget_folder_rules` удаляет правила работы здесь и операцией `rule: None` у семьи; принятые решения по файлам остаются, новые файлы снова распознаются как раньше. Неявное удаление (работа или источник исчезли) по сети не отправляется. Кнопка «Забыть правило папки», поля «сезон / сдвиг» и «тип» в «Исправить распознавание» — задача META-035; ядро и тесты готовы.

### Последствия

- Хорошо: исправление делается один раз на папку; новые серии онгоинга сразу на своих местах, без сети и без инбокса.
- Хорошо: правило защищено от чужих файлов шаблоном и названием; NFO и чужие решения пользователя не трогаются.
- Плохо: в папке, где уже есть правило другой работы, второе правило не создаётся (россыпь исправленных сериалов в одной папке).
- Плохо: нумерацию и тип пока можно задать только через ядро (FRB и экран — META-035); в приложении работают «Верно», выбор результата и ручной поиск — их правила создаются.
- Нейтрально: шаблоны учитываются только у серий с одним эпизодом в файле; мультиэпизодный файл по шаблону берёт номера из разбора с той же целью.

### Как проверяем соблюдение

`core/crates/pa-catalog/tests/folder_rules.rs`: новый файл после «Верно» и после «другой результат + сдвиг» — те же работа, сезон, эпизод, абсолютный номер, ноль вызовов провайдера; чужой сериал в той же папке не забирается; тип; удаление; синхронизация: ключ без пути, ожидание папки, перенос уже распознанных файлов, отсутствие эха, удаление. Юнит-тесты шаблонов, целей и ключей — в модуле.
