# ADR-NNNN: Главы VOD Twitch — свой таймлайн, затем GQL `moments` за флагом, затем «≈ текущая категория»

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** `TWI-008`, `TWI-007`, `TWI-004`, `TWI-009`, `TWI-013`, `TWI-018`, `docs/research/06-twitch-integration.md` §2.3, §2.7, §5, [ADR-0011](0011-maintainer-decisions-release-0-1.md) §5, [ADR-0039](0039-remote-config-minisign.md), [ADR-0041](0041-build-flavor-mechanism.md)

## Контекст и проблема

Фильтр «VOD, где была игра X» должен работать по главам VOD, а не по текущей категории канала. В Helix глав нет. Исследование 06 §2.3 называет три источника: свой таймлайн из EventSub (официально), GQL `moments` (неофициально, best effort) и текущую категорию канала (только для свежих VOD, приблизительно). Нужно решить порядок источников, где живёт код, как GQL включается и выключается и как главы кэшируются при 24-часовом лимите на данные Twitch (TWI-007).

## Факторы решения

- Store-сборки не содержат GQL-кода (ADR-0011 §5, ADR-0041).
- Хэши persisted queries и client-id GQL — только из подписанного удалённого конфига (ADR-0039), никогда не вшиты.
- Нет своих серверов: всё работает на устройстве пользователя или его сервере.
- Глава с неточной категорией не должна выглядеть как точная.
- `pa-twitch` не должен тянуть SQLite в сборки, которым библиотека не нужна.

## Рассмотренные варианты

1. Только GQL `moments` — как yt-dlp.
2. Только свой таймлайн (EventSub/поллинг) для мониторимых каналов.
3. Цепочка источников: свой таймлайн → GQL за флагом → «≈» текущая категория для свежих VOD.

## Решение

Выбран вариант **3**: он даёт официальный путь для мониторимых каналов, покрывает произвольные VOD в full-сборках и честно помечает догадку.

- **Код.** Модуль `pa_twitch::chapters`: `TimelineTracker` (события `stream.online`, `channel.update` v2, `stream.offline` из EventSub WebSocket или опрос `GET /streams`), `LiveTimeline` (сегменты с временем по часам, перевод в смещения VOD: `offset = начало сегмента − начало эфира`, обрезка по длине VOD), `HelixClient::archive_for_stream` (архив по `stream_id`), `ChapterResolver` (выбор источника). GQL-часть (`VideoPlayer_ChapterSelectButtonVideo`) компилируется только под `cfg(pa_twitch_native)`.
- **Флаг.** `ChaptersGql::resolve` включает GQL, только если full-сборка, `twitch.chapters_gql` включён и не убит kill-switch'ем (а значит, включён и `twitch.gql_playback` с client-id), и в `twitch.persisted_queries` есть хэш операции. Иначе ни одного GQL-запроса.
- **Порядок.** Свой таймлайн этой трансляции → сохранённые главы, если они не fallback → GQL `moments` (тип `GAME_CHANGE`; без моментов — одна глава с категорией VOD, как в yt-dlp) → fallback. Ошибка GQL не роняет разрешение: её код (`gql_hash_invalid`, `integrity_required`, `network`…) возвращается для мониторинга, дальше идёт fallback.
- **Fallback.** Одна глава на весь VOD с текущей категорией канала (`GET /channels`), источник `fallback`, `is_approximate() == true` — UI (TWI-013) рисует «≈». Только для архива, который закончился не раньше чем 6 часов назад (`FALLBACK_MAX_AGE_MS`); у более старых VOD глав нет, а не догадка.
- **Хранение.** Модель TWI-007 без новых миграций: `twitch_live_sessions` + `twitch_category_segments` (владелец — эфир) во время трансляции, `twitch_videos` + `twitch_category_segments` (владелец — VOD) после; категории — в `twitch_categories` с названием и обложкой. Значения `source`: `eventsub`, `polling`, `gql_moments`, `fallback`. Мост в библиотеку — `pa_twitch::chapters::store` за cargo-фичей `library` (опциональные зависимости `pa-library`, `pa-model`).
- **Кэш.** Главы из своего таймлайна и GQL не запрашиваются повторно, пока они лежат в базе (`store::stored_source`); fallback может быть заменён лучшим источником. «Вечный кэш» из исследования ограничен правилом TWI-007: метаданные Twitch живут 24 часа, если пользователь их не сохранил (файл VOD, запись); главы уходят вместе с VOD.
- **Фильтр.** `pa_library::twitch::category_videos` (все каналы) и `channel_videos` с `game_id` ищут по главам VOD.

Не входит: запуск EventSub WebSocket-сессии и расписание поллинга (TWI-009), UI полосы глав (TWI-013), главы записей (TWI-018).

### Последствия

- Хорошо: в store-сборках главы работают для мониторимых каналов только на документированных Helix и EventSub; GQL выключается сменой конфига без релиза.
- Хорошо: «≈» видна в данных (`source = fallback`), фильтр не путает текущую категорию с историей.
- Плохо: поллинг видит смену категории с опозданием до интервала опроса; эфир, начатый до старта трекера, получает первую категорию с начала эфира (догадка: стримеры выбирают категорию до эфира).
- Плохо: из-за 24-часового лимита главы несохранённых VOD через сутки нужно получить снова (для GQL — новый запрос, для своего таймлайна — потеряны).
- Требует работы: TWI-009 подключает трекер к EventSub/поллингу; TWI-013 рисует полосу глав и «≈»; хэш `VideoPlayer_ChapterSelectButtonVideo` владелец добавляет в удалённый конфиг.

### Как проверяем соблюдение

- `cargo test -p pa-twitch` (store) и `cargo test -p pa-twitch --features pa-flavor/full`: фикстуры без сети; в store-сборке тест проверяет, что GQL не отправляется даже при включённом флаге.
- Проверка артефактов store-сборки (ADR-0041) — GQL-код за `cfg(pa_twitch_native)`.
