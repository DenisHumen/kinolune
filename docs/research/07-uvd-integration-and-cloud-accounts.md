# 07. Интеграция Universal Video Downloader ↔ Kinolune и облачные аккаунты

Записано со слов владельца 2026-11-27, чтобы не потерять направление. Это **идеи и направления**, а не утверждённая архитектура: перед реализацией (после основного функционала и редизайна, по команде владельца) нужно отдельное исследование, ADR и прототип на реальных ПК. Задачи — ECO-010…ECO-013 и SUB-032 в ROADMAP; связанные: ECO-001…ECO-009, LIB-027, LIB-028, SYNC-*, SUB-*.

## 1. Что такое Universal Video Downloader (UVD) сейчас

Изучено 2026-11-27 по `github.com/DenisHumen/Universal-Video-Downloader` (наш проект, MIT, v4.8.6):

- Настольное приложение на **Electron + TypeScript** (main / preload / renderer, React + Tailwind), Windows, macOS, Linux; есть CLI, расширение браузера, трей, автозапуск.
- Скачивание через **yt-dlp + ffmpeg** (свои сборки, проверка подписи движка), очередь загрузок с событиями прогресса (`DownloadProgress`: `percent`, `speed`, `eta`, `downloadedBytes`, `totalBytes`, фазы download/postprocess), возобновление, дедупликация, обрезка и конвертация.
- **Автоматизация** (`src/shared/automation.ts`, `docs/automation.md`): *watch* — страница сериала, которую приложение проверяет по расписанию; новые серии запускают *pipeline*: скачать → переименовать → выложить на SMB → уведомить. Учитывает разные озвучки (`translatorId`, своё число серий у каждой), бэкофф при ошибках, «ожидаемый релиз» (`releaseAt`), до ~50 watch'ей.
- Свои ссылки `uvd:` (link-protocol), библиотека скачанного, настройки и секреты в хранилище ОС.

## 2. Что хотим (владелец)

1. **Связка с запущенным Kinolune.** Если на компьютере запущен Kinolune, UVD связывается с ним, авторизовавшись в **профиле Kinolune**; после этого UVD получает доступ к тем же папкам медиатеки, куда Kinolune складывает файлы (и раскладывает скачанное по правилам папок Kinolune — ADR-0150).
2. **Живая карточка скачивания.** Поставили что-то на скачивание в UVD → данные о загрузке сразу уходят в Kinolune, и там без задержки появляется карточка с прогресс-баром «сколько осталось» — так же, как при drag-and-drop (LIB-028: серая карточка, скорость, ETA, до 10 обновлений в секунду в LAN, только при подписке).
3. **Отслеживание серий.** Watch из UVD (авто-скачивание новых серий) отображается на карточке сериала в Kinolune: «Отслеживание новых серий включено · озвучка · качество · следующая проверка», с переходом в UVD для настройки; новые серии появляются в медиатеке сами.
4. **Через облако.** Когда будет облако и подписка (Kinolune+), всё это идёт через облако и синхронизируется между всеми устройствами — ТВ, телефон, компьютер.

## 3. Направления реализации (на исследование)

### 3.1. Связь двух приложений на одном компьютере и в LAN

- **Транспорт:** тот же, что у устройств семьи Kinolune (SYNC-006, SYNC-008) — локальный канал (loopback / LAN) с взаимной аутентификацией; без открытых наружу портов. Вариант: UVD — «поставщик» по протоколу ECO-001 (уже запланирован для сервера), только адресат — запущенный Kinolune desktop вместо сервера.
- **Сопряжение (pairing):** один раз — по коду / QR / подтверждению в Kinolune (как ECO-002), с выбором **профиля** Kinolune; дальше — ключ устройства, отзываемый в «Подключённых приложениях» Kinolune.
- **Доступ к папкам:** не «полный доступ к диску», а выдача Kinolune'ом конкретных целевых папок (источников с правом записи, NET-023) для этого профиля; UVD пишет туда сам или через Kinolune (запись в источник, докачка `.part`, LIB-027).
- **Живая карточка:** UVD шлёт события «начато / распознано / прогресс / готово / ошибка / отменено» в формате эфемерного канала LIB-028 (без записи прогресса в журнал синхронизации); Kinolune показывает серую карточку «Скачивается в Universal Video Downloader · 42 % · 85 МБ/с · ещё 3 мин» на всех устройствах семьи.
- **Отслеживание:** watch'и UVD публикуются в Kinolune как метаданные карточки сериала (сопоставление по TMDB/AniList-ID через распознавание Kinolune), изменения — через синхронизацию; управление остаётся в UVD (кнопка «Открыть в Universal Video Downloader» по ссылке `uvd:`).
- **Ядра:** у Kinolune — Rust-ядро (FFI во Flutter), у UVD — Node/TypeScript. Варианты: общий протокол поверх HTTP/WebSocket + общий JSON-контракт (OpenAPI, как ECO-001) или Rust-клиент протокола, собранный в N-API-модуль для UVD. Выбор — в ADR.
- **Дизайн:** карточки и бейджи в стиле редизайна (palette-v2, «жидкое стекло»), единый вид «откуда пришёл файл» (UVD, drag-and-drop, Twitch-запись, диск).

### 3.2. Облако

- Тот же протокол событий через облачный ретранслятор (SUB-011, ECO-009) со **сквозным шифрованием** (сервер видит только зашифрованные данные), прогресс — не чаще 1 раза в секунду.
- Синхронизация медиатеки, watch'ей и статусов между ТВ, телефоном и компьютером — через облачную синхронизацию (SUB-012), когда она есть; без неё — по LAN, как сейчас.

### 3.3. Правовое

- UVD умеет качать с сайтов с пиратским контентом; Kinolune в сторах (store-флейвор) **не должен** рекламировать или встраивать скачивание с таких сайтов. Интеграция — только в full-сборке (прямые загрузки с GitHub/сайта), а в store-сборке — максимум приём уже скачанных файлов в общие папки, как от любого приложения. Проверить политики сторов при исследовании (LEGAL-*).

## 4. Пользователи и облако: принципы (уже сейчас писать код с расчётом на них)

1. **Два вида пользователей:** **локальные** (профили на устройстве и в семье, без нашего облака — как сейчас) и **облачные** (аккаунт Kinolune, подписка). Модель профиля в коде уже сейчас должна иметь место под облачную привязку (идентификатор аккаунта, состояние «локальный / облачный»), не ломая локальных.
2. **Шифрование:** все данные между клиентами и нашим сервером — в зашифрованном виде; содержимое пользователя (медиатека, история, присланное) — сквозное шифрование, сервер не может его прочитать.
3. **Админка у нас:** при входе нового **облачного** (не локального) пользователя создаётся его идентификатор; в админке видна **анонимная** статистика (без содержимого и без лишних персональных данных). Каждому конкретному пользователю можно выдать **скидку на подписку** или **пробную подписку на N времени**. Связь «идентификатор ↔ скидка/пробный период» — подписанные права (entitlements, SUB-002), безопасно, с аудитом, с расчётом на масштабирование (много пользователей, несколько серверов).
4. **Офлайн-первый:** если наш бэкенд упал, у пользователей **всё продолжает работать**, только синхронизация идёт локально (LAN, папка), без облака; после восстановления — догоняет.
5. **Бэкенд по DNS-имени:** клиенты обращаются к нашему серверу только по DNS-имени (не по IP), чтобы бэкенд можно было перенести, просто изменив DNS-запись; имена — в подписанном удалённом конфиге (как `remote-config`, CORE-014) с запасным встроенным значением.
6. Всё это — направления; правки и отказ от идей возможны.
