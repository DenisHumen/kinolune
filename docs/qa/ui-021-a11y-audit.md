# Аудит доступности ключевых экранов (UI-021)

Автоматическая часть аудита доступности приложения Kinolune (`clients/flutter/app`). Полный проход с экранными чтецами на устройствах — задача QA-009; здесь записано, что проверяют тесты, что по их результатам исправлено и что пока остаётся ручной проверкой.

## Что проверяется автоматически

Тесты запускаются в обоих флейворах:

```bash
cd clients/flutter/app
flutter test test/a11y_test.dart test/a11y_focus_test.dart --dart-define=KINOLUNE_FLAVOR=store
CARGO_KINOLUNE_FLAVOR=full flutter test test/a11y_test.dart test/a11y_focus_test.dart --dart-define=KINOLUNE_FLAVOR=full
```

### `test/a11y_test.dart` — правила `flutter_test`

Экраны: онбординг (все пять шагов), главная, фильмы, страница фильма, сериалы, страница сериала, OSD видеоплеера, главная музыки, альбом, плеер музыки (Now Playing с очередью), поиск с результатами, настройки, «Источники», «Стримы» (Twitch) и страница канала. Каждый экран проверяется на телефоне (390×844, ×2) и на десктопе (1280×800, ×1).

| Правило | Что проверяет | Где |
|---|---|---|
| `labeledTapTargetGuideline` | у каждого элемента с нажатием есть подпись для экранного чтеца | телефон и десктоп |
| `textContrastGuideline` | контраст текста по пикселям кадра: 4,5:1, для крупного текста 3:1 (WCAG 2.x AA) | телефон и десктоп |
| `androidTapTargetGuideline` | цель нажатия не меньше 48×48 dp | телефон |
| `iOSTapTargetGuideline` | цель нажатия не меньше 44×44 pt | телефон |

Тест собирает находки всех правил сразу, а не только первую.

Дополнительно:

- **Навигация для экранного чтеца** — на нижней панели (телефон), рейле (планшет), боковой панели (десктоп) и верхнем меню (ТВ) каждый раздел — кнопка с подписью, текущий раздел отмечен как выбранный.
- **Цветовые токены текста** — `textPrimary`, `textSecondary`, `textSecondaryOnArt`, `textTertiary` и `accentSoft` на всех трёх фонах (`bgBase`, `bgElevated`, `bgElevated2`) не ниже 4,5:1; подпись сфокусированной кнопки на белой заливке и белая подпись на акценте — тоже. Пиксельное правило видит только то, что показывают демо-экраны, а токены проверяются целиком.
- **Reduce Motion** — при `MediaQuery.disableAnimations` новая страница проявляется поверх прежней (кроссфейд), без сдвига и масштаба.

### `test/a11y_focus_test.dart` — клавиатура и D-pad

На десктопе (1280×800) для главной, фильмов, страниц фильма и сериала, музыки, альбома, поиска, настроек, «Источников» и «Стримов»:

- Tab проходит страницу и боковую панель и возвращается на страницу — без ловушек (фокус всегда сдвигается, круг замыкается);
- каждая остановка фокуса видна в окне (WCAG 2.4.11) и имеет имя для экранного чтеца (подпись, подсказка или значение сфокусированного узла семантики);
- порядок чтения: страница, затем боковая панель одним блоком сверху вниз;
- Shift+Tab возвращает на предыдущую остановку.

Отдельно: на странице фильма фокус сразу на «Продолжить», за ним «С начала» и «Исправить совпадение»; все кнопки OSD плеера достижимы Tab и подписаны; на ТВ D-pad вниз уводит из меню в страницу на подписанную карточку, «Назад» возвращает в меню.

## Что исправлено по результатам

| Находка | Исправление |
|---|---|
| Боковая панель и рейл не попадали в дерево семантики: модальный барьер маршрута вложенного навигатора скрывал всё, что нарисовано до него | у страниц разделов свой контейнер семантики (`app_shell.dart`) |
| Цели нажатия меньше 48×48 на телефоне: кнопки-капсулы (45), чипы сезонов (39), кнопки очереди музыки (36–40), аккаунт Twitch (41) | `MinTapTarget` (`pa_player`) расширяет зону нажатия и узел семантики до 48×48 без изменения вёрстки |
| Подписи под постерами и карточками Twitch — второй узел «нажать» без роли кнопки | `excludeFromSemantics` у подписи: кнопка — сама карточка |
| «Воспроизвести, Воспроизвести»: подпись кнопки дублировалась текстом | текст внутри `KButton` исключён из семантики |
| Поверхность видео в плеере — узел без подписи | подпись «Видео. Показать или скрыть управление» (ru/en); при включённом экранном чтеце OSD не скрывается сам |
| Раздел меню и чипы сезонов не сообщали, что выбраны | `selected` у `KFocusable` (боковая панель, рейл, меню ТВ, чипы сезонов) |
| Текстовые кнопки акцентом `#00777D` — 3,7:1 на фоне («Пропустить» в онбординге и др.) | `textButtonTheme` — светлый акцент `textLink` (10,7:1) |
| Курсор и рамка поля ввода в фокусе — 3,3:1 | светлый акцент |
| Метаданные в шапке сериала поверх светлого фона-обложки — около 2:1 | на телефоне затемнение шапки справа сильнее; цвет метаданных — непрозрачный `textSecondaryOnArt` |
| `textTertiary` (38 % белого) — 3,5:1, ниже AA | 47 % белого: не ниже 4,68:1 на всех фонах |
| «Шаг 1 из 5» растянут на всю ширину — неверный прямоугольник для чтеца и замера контраста | текст выровнен, а не растянут |
| Фокус после Tab из боковой панели попадал на элемент за краем экрана (страница восстанавливала прошлый фокус без прокрутки) | `KeepFocusVisible`: элемент с фокусом клавиатуры прокручивается в видимую область (не на ТВ) |
| Shift+Tab застревал рядом с кнопками строки источника: рамка фокуса добавлялась новым слоем и пересоздавала кнопки внутри вместе с их узлами фокуса | рамка фокуса всегда в дереве (прозрачная без фокуса) |
| Строка источника без действия была отдельной остановкой Tab вокруг своих кнопок | такая строка (без `onTap`, с кнопками справа) не берёт фокус сама |
| Reduce Motion не влиял на переходы страниц | `ReduceMotionPageTransitionsBuilder`: кроссфейд вместо сдвига и зума |

Скриншоты до и после — `docs/screenshots/progress/ui-021/`.

## Известные ограничения автоматической проверки

- **Подпись 11 px на десктопе ×1** («2 связанных устройства», шаг «Устройства» онбординга): правило контраста берёт самые частые светлый и тёмный пиксели, а у такого мелкого текста сглаживание не даёт ни одного пикселя цвета текста. Сам цвет (`textSecondary`, 8,2:1) проверен тестом токенов; находка внесена в список артефактов замера в тесте.
- Правило контраста ненадёжно на градиентах и картинках; тексты поверх обложек проверены на демо-обложках (в том числе на самой светлой), но не на всех возможных постерах.
- Первый Tab после открытия «Настроек» остаётся на области страницы (одно «пустое» нажатие), дальше порядок обычный.
- На ТВ «Вверх» с первой строки страницы не возвращает в верхнее меню — для этого «Назад». Решение по поведению — за дизайном ТВ.
- В рядах, построенных лениво и прокрученных к текущей карточке (эпизоды сериала, ряды главной), Tab входит в ряд с видимой карточки, а карточки левее достижимы Shift+Tab.

## Что остаётся ручной проверкой (QA-009)

- Реальные экранные чтецы на устройствах: TalkBack (Android, Android TV), VoiceOver (iOS, macOS, tvOS), Narrator (Windows), Orca (Linux, GNOME): порядок озвучивания, жесты, объявление смены раздела и экрана, озвучивание прогресса и тостов.
- Крупный шрифт до 200 % и экранная лупа.
- Системные настройки уменьшения движения на каждой платформе (что флаг `disableAnimations` действительно приходит) и анимации внутри экранов (смена фона на ТВ, «дыхание» фокуса).
- Контраст на реальных постерах и фонах, HDR-телевизорах и OLED.
- Управление только клавиатурой на всех экранах, не вошедших в список выше (диалоги добавления источника, профили, загрузки, записи Twitch, чат).
