# Ручная проверка облачных хранилищ на настоящих аккаунтах (NET-017)

Автотесты гоняют `pa-cloud` против моков API (контракт `pa-vfs`), а этот чек-лист — то, что моки не покажут: настоящие страницы входа, квоты, большие файлы. Проходит владелец (или тестировщик со своими аккаунтами) на Linux, Windows или macOS и на Android; результат — отметки в [каталоге проверок](test-catalog.md) (SRC-132…SRC-141) и заметка в PR.

## Подготовка

- Тестовые аккаунты: MEGA (один **с 2FA**, один без), Google, Microsoft (личный; по возможности ещё рабочий/учебный), Dropbox. Личные аккаунты с настоящими данными не используйте.
- В каждом облаке папка `Kinolune test`: фильм `Дюна (2021) [1080p].mkv` (лучше 2–10 ГБ, для перемотки), сериал из 2–3 серий в папке `Сериал/Season 1`, файл с `#`, `&`, `%` и пробелами в имени, пустая подпапка; в Google Drive ещё документ Google Docs и ярлык; в MEGA — публичная ссылка на папку и на один файл.
- Сборка с client ID проекта (`PA_*_CLIENT_ID`, см. [secrets.md](../dev/secrets.md)) **или** свой client ID в «Дополнительно».
- Включите логи диагностики (Настройки → Диагностика), чтобы потом проверить, что в них нет секретов.

## MEGA

1. «Добавить источник» → MEGA → «Аккаунт»: почта и пароль аккаунта **без** 2FA → «Войти и добавить» → источник «MEGA · почта» появился, проверка «В сети», скан пошёл.
2. То же для аккаунта **с 2FA**: после первого нажатия появилось поле кода; неверный код → «неверный код»; верный → источник добавлен.
3. Неверный пароль → понятная ошибка, источник не создан.
4. «Папка (необязательно)» = `Kinolune test` → в «Обзоре файлов» корень — эта папка.
5. Фильм играет; перемотка в середину и ближе к концу начинает играть за несколько секунд; субтитры/дорожки есть.
6. «Ссылка»: публичная ссылка на папку (с `#ключ`) → добавлена без входа, файлы видны и играют; на файл — тоже. Ссылка без ключа → ошибка про ключ.
7. Перезапуск приложения → источник работает без повторного входа (сессия в защищённом хранилище).
8. Выйти из всех сессий в веб-интерфейсе MEGA → «Проверить связь» → «войдите снова»; повторное добавление работает.
9. Квота трафика бесплатного аккаунта: долгий просмотр до исчерпания → понятная ошибка «квота … исчерпана», приложение не падает.

## Google Drive, OneDrive, Dropbox (для каждого)

1. «Добавить источник» → облако → «Войти через браузер» → открылась страница входа сервиса с названием приложения и запросом **только на чтение**.
2. Разрешить → вкладка «Вход выполнен — вернитесь в приложение»; в форме «Вход выполнен: <почта>»; «Добавить» → источник добавлен и сканируется.
3. Отклонить доступ в браузере → в форме «Вход отменён…», повторный вход работает.
4. Закрыть вкладку, не войдя, → «Открыть браузер ещё раз» открывает страницу снова; «Отмена» прерывает вход.
5. Фильм и серии распознаны и играют; перемотка быстрая; имена с `#`, `&`, `%`, кириллицей открываются.
6. Google Drive: документ Google Docs и ярлык не попадают в медиатеку и не ломают скан.
7. Оставить приложение на час и больше (истекает access token) → просмотр и скан идут дальше без входа.
8. OneDrive: после нескольких перезапусков в течение дня (refresh token ротируется) → источник работает.
9. Отозвать доступ приложения в настройках аккаунта сервиса → «Проверить связь» → «войдите снова».
10. Свой client ID в «Дополнительно» (свой проект/приложение у провайдера) → вход работает через него.
11. Android: вход через браузер возвращает в приложение (loopback); со своим клиентом, зарегистрированным с `kinolune://oauth`, и включённым переключателем — возврат по ссылке открывает Kinolune и завершает вход.

## Безопасность и приватность (для всех)

- В логах диагностики и в отчёте нет паролей, сессии MEGA, ключей ссылок, refresh/access token, ссылок загрузки.
- В базе медиатеки (`library.sqlite`, таблица `sources`) нет паролей и токенов: адрес `<облако>:/<папка>` или ссылка MEGA **без** ключа.
- Удаление источника удаляет его секрет из защищённого хранилища.
