# Первый запуск (онбординг, UI-004)

Мастер первого запуска приложения Kinolune: `clients/flutter/app/lib/screens/onboarding_screen.dart`.

## Шаги

1. **Приветствие и язык** — те же варианты, что в «Настройки → Язык» (UI-016): системный, English, Русский. Язык применяется сразу. Здесь же кнопка «Открыть демо-медиатеку».
2. **Режим** (STRATEGY §1, режимы A/B/C):
   - «Только приложение» (A) — папки и сетевые папки, без сервера;
   - «Свой сервер Kinolune» (B) — показывает серверы `alpha-media`, найденные в LAN по `_projectalpha._tcp` (NET-020, `SourceDiscovery.watchServers`), с пометкой «скоро»: подключение к серверу ждёт сопряжения клиента с сервером (SRV-003);
   - «Plex, Jellyfin или Emby» (C) — «скоро», не выбирается до NET-012…015.

   Выбор сохраняется (`Preferences.appMode`), но пока ни на что не влияет: следующий шаг одинаков для всех режимов.
3. **Профиль** — имя и цвет аватара (см. ниже).
4. **Первый источник** — тот же список, что в диалоге «Добавить источник» (UI-005): сначала найденные в сети шары (`SourceKindList`, NET-020), ниже ручные типы; формы — `SourceForm`. Добавленный источник проверяется и сканируется, прогресс скана виден на шаге.
5. **Другое устройство** (необязательно) — переход на экран «Устройства» (UI-019): сопряжение по QR или коду.

Любой шаг можно пройти кнопкой «Далее», весь мастер — кнопкой «Пропустить».

## Когда показывается

- При старте, если мастер ни разу не был завершён или пропущен (`Preferences.onboardingDone`) **и** источников нет. Установка, где источники уже есть (обновление со старой версии), сразу открывает медиатеку.
- Источник, добавленный внутри мастера, его не закрывает: условие проверяется один раз при старте (`AppServices.onboardingPending`).
- «Готово» или «Пропустить» записывают `onboarding_done`. Если потом удалить все источники, на главной показывается пустое состояние, а не мастер.
- Повторно мастер открывается из «Настройки → О программе → Мастер первого запуска» (кнопки демо там нет).

## Локальный профиль

Профилей в ядре пока нет (LIB-012). До них мастер создаёт минимальный локальный профиль: имя и индекс цвета аватара, JSON в `Preferences.localProfile` (`lib/services/local_profile.dart`). Он хранится только на этом устройстве, не синхронизируется и не влияет на прогресс и фильтры. Когда появится LIB-012, этот профиль импортируется как первый профиль ядра, а ключ удаляется.

## Тесты

- `test/onboarding_test.dart` — виджет-тесты: первый запуск, «Пропустить», язык, режимы и найденный сервер, профиль, первый источник WebDAV из «В этой сети», шаг сопряжения, повторный запуск из настроек.
- `test/l10n_layout_test.dart` — все шаги на ru и псевдолокали en-XA на четырёх размерах экрана; `test/tool/screenshots_test.dart` — скриншоты шагов.
- `test/onboarding_webdav_rust_test.dart` — сквозной тест на настоящем Rust-ядре: шара WebDAV из Docker (nginx из `core/crates/pa-catalog/tests/servers`) анонсируется по mDNS на loopback, мастер находит её, форма добавляет с логином, ядро сканирует, медиатека заполняется. Запуск (нужны Docker, curl, Flutter; шрифты — `node design/scripts/fonts-fetch.mjs`):

  ```bash
  clients/flutter/app/tool/onboarding_webdav_test.sh
  ```

  Скрипт поднимает только контейнер WebDAV (проект compose `pa-ui004-onboarding`, порт 127.0.0.1:18581) и удаляет его и сеть после теста; томов нет. Пароль теста хранится в памяти (платформенное хранилище ядра, как на Android), а не в связке ключей системы.
