# Живые тесты на Windows (QA-017)

`kq.ps1` управляет **настоящим установленным Kinolune** снаружи, как человек: читает экран, нажимает мышью, печатает с клавиатуры, делает скриншоты и следит за журналом, отчётами о сбоях и памятью приложения. Это не тестовая сборка и не эмуляция: тот же `Kinolune.exe`, который ставят пользователи (установщик из GitHub Releases).

Linux проверяется сценариями внутри приложения (`tools/qa/e2e/`, QA-016). На Windows Flutter SDK не нужен: работает любая Windows 10/11, только PowerShell 5.1 и то, что есть в системе.

Цель прогонов — **проверка системы, а не дизайна**: работает ли то, что обещает план (ROADMAP, `docs/qa/test-catalog.md`, колонка Windows). Вид экранов будет переделан, поэтому замечания о внешнем виде — только если что-то нельзя прочитать или нажать.

## Как это устроено

- **Экран.** Flutter отдаёт дерево доступности (семантику) через MSAA: роли (кнопка, текст, поле, переключатель), подписи, состояния (выбрано, включено, фокус) и координаты. `kq tree` показывает его, `kq find` ищет, `kq click` нажимает в центр элемента настоящей мышью (`SendInput`).
- **Ввод.** Текст — посимвольно Юникодом; клавиши — со скан-кодами (Flutter на Windows читает по ним физическую клавишу, иначе `Ctrl+A` не работает).
- **Скриншоты** — `PrintWindow`, окно может быть перекрыто.
- **Здоровье после каждой команды:** новые отчёты о сбоях (`diagnostics/crashes`) → строка `CRASH`, ошибки и предупреждения журнала приложения → `LOGERR`, процесс пропал → `CRASH`, память (private bytes, потоки, хэндлы) → `memory.tsv`. Журналы приложения включаются на время прогона (файл `diagnostics/opt-in`).
- **Прогон** — каталог `%LOCALAPPDATA%\kinolune-qa\runs\<время>\`: `run.log` (каждое действие со временем), `screenshots\`, `trees\`, `texts\`, `crashes\`, `logs\`, `memory.tsv`, `findings.md`, `report.md`. В репозиторий прогоны не кладутся (там пути и имя пользователя).

## Команды

Из PowerShell (из Git Bash — с `MSYS_NO_PATHCONV=1`, иначе аргументы с `/` превращаются в пути):

```powershell
$kq = "tools\qa\windows\kq.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File $kq start -Fresh -Kill   # чистый профиль
powershell -NoProfile -ExecutionPolicy Bypass -File $kq tree
powershell -NoProfile -ExecutionPolicy Bypass -File $kq click "Начать"
```

| Команда | Что делает |
|---|---|
| `start [-Fresh] [-Kill] [-Exe путь]` | запускает приложение и открывает прогон. `-Fresh` — первый запуск: профиль пользователя (`%APPDATA%\app.kinolune`, `%LOCALAPPDATA%\app.kinolune`) **переносится** в `kinolune-qa\profile-backup-*` и возвращается на `stop`. `-Kill` закрывает уже открытый Kinolune |
| `stop` | закрывает приложение, возвращает профиль, пишет `report.md`; профиль теста остаётся в прогоне (`profile\`) |
| `restore` | вернуть профиль пользователя, если прогон оборвался (сбой, перезагрузка, отключение света) |
| `restart` | закрыть и снова открыть приложение в том же прогоне — проверка, что всё сохранилось |
| `status` | процесс, память, число сбоев и ошибок журнала |
| `tree [-All]` | дерево экрана: `#id роль "подпись" {состояния} @x,y ширина×высота`; `-All` — и то, что за краем |
| `texts [имя]` | все видимые тексты (сохраняются в `texts\`) — удобно сравнивать экраны |
| `find <текст> [-Role button]` | элементы, в подписи которых есть текст |
| `click <текст> [-Role ..] [-Index n] [-Right] [-Double]` | нажать; элемент за краем прокручивается в видимую часть |
| `act <текст>` | действие элемента по умолчанию без мыши (если клик не дошёл) |
| `clickxy <x> <y>` | нажать в точку окна (по скриншоту) |
| `type <текст>`, `key <клавиши>` | ввод; клавиши: `Enter`, `Esc`, `Space`, `Tab`, `Left`…, `Ctrl+F`, `Alt+Left`, `F11` |
| `scroll down\|up [n] [-At текст]` | колесо мыши |
| `wait <текст> [-Timeout с] [-Gone]` | ждать появления (исчезновения) текста; по таймауту — `FAIL`, скриншот, код 1 |
| `shot [имя]` | скриншот окна |
| `explore` | обойти все разделы левой панели: скриншот, тексты, проверка здоровья |
| `note P0\|P1\|P2 <заголовок> -Steps .. -Expected .. -Actual ..` | записать находку в `findings.md` со скриншотом |
| `logs [-Tail n]`, `report` | журнал приложения; сводка прогона |

## Процедура прогона

1. Медиатека для теста (не в репозитории):
   ```powershell
   python tools\qa\media\library.py --out "$env:LOCALAPPDATA\kinolune-qa\media\library" --seconds 120 --unique --clean
   ```
   `--unique` обязателен: Kinolune узнаёт файл по содержимому (OSHash), и одинаковые клипы делят прогресс — без него «Продолжить», «Далее» и перезапуск дают ложные находки. Нужен `ffmpeg` в `PATH`.
2. `start -Fresh -Kill` → онбординг: «Начать» → «Папка на этом устройстве» → путь к медиатеке → «Добавить и сканировать» → `wait "Актуально"` → «Далее» → «Открыть главную».
3. Пройти по плану (ниже) и `docs/qa/test-catalog.md`, колонка Windows. После каждого шага смотреть `tree`/`texts`, при сомнении — `shot` и сам скриншот. Всё, что расходится с планом, — `note` сразу, со шагами, ожидаемым и полученным.
4. `stop`. Проверить, что профиль пользователя вернулся (`kq` пишет `the user profile is back in place`).
5. Подтверждённые находки — в ROADMAP §3.27 как BUG-NNN (`docs/qa/bugs.md`); журнал работы прогона — `docs/qa/live-windows-<дата>.md`.

**Сетевой источник (SMB) с паролем** проверяется на профиле владельца (без `-Fresh`: источник и пароль уже сохранены) или владелец вводит пароль сам. Агент пароли не вводит.

### План проверки (система)

- Первый запуск: онбординг, обнаружение серверов в сети, добавление папки, скан, распознавание.
- Медиатека: главная, фильмы, сериалы, фильтры, сортировка, «На проверку» (причины), исправление распознавания.
- Плеер: старт, часы идут, пауза, перемотка (кнопки и стрелки), «закончится в», выход → «Продолжить с …», «Продолжить просмотр» на главной, «Далее» и автопереход серий, перемотка в конец и за конец, фильм из частей, субтитры и дорожки, полный экран.
- Музыка: альбом, воспроизведение, переход трек→трек, мини-плеер.
- Поиск: русское и оригинальное название, пустой результат.
- Отслеживание папки: добавить, переименовать, удалить файл — медиатека меняется сама (время).
- Перезапуск (`restart`): прогресс, источник, очередь музыки, настройки.
- Настройки: источники (сканировать, проверка связи), диагностика (отчёт без личных данных), язык, профили и PIN.
- Здоровье: ноль `CRASH`, понятные `LOGERR`, память без роста в длинных циклах.

## Ограничения

- Видно только то, что Flutter построил: в ленивых списках (полки главной, длинные сетки) карточки за краем отсутствуют даже в `tree -All` — к ним прокручивать (`scroll`) и искать снова.
- Включённое дерево доступности — то же, что видит Экранный диктор: ошибки семантики (BUG-015) воспроизводятся и у пользователей с диктором.
- Клик в момент перестройки страницы попадает в другое место: сначала `wait`, потом `click`; если клик не дошёл (окно не стало активным) — `act`.
- Системные окна (выбор папки, сохранение файла) в дерево приложения не входят; путь к папке вводится в поле приложения.
- Агент не вводит пароли и не сохраняет их; прогоны с паролями — на профиле владельца.
