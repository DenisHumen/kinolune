# Живые e2e-тесты (QA-016)

Настоящее приложение (Rust-ядро, libmpv, сеть) запускается с чистого профиля на Linux-рабочем столе под Xvfb и прокликивается против **настоящей SMB-папки** с настоящими файлами. Никаких подделок: файлы лежат на тестовом стенде, приложение находит его в сети, сканирует, играет, перематывает и запоминает позицию.

Это не часть обычного CI (CI остаётся герметичным): прогоны идут на сервере сборки по запросу.

## Стенд: `stand.sh`

```bash
tools/qa/e2e/stand.sh up [--rebuild-library] [--no-real]   # поднять (идемпотентно)
tools/qa/e2e/stand.sh status                               # жив ли, вход по SMB3 работает ли
tools/qa/e2e/stand.sh down [--purge]                       # остановить (--purge — ещё сеть и том)
```

Всё, что создаёт стенд, называется `pa-test-e2e-*`; чужие контейнеры он не трогает и `prune` не делает.

| Что | Имя |
|---|---|
| контейнер Samba (долгоживущий, `--restart unless-stopped`) | `pa-test-e2e-smb`, имя хоста `kinolune-e2e` |
| сеть Docker | `pa-test-e2e-net` (в ней стенд — порт 445, mDNS `_smb._tcp`, NetBIOS, WS-Discovery) |
| том | `pa-test-e2e-media` → `$PA_E2E_HOME/library` |
| образы | `pa-test-e2e-smb:1` (Alpine: Samba, Avahi, wsdd), `pa-test-e2e-runner:2` (Ubuntu 24.04: GTK, libmpv, Xvfb, ffmpeg) |
| порт на хосте для клиентов из LAN | `PA_E2E_SMB_PORT`, по умолчанию 4450 |

Данные — в `$PA_E2E_HOME` (по умолчанию `~/pa-build/e2e-media` на сервере сборки):

- `stand.env` — одноразовые учётные данные тестового пользователя (создаются при первом `up`, права 600). В репозиторий не попадают и не копируются.
- `cache/` — скачанные фильмы, проверенные по размеру и sha256.
- `library/` — шара **media** (только чтение); `scratch/` — шара **scratch** (чтение и запись).
- `runs/<время>/` — результаты прогонов: `run.log`, `report.md`, `screenshots/`.

### Медиатека стенда (`library.py`)

Около 75 файлов, 1,75 ГБ. Основа — `tools/qa/media/library.py` (синтетические клипы с реалистичными именами), поверх неё:

- **настоящие открытые фильмы Blender** (CC-BY, © Blender Foundation | www.blender.org): Big Buck Bunny (2008, 480p H.264 .mov), Elephants Dream (2006, 480p .mov), Sintel (2010, 720p .mkv), Tears of Steel (2012, 720p .mov), Cosmos Laundromat (2015, 1080p .mp4, CC-BY 4.0). Скачиваются один раз с официальных адресов (Cosmos Laundromat — с archive.org) и сверяются по sha256 из `library.py`; имена — как у релизов (`Tears.of.Steel.2012.720p.mov`);
- сериалы с сезонами и эпизодами, папка в стиле аниме (`[Group] Title - 01 (1080p)`), музыкальные альбомы с тегами и обложками;
- папка Blu-ray `Caminandes Llama Drama (2013) [BDMV]/BDMV/{PLAYLIST,CLIPINF,STREAM}` (поток .m2ts настоящий, служебные файлы — заглушки заголовков);
- «свалка» `Downloads/`: имена с камеры, `movie.final.FINAL(1).mkv`, `.part`, sample, `readme.txt`, `Thumbs.db`, вложенная «New folder (2)».

Атрибуция — в `library/CREDITS.txt`.

## Прогон: `run.sh`

```bash
tools/qa/e2e/run.sh                 # сценарии
tools/qa/e2e/run.sh --soak 50       # + 50 циклов «каталог → фильм → играть → перемотать → назад»
tools/qa/e2e/run.sh --force         # вне окна — только для прогонов, одобренных владельцем
```

**Правило владельца:** живые прогоны — только по будням с 10:00 до 18:00 по Киеву (Europe/Kyiv). Вне окна `run.sh` отказывается (код 75), пока не передан `--force`.

Что делает: поднимает стенд при необходимости, берёт наш LGPL-libsmb2 из свежего релиза приложения (`$PA_E2E_HOME/native/`), запускает в контейнере `pa-test-e2e-runner:2` (в сети стенда) Xvfb и `flutter test integration_test/live_test.dart -d linux` с пустыми `XDG_*`-каталогами — то есть первый запуск.

Сценарии `clients/flutter/app/integration_test/live_test.dart` (каждый шаг проверяет реальное состояние и снимает экран, `ffmpeg x11grab` — с видео):

1. первый запуск → онбординг;
2. добавление SMB-источника: сначала «В этой сети» (NET-020, mDNS), иначе по адресу; вход, выбор шары;
3. сканирование (до 10 минут), число найденных файлов;
4. главная: фильмов ≥ 10, сериалов ≥ 3, треков ≥ 10, все пять фильмов Blender в медиатеке;
5. распознавание TMDB — только если есть `PA_TMDB_API_KEY` (в окружении или в `.env.local` в корне репозитория, он в `.gitignore`); без ключа шаг пропускается с пометкой `E2E SKIP`;
6. карточка фильма → «Смотреть» → 10 с воспроизведения (часы плеера идут, считаются остановки) → клавиша перемотки и переход на 3:00 → Esc → позиция сохранена;
7. «Продолжить» на главной показывает фильм с этой позицией;
8. сериал: эпизод 1 до конца → «Далее» запускает эпизод 2, и он играет;
9. музыка: трек играет, позиция растёт;
10. поиск «Sintel» — результат на экране и в ядре;
11. настройки (переключатель «основные/расширенные» — если есть в сборке, иначе `SKIP`);
12. диагностика «Сохранить отчёт» — файл отчёта создан.

`--soak N`: N циклов по пяти настоящим фильмам — открыть, 6 с играть, перемотать в случайное место, 4 с играть, назад. В отчёте: RSS процесса после каждого цикла, рост памяти, остановки (≥ 1 с без движения часов), ошибки плеера, неудачные циклы. Это начало «часов прокликивания»: многочасовые прогоны на Mac владельца — после 100 % дорожной карты.

Отчёт — строки `E2E STEP/FAIL/SKIP/SOAK/MEM` в `run.log`, сводка в `report.md`.

## Ограничения

- Linux под Xvfb, программный рендер (llvmpipe), звук — в нулевой приёмник PulseAudio; libmpv из Ubuntu (`libmpv-dev`) — не наша LGPL-сборка; libsmb2 — наш, из релиза. Сборка отладочная (`flutter test`), поэтому память в soak — с запасом отладочного режима; сравнивать прогоны между собой, а не с релизом.
- Стенд и раннер — в одной Docker-сети: настоящий TCP/SMB3 и mDNS, но без потерь и задержек LAN (плохую сеть проверяет QA-007).
- Для клиентов из LAN (например, Mac владельца) стенд доступен по адресу сервера сборки и порту `PA_E2E_SMB_PORT`; обнаружение по mDNS из LAN не работает (стенд в мосте Docker).
